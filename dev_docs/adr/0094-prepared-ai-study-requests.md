# AI依頼を未開始から保存し、確認元入力を編集対象と分離する

Status: accepted

## 判断

Issue #983の依頼準備は、#982の検討内台帳にあるTaskへ保存する。開始時刻がない状態を未開始とし、begin_requestの実受理だけが開始時刻を設定する。準備済みの種別・元案版・基準・比較編集対象と現在の要求・許可を照合し、確認依頼を後の比較許可で昇格させない。現在入力が変われば依頼を再確認する。保存入力の確認は、人が明示した読取専用入力の依頼と保存旧版許可の組でのみ開始できる。

確認の固定対象はTaskが所有する共通参照とし、Study.fixedが所有する鉄骨比較の編集許可対象と分ける。依頼時の入力・条件と表示条件を保持し、既存の案切替・Slot・読取専用制限に依頼時入力の表示先を加える。未計算の確認入力をStudyRunへ入れると実計算の失敗・完了状態や保持run番号に混在するため、計算していない入力だけを疑似runにしない。依頼作成時に実際に保持している結果は、元の案・実行・生成入力識別のまま既存の保持根拠で扱う。結果を基準案の新しい案IDへ読み替えない。

依頼元のsnapshotと依頼元内の対象参照を、比較編集に使う基準の固定対象から分離する。変更済み比較案の依頼元を基準案へ置換しない。本案由来であることも保存し、開始前の版照合と本案由来成果の現行性には実際の本案入力を使う。元の本案と同じ案識別を持つ読取専用コピーを、実際の本案の現在版を知る根拠にはしない。

| 入力の役割 | 照合先 |
| --- | --- |
| 依頼元入力・依頼元対象 | 依頼作成時のsnapshotとその入力版内の共通参照。読取専用表示の元 |
| 操作開始入力 | 外部要求が明示する案・入力版。現在案または許可された保存元と照合 |
| 検討の基準・編集固定対象 | 比較の不変な基準と、編集許可する鉄骨大梁の共通参照 |
| 実際の現行版 | 検討内の現在案版と一致し、本案識別なら実際の本案版とも一致する入力 |

保存旧版の許可が必要な条件を「明示保存入力から作った依頼、または実際の現行版ではない要求入力」に統一する。RequestInputから派生した依頼も、その入力と検討内のコピーが一致するだけでは許可を省略しない。同じ判定を開始・参照・保存応答の再検証に使い、再接続の許可変更後は同ID再送とreceiptにも現在の旧版許可を要求する。受理済み変更の結果照会を、新しい実行や入力の再取得へ読み替えない。

結果の方向・成分・ケースは、人が根拠窓で明示した共通参照を保存する。形状図の選択から、保持する全結果や未指定の成分を列挙して依頼対象へ追加しない。依頼側に新しい結果取得・計算式・進捗推定を作らず、#982の受理台帳・実job・submitと、#978の根拠閲覧・#980の比較・#981の人の採否を利用する。

数量の確認依頼では、明示されたQuantityScopeを固定範囲として保持し、現在の選択を要求・補完しない。数量の元入力・範囲・識別は、準備・取得・再送と受理照会・提出で同じ保存参照へ照合する。保存範囲がモデル全体であることを、固定部材0件やStudy.fixedの編集範囲へ読み替えない。数量根拠と表示入力が異なるときは、元の保存入力の明示表示を要求する。

接続終了と再読込後の継続未確認は、提出・計算状態と分離した観測として保存する。拒否要求の観測を理由に既存の受理台帳を変更しない。実jobの失敗と理由は既存jobに残す。接続許可は保存せず、再読込で開始済み作業の再開・成功を推測しない。人の補足・判断理由は提出されたAI説明と別に保存し、本文だけの変更でもdirtyとする。

## 保存と依存

開発中のスキーマは[ADR0014](0014-schema-compatibility.md)に従い直接変更し、開発版間のマイグレーションを設けない。未開始・依頼元入力・観測中断を含む検討の新形式に旧開発版Taskを黙って読み替えない。

表示時刻は既存lockと同じ版のtimeをGUIだけの直接依存とし、UTCの日時形式へ変換する。独自の日付変換やOS設定変更を加えない。
