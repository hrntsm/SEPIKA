# GUIを検討の所有者とし、外部AIは名前付きパイプで比較案を操作する

Status: accepted

2026-10-28、[#972](https://github.com/hrntsm/SEPIKA/issues/972)・[#973](https://github.com/hrntsm/SEPIKA/issues/973)の判断として確定する。これは所有権・保存境界・接続方式の決定であり、製品への実装完了を意味しない。操作の決定記録は[申し送り](../handoff/UI検討_Issue973_決定記録.md)、実測の範囲は[接続実験](../v_and_v/UI検討_Issue973_接続確認.md)に分ける。

## 所有権と採用

GUIプロセスを、開いているプロジェクトの本案・検討・比較案・実行ジョブの唯一の所有者とする。人のUI操作と外部AI要求を同じ直列化された編集・検証・Undo・既存計算経路へ渡す。[ADR 0003](0003-single-writer-edit-commands.md)の単一ライタを、別プロセスの独立モデルを共有状態とみなすことで代用しない。

基準案は検討開始時のモデル全体・明示入力・計算設定の不変スナップショット、比較案は基準案から独立したモデル全体とする。初回の比較案編集は固定した既存鉄骨大梁への既存有効断面の割当だけに制限する。差分だけを将来の本案へ再適用する方式では、共有断面・派生荷重・参照IDの変化を誤って拾うため、保存は完全スナップショットとし、表示用差分も残す。

本案への採用を実行できる主体はGUIの人だけとする。採用直前に、プロジェクト・本案の編集世代・固定対象・基準入力・比較案版を照合し、一つでも違えば拒否する。自動マージはしない。採用するのは確認済み断面割当の一まとまりの編集であり、比較案の計算結果を本案の最新結果へ移植しない。採用後は既存規則で要再計算となる。一度のUndoで割当を戻せる。

## 接続と権限

Issue #982の製品実装では、この方針を[ADR0093](0093-gui-ai-connection-protocol.md)で具体化した。製品Rustの実測範囲は[接続確認記録](../v_and_v/外部AI接続_Issue982_確認記録.md)に分ける。末尾の#973時点の候補・小実験記述は当時の判断根拠である。

Windowsのローカル接続は **名前付きパイプの双方向バイトストリーム** 一方式とする。外部AIクライアントとは既存のMCP stdio方式で接続する薄いブリッジを使い、ブリッジからGUIへだけ名前付きパイプで要求を中継する。ブリッジはモデル・Undo・計算結果を所有せず、既存独立MCPサーバをGUIの共有モデルとして使わない。HTTP/TCPの待受・ポート探索・ファイアウォール設定を避け、Windowsのアクセス権とプロセス終了時のハンドル閉鎖を利用する判断である。

GUIが外部AI接続を明示的に有効化した時だけ、ランダムなセッション識別を持つパイプを作る。GUIの接続案内からユーザーがブリッジへ接続先を渡し、ブリッジが実際に接続した時にGUIでクライアントと許可する検討を確認する。接続権は当該ログオンの同一ユーザーに限定し、リモートクライアントを拒否する。既定DACLに任せずログオンSIDのDACL・最初のインスタンスの排他作成を使う。パイプ名を秘密や権限として扱わない。GUIの承認後に発行する接続セッション内の許可で、閲覧範囲・比較案編集・計算を制限する。同一ユーザーの悪意あるプロセス全般を隔離する仕組みではない。

全要求にプロトコル版・要求ID・接続セッション・プロジェクト・検討・対象案と期待版を含める。UTF-8の1行JSONを最大1MiBに制限し、結果一覧はページ取得とする。不正JSON・未知の版/操作・過大フレームは変更前に拒否する。GUIが受理を確定した要求IDは検討へ保存し、同じ内容の再送には同じ受理結果を返し、異なる内容での同じIDは拒否する。応答喪失は成功とも失敗とも断定せず照会する。再接続時に旧許可を復活させず、新規承認して同じ検討の要求ID・ジョブIDを照会する。

## 最小操作と責務

| 操作 | 入力 | 出力・責務 |
| --- | --- | --- |
| 接続確認 | プロトコル版・GUI接続先 | GUIインスタンス/プロジェクト・対応能力。誤GUIなら終了 |
| 本案参照 | プロジェクト・期待編集世代・ページ | GUIが許可範囲の対象/断面/条件を返す。全ファイル読取は許可しない |
| 検討参照 | 検討ID | 基準・固定対象・案版・目的・採否・権限 |
| 比較案作成 | 検討・基準ID・要求ID | GUIが新案ID/版を返す |
| 断面割当 | 比較案・期待版・固定対象ID列・既存断面ID・要求ID | 共通編集経路で原子的に適用、差分/影響/新案版、拒否理由 |
| 計算開始 | 比較案・期待版・準備/静的/検定/数量の対象・明示荷重状態・要求ID | GUIが入力を固定しジョブIDを返す。未対応は拒否 |
| 依頼/ジョブ照会・取消要求 | 検討・要求ID/ジョブID | 受理・待機・実行・成功・失敗。取消は既存ジョブが対応する範囲だけ受理し、未対応なら理由付き拒否。取消完了まで取消済とみなさない |
| 結果参照 | 結果ID・案/入力識別・対象・成分・ページ | 単位・生成条件・有効性・未算定理由付きの数値。AI説明とは別に表示 |

検討作成、対象固定、接続許可・取消、本案の採用/Undo、保存先の選択はGUIの人が行う。AIへ本案編集・任意コマンド・ファイル読書き・任意コード実行・採用・保存先指定を公開しない。拒否は無変更で、機械可読の理由（権限拒否、基準相違、案版競合、対象不成立、未対応、計算失敗、接続切断）と日本語説明を返す。

## 切断と並行操作

GUIイベントキューで受理と編集を直列化する。重い計算は既存ジョブへ渡し、開始時の案/入力版へ結果を結び付ける。同じ案の計算中は案編集を拒否し、他案の編集・本案編集・閲覧は可能とする。初回は計算ジョブをGUI所有の一列で実行し、並列solver運用を追加しない。

クライアント切断では新規要求権を停止し、受理済み計算はGUIで継続・照会できる。取消は既存ジョブの対応範囲に限り、実行中solverの強制中断機能を新設する要求にはしない。取消未対応なら計算は継続し、切断を取消完了と表示しない。GUI終了/プロジェクト切替は許可を破棄し、新規要求を拒否する。未完了ジョブは保存時に未完了として記録し、再読込時は「中断・結果なし」、自動再実行しない。権限拒否や応答タイムアウトで本案や案が変わったと推定しない。

## 代替案と影響

- 既存MCPの独立OVIKA読込を継続するとGUIの編集中状態・採否と乖離するため採用しない。既存独立起動の用途は本判断で共有化済みとはならない。
- ローカルHTTPはクライアントの直接接続に便利だが、起動ごとのポート・認証・待受の管理が増えるため初回には採用しない。
- GUI自身をMCP stdioの子プロセスにすると、人が開いたGUIへの後付け接続とライフサイクルが合わないためブリッジを置く。

Rustでは既存依存のTokioのWindows named pipeを入口候補とするが、現在のfeatureに`net`はなく、権限属性を含む製品実装・MCP中継・UIイベントへの接続は[#982](https://github.com/hrntsm/SEPIKA/issues/982)で検証する。[Tokioの公式API](https://docs.rs/tokio/latest/tokio/net/windows/named_pipe/struct.ServerOptions.html)と[Windowsのアクセス権](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights)を参照した（2026-10-28 JST）。既定ACLが十分狭いとは仮定しない。小実験は.NETの同一ユーザー制限で往復/EOF/不在を確認しただけで、製品DACL・別ユーザー拒否・MCP相互運用の完了証拠にはしない。
