# 断面 J の算定元を解決し、CFT コアの数値ねじりを幾何性能から分離する

- Status: accepted
- Date: 2026-10-18
- Related: [#416](https://github.com/hrntsm/SEPIKA/issues/416)、[ADR 0039](0039-section-property-basis.md)、[ADR 0014](0014-schema-compatibility.md)

## 背景と判断理由

断面の保存 J を直接消費すると、形状由来の古い値を現在の算定値として扱い、CFT 換算で形状から鋼管 J を再計算すると供給値を失う。
また、CFT コアの A・I と J を同じ幾何取得経路で算定すると、重量・耐力など J を使わない処理にも数値求解の費用と失敗が波及する。
算定元の意味を実際の消費境界で実行し、コアのねじりだけを必要時に解決する設計を採用する。

## 決定

### 物理モデルと形状由来の鋼管 J

H はフィレットを省略した既存の慣用薄肉式を維持する。A・I の半径反映と区別し、厳密な半径不変性や全域での安全側を主張しない。
丸角 Box は一様厚さ・単セル・同心円弧の中心線式を採用する。外角半径を ro、板厚を t、外寸を B・H として、初期適用域を t ≤ ro ≤ min(B,H)/2 かつ min(B,H)/t ≥ 10 に限る。
これは採用モデルの限定であり、普遍的な誤差保証ではない。
明示 ro = 0 は既存の直角薄肉モデルの独立分岐とし、丸角分岐の厚比条件を転用しない。
未知半径、0 < ro < t、無効寸法、丸角式の適用域外は理由付き未算定とし、半径の推定・clamp・旧式への無言の代用を行わない。

CFT は既存の初期弾性累加 GsJs + GcJc を継続する。各単体の自由ねじりを用いたモデルであり、完全付着の共通そりの厳密解と同一視しない。
角丸コアには、均質等方・穴なし・一定断面・一様自由ねじりの正規化 Prandtl 問題と適合 P1 三角形 Galerkin 法を採用する。
コア境界の Dirichlet 条件は単体問題の条件であり、CFT 界面の応力ゼロを意味しない。
内法・内角半径は既存の幾何規約に一致させ、円弧を接線接続点を保つ内接弦で表す。代表長で正規化して解き、J を長さの 4 乗で復元する。
円形コアの既存解析式は維持し、角丸コアの矩形近似への置換や面積比補正は採用しない。

### 算定元と CFT の消費境界

`Section::resolved_j() -> Result<f64, String>` を J の解決入口とする。

- `Supplied` は有限非負の供給値を返し、形状式の適用外を理由に上書きしない。正値が必要な利用側では別途検証する。
- `Shape` は現在の `shape.try_calc_j()` を使い、保存 J の cache は消費も一致検査もしない。
- `PendingShape` は理由付きで拒否し、現在の形状が算定可能でも getter が自動的に成功へ昇格させない。

生成・半径編集では形状由来 J を再評価し、供給値は保持する。幾何が成立して J だけ適用外なら、A・I の更新と理由付き未算定の J を保持できるようにする。
完全算定を約束する生成 API は未算定を拒否する。この区別により、J 不要の形状編集を J の限定域で妨げない。

CFT の `Section.j` は鋼管単体 Js とし、合成 J を書き戻さない。
`CftCoreProps` は J を持たない幾何性能 API とし、コア Jc の数値 API を分離する。J getter、A・I・重量・耐力・幾何一覧にはコア数値求解を持ち込まない。
CFT 換算は解決済み Js を受け取り、線形 Beam と Fiber の両経路、および J を必要とする剛性詳細へ同じ累加を接続する。
実要素の `Material::shear_modulus()` は材料の明示 G を優先するため、CFT 換算も同じ実 Gs を受け取る。Es と νs だけから Gs を再構成すると、明示 G がある場合にコア寄与が既存の初期弾性累加と一致しないためである。
CFT 等価 API の引数を `(es, nu_s, gs_mpa, fc, gamma_c, steel_j_mm4)` とし、軸・曲げの換算比は Es/Ec、ねじりとせん断面積の換算比は実 Gs/Gc による。Gs の上書きや仮想 ν の逆算、旧引数の互換ラッパーは設けない。
材料入力と νs の検証を保持し、実 Gs の有限正値、必要な換算比、最終性能と剛性を検証する。この境界整合は新たな物理近似ではなく、供給 Js の優先、純幾何のコア J 再利用と明示診断の fresh solve を変更しない。
供給 Js があるコアの数値問題へ鋼管薄肉式の限定域を転用しない。
材料不正やコア数値失敗は理由付きエラーとし、`None` や鋼管のみの成功へ置き換えない。
この判断は [ADR 0028](0028-src-cft-ns-material-or-fallback.md) の CFT 材料不正時の鋼管のみへのフォールバックを置き換える。SRC の判断は変更しない。

### 依存配置と品質判定

core の限定コア用モジュールから Spade 2.15.1 の制約付き Delaunay 細分化と、既存の faer 0.24.0 の疎 LLt を直接使用する。
自作メッシュ・線形ソルバを増やさず、core から同層の math への依存や依存規約の緩和も避けるためである。
core の外部依存が増える負担を受け入れ、汎用任意断面 FEM や本番 Python 依存は追加しない。
通常の制約辺細分化を許し、固定した元弦ポリゴン上での共線分割と円弧分割の変更を区別する。制約辺固定オプションは必須にせず、接線点・輪郭被覆・面積・正向きを監査する。

通常の細分化が正常完了しても、全頂点が境界上にある粗いメッシュでは非自明な P1 試行空間が得られない。
限定した角丸コアでは中心が厳密内点と分かるため、初回の全監査後に内部節点が 0 の場合だけ中心を Spade で追加し、残余頂点上限内で同じ面積・角度条件により再細分化して全監査する。
元の弦領域・境界条件・積分・品質閾値を変更せず、既に内部節点があるメッシュには追加操作を行わない。任意輪郭へ中心の仮定を広げず、初回不正や再細分化の資源不足を成功へ置き換えない。

境界分割と内部サイズを別系列で各 3 段以上評価し、各系列の最後の連続 2 区間の J 相対変化を各 0.1% 以下、相対残差を 1e-10 以下とする。
境界比較は同じ内部サイズで行い、内部収束も確認する。メッシュ不変の J 差ゼロは収束としない。
退化・反転要素、非正・非有限 J、品質未達は数値未確定とする。閾値は設計上の品質基準であり、厳密誤差上限や安全側の証明ではない。

有限資源上限を頂点 200,000、三角形 400,000、境界最大 6 段・内部最大 8 段とする。
内部の元 6 段と最初の合格時点での停止を維持し、factor 4 の細分化を末尾に 2 段追加する。品質基準を変えず、元 6 段で未達だった経路だけ探索を延長するためである。
上限は未確定として終了する条件であり、全形状での成功や処理時間を保証しない。
未収束を外挿・面積比補正・旧式で成功にせず、品質閾値や物理適用域も無言で緩めない。
J、段階ごとの残差・自由度・両系列の変化・資源・時間と失敗履歴を非永続の診断として観測可能にし、数値品質を保存済み鋼管 Js の算定元へ混入させない。

### CFT 剛性でのコア J 再利用と診断の分離

Windows release の単一輪郭に対する別プロセス 4 回の初期計測で、毎回の数値求解に無視できない費用を観測した。
同じ輪郭の多数部材でこの費用を繰り返さないため、CFT 剛性の private な composite 消費経路に限り、品質合格済みコア J の scalar だけをプロセス内で最大 64 形状まで LRU 再利用する。
これは同じ幾何問題の数値解の再利用であり、物理モデル・品質閾値・適用域を変更しない。計測値と再現条件は V&V で管理する。

各呼出しで材料・鋼管 Js・コア幾何を通常どおり検証してから、実内法 b・h と内角半径の正確な f64 bits をキーとして照合する。
材料と鋼管 Js は純幾何のキーに含めず、供給 Js を含め毎回別途累加する。半径編集は異なるキーになり、不正値・未知半径・未収束・エラーは保存しない。
安価な円形コアの解析式にはこの再利用を設けない。

有限容量の管理を自作しないため、保守された [lru 0.18.5](https://docs.rs/lru/latest/lru/) の `LruCache` と標準の `OnceLock`・`Mutex` を core 内部で使い、層依存規約を維持する。
重い求解中は mutex を保持せず、同時の cache miss では重複求解を許容する。容量を超えると再求解が必要になり、初回求解自体の費用も残る。
保存・serde・スキーマ・結果契約には持ち込まず、失敗をゼロや鋼管のみの成功へ置換しない。

明示的なコアねじり診断 API は毎回 fresh solve し、全段階と失敗履歴を取得できるようにする。
cache hit の時間を fresh な数値算定時間として扱わず、この再利用の採用だけで初回求解の高速化や全代表域・Windows アプリ全体の性能達成を主張しない。

### 検証と結果契約

独立 V&V は、本番 Prandtl/P1 と異なる二次要素のそり Neumann 法を開発専用環境で用い、参照自身を円・楕円・矩形級数・円環で校正する。
H・Box の独立解はモデル差の比較用とし、本番エンジンへ拡張しない。
算術誤差・モデル誤差・数値収束を分け、代表域の失敗も記録する。Windows の実行環境で初回と反復の処理時間を測り、cache の再利用時間だけで性能を主張しない。

解析結果契約を analysis 25 から 26、設計結果契約を design 17 から 18 へ更新し、旧・未来の結果の再利用を拒否する。
形状 J の現在式への解決は版別の移行ではなく、通常の算定元契約とする。
[ADR 0014](0014-schema-compatibility.md) に従って保存スキーマは 1 を維持し、移行・旧版検出・cache 一致許容差を追加しない。
