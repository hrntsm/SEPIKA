# ダンパーはモデル化範囲の総重量を直接入力し、断面由来質量を置き換える

Status: accepted

## 判断と理由

[Issue #422](https://github.com/hrntsm/SEPIKA/issues/422) に関連するユーザー合意により、通常線材の自重整合に加え、ダンパーの自重と動的質量への接続も対象とする。
明示入力の Fiber/MultiSpring 通常線材には、同じ断面・用途・配置の Beam と同じ自重・割増・付加重量・仕上げ・被覆の契約を適用する。剛性や非線形の定式化を理由に総質量を変えない。

ダンパーとしてモデル化した範囲の総重量 W [N] を直接入力する。範囲内の支持部と付加重量も W に含め、支持部の面積・長さによる自動重量算定や付加重量の自動二重加算は行わない。支持部を別にモデル化する場合は、その範囲を W に重複して含めない。
装置・支持部の重量範囲を入力で明確にし、剛性を表す元断面から重量を推定する代わりに、重量・質量の計上元を一つにするためである。

明示 Damper およびダンパー重量を指定した Beam/Brace/Fiber/MultiSpring では、断面由来の自重・要素質量を算入せず、入力 W を自重・階設計重量・物理質量相当重量の計上元とする。
動的質量は W/g（g は重力加速度）を既存の両端半分の集中配置経路で一度だけ計上する。元断面は剛性・非線形特性に用い、質量源にはしない。
`CorrectedLumped` / `LumpedOnly` の方式自体は変更しない。

階生成の代表節点質量を生成データとして記録し、組立時には実節点への反映を照合する。
方式に依らない階の物理質量全量だけでは、補正質点方式の代表節点質量の正解を特定できない。
また GravityCasesOnly では入力 W を自動追加しないため、W/g を一律に検証の下限とすることもできない。
算定済みの6成分をそのまま記録して照合することで、不足・欠落を検出しつつ再生成や別の近似配置を避ける。
質点系が使用する方式に依らない全量物理重量・重心・慣性も、階生成時の動的質量として別途保持して照合する。
これらを代表節点の補正質量6成分から逆算すると方式・荷重経路の契約を崩すため、再算定せず生成結果を保存する。
未算定や反映記録の欠落を含む生成データ単独の不一致も拒否する。
入力・配置・反映の不備は公開解析 API の `InvalidInput` として返し、unwind しない。

階別W合計では同じ階の重量再配分や指定先変更を区別できないため、部材ID・個別W・材端IDと座標を
生成記録へ保持し、完全な一覧として照合する。合計やハッシュだけには依存しない。
指定なしの生成も空の記録を残す。これにより、生成済み通常部材へのW=0置換追加と、
階生成を必要としない無重量ダンパーを区別する。
配置記録は対象の剛床代表・スレーブと、それらに直接関係する拘束・節点の幾何と拘束に限定する。
一般の剛性・断面編集を含む全モデルのstalenessや、生成記録と実質量の同時偽造は対象にしない。
記録の残存項目だけを検査すると部分欠落を見逃すため、対象の階・配置・参照節点の集合を
現モデルから求め、不足・重複・余分を照合してから反映値を検証する。必要集合の導出は質量の再生成ではない。

## トレードオフと制約

支持部重量の自動算定や元断面の分布質量の併用は、入力総重量との範囲重複・二重計上を招くため採用しない。
両端への集中配置は、分布質量による局部応答や装置・支持部の回転慣性の再現を保証しない。安全側・危険側を一律には認定できない制約として、ユーザー了承済みである。
