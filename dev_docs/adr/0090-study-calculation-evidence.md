# 検討の計算根拠を現在の案入力と分離して保存する

Status: accepted

## 判断

検討を OVIKA の任意エントリ `studies.msgpack` に保存し、manifest のハッシュ検証対象にする。検討は開始時の本案・固定対象・各案の現在入力と設定を持つ。保持する計算は、開始時入力・準備後入力・既存の結果一式・数量の出力・警告とエラー・生成日時・アプリ版を一緒に所有する。実行中ジョブと Undo 履歴は保存しない。計算中のログは通常画面ログの件数上限とは独立に全件保持し、準備開始から完了までの通知と、各段階の診断本文・重要度・対象を保存する。単一の直近通知は実行入口で消去されるため、警告の根拠には用いない。

計算履歴の閲覧中に固定する対象・結果参照は、開始時入力ビューと準備後結果ビューの注記として計算根拠から分離して保存する。案切替と通常保存で注記を回収し、入力・結果を更新せずに保持する。参照から表示するときは対応する読取専用入力を開く。結果選択で再生成する検定を参照として保存した場合は、その検定時の入力・設定・解析結果を含む結果一式を別の根拠として保持する。参照されない再検定の閲覧履歴は保存しない。

数量だけを確認する検討では解析履歴を要求しない。固定数量根拠は、その案・入力版・全体入力・集計対象・契約・識別を含む既存の根拠参照のまま、明示操作で検討の注記へ保存する。基準案・比較案・計算履歴の表示から保存でき、閲覧しただけでは保存しない。現在入力や基準案への読み替えを避けるため、計算原本とは別に所有する。

根拠窓の入力と数値は、参照が指す元結果または別保持結果の読取専用ビューから同時に取得する。断面・材料の編集へ移る操作は本案へ切り替え、戻るまで元の読取専用表示状態を一時保持する。この状態は永続履歴には加えない。

保存結果の表示用状態には、通常読込と共通の契約・生成入力・未対応パネルの失効規則を適用する。原本はその判定から分離し、履歴の再表示・追加根拠への切替・参照解決用の読取ビューでも、原本を更新せずに利用可否を判定する。検討から契約失効した成果を再認証してしまう別経路を作らないためである。

保持した結果は現在の案の結果へ自動置換せず、計算時入力の読取専用ビューで既存図表へ渡す。共通参照の実行 ID と生成入力を保持結果から照合し、対応する計算時入力へ移動する。結果を保持する案は削除不可とする。採用記録を追加する後続の実装でも、この計算根拠を所有する保存単位へ参照を接続する。

## 理由と代替案

断面変更では準備計算が自重・質量・自動荷重を更新する。固定した基準案や編集中の案を作業モデルと兼用すると、計算前処理や実行中の再編集によって判断時の根拠が変わる。計算専用の作業状態で既存準備計算と解析ジョブを使い、開始時と準備後の両入力を保持することで、手入力の固定と派生入力の再算定を両立する。

現在入力と結果だけを保存する案は、再編集前の判断根拠を復元できないため採用しない。全編集版と Undo の永続化は必要な計算時点を越えた履歴管理となるため採用しない。結果の計算時入力を既存図表で表示するため、別の編集系・解析系は導入しない。

案切替は AppCore と入力ドラフトを所有する状態を移動する。切替時以外は全案を複製しない。計算作業スレッドが既存ジョブの準備・続行・結果適用・検定・数量まで所有し、GUI は確認待ちか完成した保存単位だけを受け取る。通常保存は一時的に本案の状態へ移動して既存保存経路へ渡し、表示案を復元する。保存パスと大容量保存の確認待ちはプロジェクト共通で移送する。
