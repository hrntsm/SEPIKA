# 階の FL・差分を入力とし、構造基準 SL と用途別の高さを導出する

- Status: accepted
- Date: 2026-10-24
- Related: [#729](https://github.com/hrntsm/SEPIKA/issues/729)、[ADR 0014](0014-schema-compatibility.md)、[ADR 0059](0059-incomplete-model-reference-integrity.md)

## Context

単一の階標高が階高・階所属・剛床と構造基部に兼用されていた。FL をそのまま構造基準へ読み替えると、梁代表節点が剛床から外れる。
節点からのレベル推測・基部階の自動追加は、利用者が指定した上下 FL の組を変え、未知の建築階高を幾何から補ってしまう。

## Decision

Story は FL と ΔSL をそれぞれ Option<f64> で保持する。未入力をゼロとは区別し、SL と各高さは導出する。
製品上の式・単位・参照規約は[階の分布](../../docs/preparation/01_階の分布.md)を正とする。
Layer.height と既存の床標高欄は FL、構造用の上下端 SL と SL 間高さは独立した導出欄にする。

階の編集は元の ID と隣接対を保持し、FL／SL が逆転する変更を拒否する。元 STB 階は明示した原階 ID で参照し、現在 FL の変更を元属性の変更としない。
ネイティブ階から作成した標準出力用の原階だけは、現在の名前・FL の変更を同期する。
自動所属の反映値を生成記録に保持し、明示所属と区別する。ネイティブ原階の初期化でも自動所属を明示へ昇格させない。

保存・一般モデル検証では入力途中の None を許容し、計算入口で必要情報の不足を検査する。
階生成と明示準備は上下階の入力を要求し、階依存の準備失敗を正常な解析開始として公開しない。
階を持たない低水準の要素／重力解析は階不要の入口を維持する。
既存節点の移動・FL 推測・差分補完・基部自動追加・旧形式の移行は実装しない。

## Consequences

高さ入力と構造配置を独立して編集・診断できる。生成代表節点は SL に配置でき、既存の計算には FL 間高さを供給できる。
FL や差分が不足する取込モデルを編集・保存できる一方、依存計算の開始前に明示入力が必要になる。
モデル共通型と保存構造に破壊的変更を行う。初回リリース前の schema_version は ADR 0014 に従い 1 を維持し、解析／検定の計算契約版を更新する。
