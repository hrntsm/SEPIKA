# ADR 0036: ST-Bridge 断面用途の明示マッピング

## 状態

採用

## 決定

ST-Bridge の部材タグと断面定義タグから断面用途を明示的に保持し、`Section.frame_use`へ設定する。
`StbColumn`、`StbGirder`、`StbBrace`はそれぞれ柱、大梁、ブレースとして扱う。
`StbBeam`、`StbPost`は二次部材（小梁、間柱）として扱い、`Section.frame_use`を決めない。

`StbSecBeam_*`は大梁・小梁が共有できる梁系断面定義、`StbSecColumn_*`は柱・間柱が共有できる柱系断面定義であり、定義タグだけから用途を推定しない。同一断面が主架構部材と二次部材から参照される場合、主架構部材の用途だけを内部断面へ設定する。主架構用途が競合する場合はimportを失敗させる。二次部材については断面参照の実在、領域・種別などの構造整合を検証し、`Section.frame_use` の値だけで拒否しない。

断面file IDの参照用途と定義タグ用途が一致しない場合、また同一符号・階の定義が異なる用途を持つ場合は、改番や警告で継続せずimportを失敗させる。名称、角度、節点座標による用途推定は行わない。

exportでは`Section.frame_use`と二次部材種別を正とし、柱・大梁・小梁・間柱・ブレースごとのST-Bridge断面要素と部材コンテナへ出力する。同一内部断面を出力側の断面種別ごとに必要な場合だけ分け、内部断面は複製しない。標準要素で表現できない断面の`StbSecRaw`にも用途属性を保持する。

## 理由

用途を形状や幾何から推定すると、同一断面の設計分類と解析形状が乖離する。またST-Bridgeの定義タグと参照部材タグの不整合を警告だけで通すと、設計分類が変わったまま計算へ進む。入力段階で用途を確定し、不整合をfail-loudにすることで断面用途を単一情報源として維持する。
