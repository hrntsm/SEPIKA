# ADR 0036: ST-Bridge 断面用途の明示マッピング

## 状態

採用

## 決定

`Section.frame_use`の正は、主架構部材（`StbGirder`、`StbColumn`、`StbBrace`）の参照文脈であり、断面定義タグは用途を決めない。
`StbColumn`、`StbGirder`、`StbBrace`はそれぞれ柱、大梁、ブレースとして扱う。
`StbBeam`、`StbPost`は二次部材（小梁、間柱）として扱い、`Section.frame_use`を決めない。

`StbSecBeam_*`は大梁・小梁が共有できる梁系断面定義、`StbSecColumn_*`は柱・間柱が共有できる柱系断面定義であり、定義タグだけから用途を推定しない。同一断面が主架構部材と二次部材から参照される場合、主架構部材の用途だけを内部断面へ設定する。主架構用途が競合する場合はimportを失敗させる。二次部材については断面参照の実在、領域・種別などの構造整合を検証し、`Section.frame_use` の値だけで拒否しない。

`Section.frame_use`の正は主架構部材の参照文脈であり、断面定義タグは用途の正ではない。同一STB断面系列内で、同一符号・階、断面性能・形状・材料等と全強度・配筋metadataが一致する定義に限り、主架構用途が`Some`、二次部材用途が`None`でも統合する。別系列は同名同形状でも改名して別の内部断面として保持する。Column/PostとGirder/Beamの同系列共有は維持する。`Some`同士の主架構用途が競合する場合だけ、改番や警告で継続せずimportを失敗させる。名称、角度、節点座標による用途推定は行わない。

exportでは`Section.frame_use`と二次部材種別を正とし、柱・大梁・小梁・間柱・ブレースごとのST-Bridge断面要素と部材コンテナへ出力する。同一内部断面を出力側の断面種別ごとに必要な場合だけ分け、内部断面は複製しない。標準要素で表現できない断面の`StbSecRaw`にも用途属性を保持する。

## 入力と出力の境界

入力では標準2.0.2の対応済み断面・形鋼参照を使い、独自の `StbSecRaw` や `StbMaterial`、`id_material` 系参照で標準参照の欠落を救済しない。必要な節点・断面・形鋼参照が解決できなければ、通常の取り込みエラーで全体を失敗させる。旧形式の検出・専用エラー・移行処理は設けない。

上記の `StbSecRaw` は現行exportの出力契約であり、importの受理契約ではない。Raw出力の撤去・標準出力への置換は本判断では行わず、その再importを受入条件にしない。書き出しの開発中・機能不足表示も維持する。内部の任意断面性能・材料物性・強度、内部編集とOVIKAの保存・再読込・再採番は保持する。

## 理由

### 入力識別の判断（Issue #571）

主架構用途とSTB断面の入力識別は別の責務とする。入力識別は採用namespace `https://www.building-smart.or.jp/dl`、具体的な断面系列、正規化した元数値IDの組とし、定義・部材参照・断面強度を同じ識別に結ぶ。採用namespaceは入口で保証する不変条件として持ち、各キーへ同じURI文字列を重複保持する必要はない。同URIの接頭辞と既定namespaceを等価にし、foreign/no-namespace/未束縛接頭辞をlocal名だけで救済しない。属性のQNameを標準属性名へ短縮しない。標準ルート直下の `StbExtensions` はnamespace検査を続け、配下の意味処理を遮断する。未知の同URIグループを含む全XML文法の検証へは拡張しない。

具体系列の選択表は[製品仕様](../../docs/model_io/03_ST-Bridge_要素別変換状況.md#断面参照の系列対応)を正とする。Post/Column、Beam/Girderはそれぞれ系列を共有し、主架構用途の有無をキーへ混ぜない。数値IDの既存u32入力範囲・字句規則は維持し、`1`と`01`を同じ数値として扱う。XSDのpositiveInteger適合とは別の契約である。同系列重複は形状生成より前に拒否し、未対応形状のskipによって重複を見逃さない。別系列同IDの一律拒否は行わない。

裸ID、Column/Beam等の大分類、形状・名称・階・材料一致による結合では具体系列を区別できない。内部断面の統合候補があっても、元の断面強度が異なる定義を混同しない。要求系列欠落、kind_structure欠落・不正・未対応は理由付き全体失敗とし、他系列や既定断面へ救済しない。core/OVIKAには外部キーを追加せず、既存の内部SectionIdとStrengthTargetへ接続する。強度優先順位、原階・指定節点、配筋、任意物性と保存/内部再採番は維持する。出力写像や外部断面ID永続化は本判断に含めない。

根拠は[公式2.0.2 XSD](https://www.building-smart.or.jp/wp-content/uploads/2026/04/ST-Bridge_v202.zip)の具体系列ごとの19個のkeyと、[公式仕様説明書](https://www.building-smart.or.jp/wp-content/uploads/2022/06/ST-Bridge_XML%E4%BB%95%E6%A7%98%E8%AA%AC%E6%98%8E%E6%9B%B8%EF%BC%88ver.2.0.2%EF%BC%89_20220615.pdf)の本文64/68/73/75/77頁である。XSDにはkeyrefがなく、部材と断面の意味結合をschema適合だけでは保証できない。固定資料・独立入力の証拠と未確認範囲は[V&V](../v_and_v/STB断面系列別ID_Issue571_2026-10.md)で区別する。

用途を形状や幾何から推定すると、同一断面の設計分類と解析形状が乖離する。また主架構部材の参照文脈同士の用途競合を警告だけで通すと、設計分類が不定のまま計算へ進む。主架構用途の競合をfail-loudにすることで、断面用途を単一情報源として維持する。
