# 保有水平耐力に採用する結果ごとに生成入力を照合する

Status: accepted

## 判断と理由

[Issue #502](https://github.com/hrntsm/SEPIKA/issues/502) では、静的解析や時刻歴の完了が全体の stale フラグを解除しても、既存 bundle の旧増分結果は残る。そのため全体のフラグだけでは、現在入力と採用結果の一致を証明できない。

結果 bundle に、静的荷重ケース・組合せ名・増分方向・固有値のキーごとに生成入力の直列化スナップショットを保存する。解析前処理後のモデルと当該種別の関連設定を記録し、判定入口で剛域を再反映した現在入力と比較する。識別記録の欠落も拒否する。部分再解析は成功したキーの記録だけを置き換え、他種別や他方向の記録を最新化しない。

入力モデルは表示専用の通り芯と、時刻歴実行後に登録する振動ケース一覧を除き、荷重生成・非線形・断面判定への影響を漏らさないよう広く保持する。設定は荷重生成条件・質量方式・並列度を共通に含め、増分結果には方向と制御・終了条件・塑性率算定方式・長期初期載荷を加える。実行方向の選択操作だけで保存済み他方向の有効性を失わせない。ジョブ完了時は開始時モデルと解析設定を照合し、変更前の結果を適用しない。

精算周期（SemiPrecise）で標準 EX/EY を生成する場合は、その生成に使用した1次周期を、地震静的・EX/EY を含む静的組合せ・増分解析の結果入力へ加える。固有値だけを更新しても、それ以前の周期で生成された水平力から得た結果が有効にならないためである。Approx には固有周期依存を加えず、固有値結果自身にも自身の周期を含めない。

固有値のモデル識別では標準 EX/EY ケースだけを除外する。固有値解析は `Analysis::eigen` から剛性・質量の組立へ進み、外力ベクトルを用いない。`assemble_global_m` は材料・断面の要素質量、節点質量、拘束から質量行列を構築する。GravityCasesOnly の荷重由来質量も、階生成で反映した節点質量とその生成記録をモデル内に残して照合する。重力系荷重・階・質量生成記録は除外しない。固有周期による EX/EY 再生成だけを固有値の入力更新とすると、固有値→Ai 同期→固有値という不要な再実行循環になるため、この派生水平荷重を独立させる。

採用静的結果は画面の表示選択から独立させ、判定方向の地震静的キーで特定する。偏心率精算が実際に使用する X／Y と長期組合せ、周期に使用する固有値も共通照合を通す。純粋な耐力計算関数へ GUI の世代状態は持ち込まない。

## トレードオフ

直列化した入力全体の保存は、編集通知だけの世代管理やハッシュよりメモリ・保存サイズが増える。一方、編集通知の呼び忘れや全体 fresh の解除に依存せず、ハッシュ衝突なしに一致を判定できる。解析依存のないモデル属性の変更でも再解析を求める場合があるが、表示専用変更は明示的に除外する。現在のスキーマ方針は [ADR-0014](0014-schema-compatibility.md) に従う。

結果を表示する既存入口は設計タブ `design_view.rs` と増分結果タブ `app/panels/results.rs` で、いずれも `App::compute_holding_capacity` を呼ぶ。現行 MCP に同メソッドの直接入口はない。追加入口もこの共通照合を通す。

現在仕様は [保有水平耐力の判定](../../docs/calc_basis/07_二次設計/01_保有水平耐力の判定.md) を正とする。Qu／Ds の式と評価ステップ選択の改定は #441／#442／#443 の対象であり、本判断には含まない。

## 静的検定への適用（Issue #602）

同版の旧入力で生成した静的検定も、時刻歴・増分等の成功による全体 fresh の解除だけでは認証できない。
既存の `ResultInputKey` の末尾へ `Design` を追加し、`input_records` に検定成功時の計算用モデル、実効荷重期間、RC損傷制御・付着・QD方式、採用した Static/Combo キーと既存生成入力を記録する。応力源キーは省略既定を持つ `design_source` に保持し、利用時は現在の表示選択から独立して照合する。直接床板・小梁には応力源を要求しない。

`run_design_check` の成功完了だけがこの記録と検定版を作る。失敗時は旧検定とその記録を消去する。解析成功の `mark_fresh` は検定を単独で認定しない。GUI表・着色・tooltip・Inspector・CSV・OVIKA保存は同じ `require_design_input` を通す。失効した比率・合否は出力しないが、既存のパネル適用条件の非数値診断は CSV に保持する。

OVIKA保存では無効検定を保存用cloneから外す。新しい時刻歴等は保存でき、読込時に無効な選択静的結果を除いても、それだけを理由に保持した時刻歴を古い扱いにしない。解析がstaleの新規直接検定は検定欄だけを保存し、旧解析を伴って認定しない。保存や読込は生成入力を捏造しない。Undoで入力が厳密一致する場合は保持検定を再利用できる。

全 `AnalysisSettings` 比較や汎用世代基盤は追加しない。既存の表示専用入力除外を維持する。検定生成入力の欠落する従来成果は利用できないため検定契約を3へ更新し、解析式・準備・既存解析入力の意味を変えないため解析契約は4を維持する。MCP毎回新規DesignCheckとParquet/FsResultStoreは本変更の対象外。

## 時刻歴の実入力とケース所属への適用（Issue #611）

[Issue #611](https://github.com/hrntsm/SEPIKA/issues/611) では、表示選択やケース名で結果を対応付けると、サンプル・直接 CSV・実行中の選択変更によって別入力の結果を上書きしうる。
生成・読込・変換した波形と生成時の設定、入力元表示名を一組として確認待ちから完了適用まで渡す。
立体は solver に用いる GroundMotion、質点系は方向変換後の加速度列・dt と、それぞれ実際に使用する設定から入力識別を作る。
波形生成のためだけの設定は生成済み実列で識別し、元 CSV ハッシュや選択名では代用しない。
質点系は必要な静的・増分成果の既存 `input_records` 生成証明も識別に含める。
必要キーは先行成果の存在・入力一致検査と共有し、Planar 線形は加振方向の静的、Planar 非線形は同方向の増分、Spatial 線形は X/Y 静的、Spatial 非線形は X/Y 静的と増分を対象とする。
直接の質点系設定が同じでも、剛性・復元力の生成条件が違えば同じ実効条件とはいえないためである。
生成証明を確認待ち・ジョブへ保持し、実起動時に先行成果を検査してから現在の証明と照合する。結果全体の payload hash や新たな証明台帳は導入しない。

実波形・実効設定・必要先行成果の基礎 digest を、開始時に準備した計算モデルへ結合して最終入力識別とする。
生成時の暫定識別は、`begin_analysis`／`begin_analysis_job` による準備と必要先行成果検査の後、solver へ渡すモデルで確定する。未準備の初回と同条件再実行が別ケースになることを防ぐためである。
同じ波形・設定でも材料・構造条件が違えば別ケースとする。
入力識別を振動ケースへ保持し、同一入力・条件の再実行は同じ ID と結果スロットへ対応付ける。
既存対象は開始時に固定し、適用時に消失または識別変更されていれば結果を破棄する。新規対象のケースは成功適用時だけ作る。
表示名は一意キーにしないため、同名の異なる入力は共存する。

生成後に設定が変わった確認待ちは明示的に起動拒否し、実行中のモデル・設定変更は既存の共通ジョブガードで拒否する。
拒否・失敗・取消・通信路異常を成功完了と扱わず、今回のケース・結果・表示・fresh 認定を更新しない。
既存の別結果や検定生成入力を保つ。旧計算契約成果の拒否とは別の経路で扱う。

ケース ID ごとの時刻歴生成入力を既存の `ResultInputKey` / `input_records` に接続し、入力識別も照合する。
OVIKA にはケースの識別と結果所属を保持するが、波形 payload を追加しない。
識別欠落・不一致の旧成果を現行ケース名や再保存から補完しない。保存成果の意味が変わるため共有解析契約版を18から19へ更新する。検定契約版10は維持する。
同じモデルで実行した複数の正常時刻歴は、最後に選択した設定ではなく各成果の実行条件を照合し、各 ID と結果スロットを保存再読込で保持する。
既存 `input_records` の時刻歴証明は `VibrationResultInput { model, analysis_identity, identity }` とし、保存保持では契約版・正規 bytes・ケース識別・基礎 digest と記録モデルから再構成した識別の内部一致を確認する。
現モデルでの採用は既存 `require_result_input` で記録モデルと現計算モデルの一致も要求する。
現モデル B での成功結果があるとき、旧モデル A の正常な履歴は保存再読込で保持するが、B の結果へ読み替えない。履歴だけが残る読込を全体 fresh と認定しない。
モデル編集後に未再実行の stale 保存で解析を同梱しない既存 gate は維持する。
スキーマ方針は [ADR-0014](0014-schema-compatibility.md) に従い、波形 registry、移行処理、別の鮮度基盤は追加しない。

実列からの識別は入力処理量を伴うが、名前や元ファイルだけでは変換後の入力差を捕捉できないため採用する。
時間添字・初期釣合い・記録時刻と非ゼロ応答の精度は #610 の対象として分離する。
