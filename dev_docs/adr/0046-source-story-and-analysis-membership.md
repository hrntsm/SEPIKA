# 原階の明示所属は解析用所属から独立して保存する

Status: accepted

STB の StbStory 属性と明示節点列を `SourceStory` に保存し、準備計算の `Story`・`Node.story` と所有を分ける。STB height は GL から意匠 FL の高さであり、節点 Z・解析所属とは一致しないため、幾何所属で元属性を置き換えない。原階の ID/GUID と節点の標準 ID/GUID は内部配列 ID から分離する。

未採番ネイティブモデルの構造節点は最初の成功編集で標準IDを保存する。候補編集前に既存節点へ採番するため、初回の削除でも残存節点の交換IDが変わらない。失敗・Noopは候補を破棄し、undoは側表も編集前へ戻す。

意図的な原所属編集と節点削除を単一編集 transaction に含め、undo/redo で元参照と標準識別子を復元する。準備計算は原階を変更しない。所属曖昧さの階依存診断と Fc の優先解決は別の判定とし、上位の明示値があれば原階段階を参照しない。原階 Fc が競合する段階を共通値で迂回しない。

原階のkindがnative明示分類から作成されたかを保存する最小属性を持つ。既存SetStoryLevelKindによる明示操作はnative由来kindだけを更新し、取り込みkindを上書きしない。undo・ネイティブ保存・入力世代にこの区別を含める。階対応は厳密heightで確認し、原階のない生成基礎階以外の対応喪失・重複は拒否する。

STB kind は階分類であり、Frame/WallBuilding の設計法を意味しない。現行モデルに階別設計法型はなく、本件で推定機能を導入しない。将来の消費側は一意な安定階対応がある場合だけ既存の明示設定を引き継ぎ、統合・分割の曖昧さを利用者へ示す。

原階 Fc 参照 API は #520 の消費側へ渡す供給契約とする。部材・断面・共通の元材料指定の保存や全材料解決は #520 に残す。

原階の初期化済み状態を保存し、STB取り込み時は階0件でも初期化済みとする。全原階削除後も状態を保持し、exportや基部編集が派生解析階を原階へ再作成しない。未初期化のnativeモデルは従来のexportを保持し、成功した初回階編集でだけ原階を初期化する。状態はModelの末尾へserde既定falseで追加し、保存・snapshot・undo/redo・入力同一性へ含める。

## native初回所属保存

原階未初期化のnative階編集は既存標準出力と同じ `Node.story` と `Story.node_ids` の和集合を保存する。片側入力の合法な所属を失わず、同一階の重複は除去し、解析生成代表節点は除外する。相異なる階への指定は両方を残して原階の多重所属診断へ渡す。取り込み済み原階と意図的な原階0件では初期化せず、prepareの解析所属を追加しない。
