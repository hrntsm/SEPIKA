# 部材表と解析モデルの3D表示は準備計算の方式判定を共有する

Status: accepted

Related: [Issue #2041](https://github.com/hrntsm/SEPIKA/issues/2041)

## Context

同じ柱・大梁でも解析種別によって扱いが変わる。非線形方式の入力指定や、画面が編集中の入力から求めた分類だけでは、その方式が適用可能かは分からない。例えば、[ADR 0170](0170-src-concentrated-spring-flexural-backbone-hold.md) の矩形SRC梁・柱では、材端集中ばねが選ばれても適用外となる。

## Decision

- 部材表と解析モデルの3D表示（表示モード「モデル化」）は、確認対象の解析種別を共有する。表示対象の切り替えは入力設定を変更しない。
- 両画面に示す柱・大梁の解析方式の判定と診断は、現在の入力に対して準備計算が返した、確認対象の解析種別の情報に限る。準備計算と解析は、GUI に依存しない共通 API が返す方式・適用可否の判定と、それに伴う診断を用いる。GUI で方式や適用可否を判定し直さない。線形解析では、非線形方式の指定にかかわらず対象の柱・大梁を弾性とする現行の扱いを維持する。
- 重量・荷重などの共通準備が成立すれば、一度の準備計算の成果で、線形静的・増分・非線形時刻歴の方式判定と診断を切り替えて確認できる。解析種別の切り替えでは共通準備をやり直さず、解析も実行しない。
- 準備計算が未実行、または入力の編集で成果が古い場合は、入力から推定せず、古い判定も流用せず、現在の入力での準備計算を案内する。共通準備自体が成立しない場合は、方式を推定して表示せず、準備計算が返した不成立の理由を確認できるようにする。
- 準備表・解析結果の復元は従来どおり行うが、復元した値だけでは共通準備の成立を確認できないため、方式判定は再構成しない。
- 準備計算が診断を返して解析を開始できない場合も、得られた方式判定と診断は確認できるようにする。適用外の理由は該当する解析種別で示し、その方式を採用済みとは表示しない。ある種別での適用外は他の種別の判定の確認を妨げない。解析の実行や完了は、これらの判定を確認する前提としない。
- 非線形解析の要素生成には、同じモデルの事前診断が確定した方式を渡す。公開ファクトリを単体で呼ぶ場合も線材に同じ診断を使う。実行時に決まる荷重条件や壁の耐力は別に検証する。

## Alternatives and consequences

編集途中でも入力から参考プレビューを表示する案は採らない。準備計算前に確認できる即時性は失うが、判定の出所を準備計算に固定することで、参考分類が実際の解析に用いる判定と食い違ったり、適用済みと誤認されたりするのを防ぐ。解析結果だけを表示元とする案も、解析前の確認と、解析を開始できない場合の理由の確認を妨げるため採らない。

共通準備を使い回すことで、同じ入力の重量・荷重などを計算し直さずに解析種別を比較できる。種別固有の適用外を共通準備の不成立と区別し、その理由だけで他の種別を確認できなくなるのを防ぐ。

この判断は、表示と解析で情報源を分けないという [ADR 0023](0023-hinge-detail-single-source-analysis-models.md) の方針に沿う。解析方式や適用条件を変更するものではなく、[ADR 0170](0170-src-concentrated-spring-flexural-backbone-hold.md) の適用外判定と [ADR 0176](0176-remove-explicit-multi-spring.md) のマルチスプリング廃止を維持する。
