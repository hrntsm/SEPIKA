# ADR 0054: MCP 保存成果の生成元と公開ファイルを結び付ける

## Status

accepted

## Context

MCP の静的・固有値成果は case/kind だけではモデル世代・計算契約・生成条件を識別できない。
固定ファイルの先行上書きは、途中失敗時に以前の公開 manifest と bytes を別成果にする。
現在解析設定は MCP の永続状態にないため、現在モデルとの一致から設定一致までは推定できない。

## Decision

既存 ResultEntry に開始入力の SHA-256、実行識別、ジョブ種別、解決済み条件、計算契約版・結果スキーマ版、公開 bytes の SHA-256 を保持する。
#502 の表示専用値除外を Model の共通メソッドへ移し、既存 GUI と MCP が再利用する。
計算契約版は #587 の core 定義を共有し、スキーマ版・リリース版とは分離する。

既存 writer/finish/sync を維持し、tempfile による同ディレクトリの一意ファイルへ書く。
finish 後にファイル同期と hash を完了して保留 entry に接続し、一時 manifest の同期後に原子的置換で公開する。
過去の公開ファイルを上書き・削除せず、保存失敗では旧公開対応を保持する。
run は UUID と既存 job_id の組で再起動後を区別し、別の ID 台帳は追加しない。

照会は選択 entry の path/hash を用い、生成元・必要条件・版を検査した後だけ rows を返す。
現在モデルの入力一致だけを current とし、不一致は保存 snapshot の stale として照会可能にする。
別 run の種別は同じ成果と推定せず、選択 entry と生成条件を応答へ出す。

## Consequences

失敗・再実行で不要になった未参照ファイルは削除しない。保存成果の整理機能は別課題である。
欠落・旧版を現在値で補完しないため、旧成果は生成元不明／旧契約として再実行を要求する。
原子的置換は通常の公開失敗時の整合性を扱い、電源断耐性を保証しない。
時刻歴全節点保存・ページ照会・取消・新 manifest 基盤（#483）を先行条件にしない。
