# 支持境界による割当領域の同一性

対象は床板・壁版の割当領域 ID、版の割当、入力荷重と編集履歴の状態契約。
本件はアプリの同一性契約であり、力学式や構造規準の数値妥当性を定めない。
参照解は [ADR 0020](../adr/0020-assign-plates-to-member-bounded-regions.md) と
[現在の編集仕様](../../docs/model_edit/04_立体グリッドとスナップ.md)。
親の床領域・壁領域名を重心・面積から再配置することと、版割当の境界照合を分ける。

## 入力と独立期待値

共通 fixture は `crates/sepika-core/tests/support/assignment_identity_model.rs`。
4000 × 3000 mm の矩形を床 XY 面と壁 XZ 面で用意し、支持 ID は 0–3、
初期割当領域 ID は 0、版 ID は 0。版の入力面荷重は「入力仕上げ」0.0025 N/mm²、
壁の開口重量は 1234 N。中央の二次部材は支持 0 と 2 の 0.5 位置を結ぶ。
主架構の試験は支持 ID 0 の削除、節点 ID 1 の構面外 1000 mm 移動、節点 0 と 2 を結ぶ部材 ID 4 の追加。
いずれも旧版 ID 0 と入力面荷重 0.0025 N/mm² が除去対象になると入力から定める。
期待 ID・状態・値を入力から明示し、実装の生成キーをテスト側で再計算して正解にしない。
不変性は入力モデル全体（導出 DOF map を除く）と、領域の次 ID を含む集合の比較で検査する。

| 契約・期待 | 直接検証する入口・fixture |
|---|---|
| 巡回・逆順・±0 で ID 0 と割当を維持 | core `assignment_identity_tests.rs` → `replace_boundaries` |
| 0.5 と 0.5000000000000001 は新 ID 1、2 の Unset | 同上。入力した span の値をそのまま候補へ渡す |
| 候補キー衝突、既存キー衝突・同じ版の重複割当で領域/next_id を保持 | 同上 → `replace_boundaries`・公開 `rebuild` |
| 正常な面走査重複は 1 領域にまとめ、不正既存領域の修復には使わない | 同上 → 支持線分を渡す公開 `rebuild` |
| 同重心・同面積・同親名でも支持 ID が変われば新 ID 1 の Unset | 同上 → `Model::rebuild_assignment_regions`、床/壁の親領域再構築 |
| 同じ支持/span の節点移動で ID 0・版 ID 0・0.0025 を保持し、幾何は幅 5000 mm | 同上 → 公開再構築・割当領域座標。5 回の反復も不変 |
| 一般再構築は孤立版 ID/件数/入力荷重を診断して未更新 | 同上 → 公開床壁一括再構築。床候補成功・壁候補失敗でも床の新 ID を確定しない |
| 明示分割は旧版を除去、領域 ID 1/2 の Unset、1 Undo で全入力復元、Redo で同じ入力、統合は新 ID 3 | edit `tests/assignment_identity.rs` → `preview_plate_assignment_loss`・`UndoStack::run/undo/redo`。小梁・間柱両方 |
| 拒否で next_id・版/荷重・revision・Undo/Redo 履歴を保持 | 同上。既存キー衝突と版重複を直接 `EditCommand::apply` と Undo 入口で検証し、編集前から孤立した版の除去も確認対象へ含める |
| 主架構追加・削除・非平面節点移動は旧版 ID 0・入力荷重 0.0025 を診断し、1 Undo/Redo で全入力復元 | edit `tests/assignment_identity.rs` → 3 命令の preview と run/undo/redo。床・壁各 3 入力 |
| 同一支持/span の構面内節点移動は確認不要で ID 0・版 ID 0・入力荷重 0.0025 を保持 | 同上 → 節点 1/2 を幅 5000 mm へ移す `SetNodeCoord` の Composite と `run_preserving_plate_assignments`。床・壁各 1 入力。中間で矩形が崩れる壁も最終支持境界で照合 |
| 確認できない入口は版・荷重消失を拒否し revision・next_id・Redo 履歴も維持 | 同上 → `UndoStack::run_preserving_plate_assignments`。各入力で事前に Undo した履歴を保持 |
| 主架構一覧削除は確認待ち/キャンセルで未更新、確認後 1 Undo/Redo。節点グリッドは構面外貼付を拒否して理由表示 | app `app/assignment_identity_tests.rs` → 実一覧入口 `delete_frame_member`・`NodeGridAdapter::apply_block`・`nodes_table`。床と壁 |
| 解析準備は孤立版・荷重を候補段階で診断 | job `tests/assignment_identity.rs` → `prepare_model_for_analysis` |
| GUI は理由を表示し未更新、除去確認待ち/キャンセルで履歴不変、確認後 1 Undo/Redo | app `app/assignment_identity_tests.rs` → `sync_auto_load_cases_action`・GUI `apply_model_edit/resolve_plate_loss_edit`。配置の表・3D入口もこの共通経路を使う |
| MCP は確認なしで未更新、`confirm_plate_loss=true` で除去対象を返して確定、1 Undo/Redo | MCP `tests/assignment_identity.rs` → `apply_edit` |
| 別階同 XY は別 ID、削除 ID は再利用しない | core 既存 `別階で重なる床は別の割当領域になる`・`除去した領域のidを再利用しない` |

ID・割当・入力荷重と履歴は厳密一致を要求する。幾何は fixture の座標を直接比較する。
親 FloorRegionId/WallRegionId の不変は要求しない。

## 制限と対象外

支持境界の厳密な同一性は、面走査に使う座標の幾何許容差を撤廃する契約ではない。
節点移動で面が閉じなくなる、交点が移動して span が変わる場合は同一境界の保持対象外。
孤立版を別領域へ転用する救済や、近傍 span の同一視は行わない。
MCP は主架構追加・削除と節点座標変更の 3 命令を公開していないため、その輸送入口は対象外。
節点グリッドでは旧版を失う座標変更を確認付きで確定できず、診断して拒否する。
GUI の確認状態と編集入口を直接呼ぶ試験は、実マウスの全操作・全画面サイズの視覚確認を保証しない。
本レポートは状態契約の Verification。荷重分配、自重、構造応答、描画一般精度や実験 Validation を追加認定しない。
