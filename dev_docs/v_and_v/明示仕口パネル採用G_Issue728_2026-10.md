# 明示仕口パネルの採用G（Issue #728）

## 対象と根拠

対象は [Issue #728](https://github.com/hrntsm/SEPIKA/issues/728)、整理親は [#524](https://github.com/hrntsm/SEPIKA/issues/524)。基点は main `ecac69837edf9c3f8f085b2b383b20a8c3733ebc`。2026-10-21 に両 Issue と関連 [#585](https://github.com/hrntsm/SEPIKA/issues/585)・[#712](https://github.com/hrntsm/SEPIKA/issues/712) の全文を GitHub connector で独自取得した。

採用材料・式・単位・入力条件は[仕口パネル要素の剛性](../../docs/calc_basis/04_要素剛性/06_パネルゾーン.md)と[準備計算の仕口パネル](../../docs/preparation/06_仕口パネル.md)を正とする。本件は既存明示パネルの入力検証に限定し、参照柱の選択、通常梁のG検査、材料強度F、耐力式の軸力比・断面積、非線形履歴全体、新材種・接合形式・保存項目は変更対象としない。

## 変更前の経路の読取り

`crates/sepika-core/src/model/material.rs::Material::shear_modulus` は明示値を優先し、未指定時だけEとνから導出する。`resolve_panel_joint` が選択した柱と `Model::element_material` を通して採用材料を追跡した。#585の物理的な下側優先参照と、本件の採用Gの数値検査は別の契約である。

自動生成の `springs/panel_gen.rs::panel_at` はGと実効体積の積を有限正値として検査する。一方、明示要素の `springs/panel.rs::PanelZone::build` には、不正な積を `1e14 N·mm/rad` へ置換する経路がある。これはコード読取りであり、公開入口で補完や正常結果を観測した証拠とは区別する。#712の通常梁検査に先に拒否される入力も、明示パネル固有の検査に成功したとは数えない。

G=0を許容するモデル化条件は既存の仕口パネル仕様に存在せず、要素剛性と自動生成が要求する有限正値条件にそろえて入力不備として拒否する。不正なGの剛パネル補完を安全側と認定せず、新たな近似を加えない。

## 変更後の直接Verification

`resolve_explicit_panel_joint` に採用GとG・Veの検査を加え、明示パネルのモデル検証・直接線形入口・非線形入力診断と直接生成へ適用した。自動生成の汎用解決と断面検定の責務は変更していない。

文書担当が `target/issue728-final/public-entry-matrix.log` を独自照合した。同じCargoコマンドの対象1試験が成功し、正常3条件は全入口で成功した。不正9条件に、正の有限G=`f64::MAX`によってG・Veが無限大となる条件を加え、次を確認した。

- 自動生成は既存の接合部0・柱1を含む有限正値エラーで拒否する。
- モデル検証・公開準備・単発線形・増分解析は「接合部 ID 0 のパネル未算定: 柱 ID 1: せん断弾性係数 Gは有限の正値が必要です」を含むエラーとなる。有限Gの積オーバーフローでは対象量が「せん断剛性 G・Ve」となる。入口の付加文言や、非線形の通常梁診断の併記は区別する。
- 直接の線形・非線形パネル生成は同じ理由を `resolution_error` に保持し、K=0の失敗状態となる。要素更新もその理由で失敗し、K=0を正常なゼロ剛性パネルとして受理しない。剛性1e14への正常補完は行われない。

後続の `target/issue728-final/panel-zone-suite.log` は `cargo test -p sepika-solver --test panel_zone --locked -- --nocapture` による全10試験成功を示す。文書担当は原本を独自照合した。正常3条件・不正9条件・積オーバーフローに、G=1e−200 N/mm²、明示パネル板厚1e−200 mmの積アンダーフローを追加した計14入力を同じ公開入口試験で確認した。この場合もG自体は正の有限値で、G・Veを理由として全対象入口が拒否する。先行の対象1試験はこの10試験と重複し、11件とは数えない。

この試験は既存 `l_frame` fixture を使い、応答値の物理的Validationではなく、入力拒否・診断・正常対照のVerificationである。
