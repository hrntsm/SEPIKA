## XSDと公開取込の観測

修正版XSDでは柱・大梁に各 `ViaNode` が0または1個、その中に `StbNodeIdOrder` が1個、その後に `StbMemberOffsetList` が0個以上並ぶ。ID列は `monolist` 型で、正整数の列に `minLength=3` がかかる。PDFの対象節は端を除くよう指示し、§1.8は空の内容を禁止するが、最小3点は明記していない。中間が1点または2点の入力はXSDに適合しない。端の混入やIDの繰返しで個数を満たす方法は、節点列の意味を壊す。

XSDは要素の順序・必須属性・値の型を検証する。`StbNodes` のIDキーは定義されるが、当該ID列・`id_node` への参照制約はない。個々の参照の存在、列への所属、節点順、同じ中間点やオフセット対象の重複、各区間の正長などは別途照合が必要となる。`xs:double` で受理された `NaN` も有限な幾何量にはならない。

次の23条件を柱・大梁それぞれに適用した（46入力）。同じ全文書を上記XSD検証と両公開取込に用いた。公開取込は対照2入力で各2部材を生成し、残る44入力は各入口で同じ理由付きエラーを返した。

| 条件（各部材種に共通） | XSD | `import_stbridge` / `import_stbridge_with_report` |
| --- | --- | --- |
| 中間節点要素なし | 適合 | 成功。柱・大梁各1本の節点座標を照合 |
| 中間3点。直線でオフセット省略、節点自体が折れた線、非0中間オフセット、端と列の反転、非0中間オフセットとglobal変換 | 5例とも適合 | `ViaNode` で停止 |
| 端からの順序を入れ違え、列内ID重複、端ID混入、列内に未定義ID 999 | 4例とも適合 | `ViaNode` で停止 |
| オフセット対象が列外（存在する節点 / 未定義ID 999）、同じ中間点に異なる2オフセット、オフセット成分が `NaN` | 4例とも適合 | `ViaNode` で停止 |
| 空列、1点、2点、列要素欠落、列内ID 0、`offset_Z` 欠落、ID列より前にオフセット要素 | 7例とも不適合 | `ViaNode` で停止 |
| `StbMemberOffsetList` を柱・大梁の直下、または `StbMembers` 直下に置く | 2例とも不適合 | `StbMemberOffsetList` で停止。前者は親部材IDを報告。後者に前の部材IDを付けない |

適正な位置に置いた中間節点要素の診断には、親 `StbColumn id=Some(11)` または `StbGirder id=Some(21)`、対象タグ、理由「部材中間節点・中間offsetの配置変換は未対応です」が含まれた。
共通情報のglobal変換属性は先に読み取られる。中間節点列・中間オフセットの内容を処理せず、座標へglobal変換を適用する前に、対象の開始タグで停止した。[公開取込](../../crates/sepika-io/src/stbridge/import/mod.rs)・[開始タグでの診断](../../crates/sepika-io/src/stbridge/import/parser.rs)

## 独立幾何と入力の再構成

座標・距離はmm。版2.0.2、名前空間 `https://www.building-smart.or.jp/dl`。元の各節点座標を次とし、全節点を `kind="ON_GRID"` とした。

| ID | (X, Y, Z) | ID | (X, Y, Z) |
| --- | --- | --- | --- |
| 1 | (0, 0, 3000) | 6 | (3000, 0, 0) |
| 2 | (1500, 0, 3000) | 7 | (3000, 0, 6000) |
| 3 | (3000, 0, 3000) | 8 | (3000, 0, 1500) |
| 4 | (4500, 0, 3000) | 9 | (3000, 0, 4500) |
| 5 | (6000, 0, 3000) | | |

- 柱の組は柱11（下端6・上端7、中間 `8 3 9`）と大梁22（1→3）。大梁の組は大梁21（1→5、中間 `2 3 4`）と柱12（6→3）。親に対応する `ViaNode` を置き、列は `<StbNodeIdOrder>8 3 9</StbNodeIdOrder>` の形式で指定する。非0例は列の後に `<StbMemberOffsetList id_node="3" offset_X="0" offset_Y="200" offset_Z="0"/>` を置く。中間要素を親から外したものが対照。
- 共通情報は `project_name="test" app_name="test" app_version="1"`。両材種に `name` と `kind_structure="S"`、大梁に `isFoundation="false"` を付ける。柱断面1は `StbSecColumn_S`（`name="C" kind_column="COLUMN"`）の `StbSecSteelFigureColumn_S/StbSecSteelColumn_S_Same`、大梁断面2は `StbSecBeam_S`（`name="G" kind_beam="GIRDER"`）の `StbSecSteelFigureBeam_S/StbSecSteelBeam_S_Straight`。両図形とも `shape="H" strength_main="SN400B"` とし、`StbSecSteel` 内に `<StbSecRoll-H name="H" type="H" A="600" B="300" t1="12" t2="20" r="12"/>` を置く。断面回転・端オフセットは省略する。
- 直線では柱のZ・大梁のXが1500ずつ増え、4区間とも1500で計6000。折れ線例は節点3のYを200に変え、中間オフセットは省略した。非0例は節点3のYを0に戻し、対象部材の点だけを `P = N + d` で置く。柱図心・大梁の天端幅中心を追う幾何例として、両例で配置点は一致し、区間長は順に1500、√(1500² + 200²)、√(1500² + 200²)、1500、計6026.549190 mm。端間の直線長6000 mmとの違いは、配置点間の長さだけから確認できる。梁の折点にも天端幅中心を追うという前提を置いた計算であり、折点での材軸・断面姿勢の採用則は未確定。
- 非0例の元節点3は (3000, 0, 3000)、対象部材の配置点は (3000, 200, 3000)。他部材の端が参照するのは共有節点3であり、対象部材のオフセットはその参照先の座標に加えない。折れ線例では共有節点自体が (3000, 200, 3000) にあり、他部材の同じIDの端の節点座標も移る。両例とも部材間の接続表示を持つ。配置点の一致・交差から接合を推定しない。
- 共通変換例は `global_rotation="90" global_offset_X="100" global_offset_Y="200" global_offset_Z="300"`。点の変換は (100 − y, 200 + x, 300 + z)。共有節点3は (100, 3200, 3300)、非0の配置点は (−100, 3200, 3300) で差は (−200, 0, 0)。長さは変わらない。端と列をともに反転すると同じ位置列を逆順にたどり、`id_node="3"` の全体座標オフセットの符号は保存される。柱の下端・上端属性の入替えは幾何とXSDを照合するための例で、上端・下端の意味や断面姿勢まで同等とする根拠は確認していない。
- 別の端オフセットを考える独立算術では、上の非0例の第1点を元の直線に沿い+100、第5点を−50移しても中間3点の位置は変わらない。柱はZ、大梁はXにのみ加算する。各区間は1400、√2290000、√2290000、1450で計5876.549190 mm。この算術では端と中間の値をそれぞれの位置に一度だけ加えた。両端との距離だけを調整しても、200 mmずれた接続位置を幾何として再現できない。

異常系は、上の2組から列・ID・オフセットのうち表に示した箇所を変更して作った。順序誤りは最初の2 IDを交換し、重複節点は末尾を3へ変更した。列外の存在するIDは柱で1、大梁で6とした。重複オフセットはID 3のYを200と−200で指定した。

## 残る設計判断と依存

- PDF §1.1（本文1頁 / PDF13頁）は荷重・設計条件・解析モデルの詳細を別途「計算編」に委ねる。今回確認した配布ページからは計算編を特定できなかった。最小3点と本文の関係、大梁の中間オフセットに関する柱参照、および不正な順序・重複・参照の診断方針を詰める。XSD適合を解析成立や相互運用の判定に使うには、意味検証が別に必要となる。
- [現行本体の節点数検査](../../crates/sepika-core/src/model/aggregate.rs)は主架構線材を2節点に制限する。[#562](https://github.com/hrntsm/SEPIKA/issues/562) はこの境界の診断に関する完了済みの課題。正式取込の前提となる本体側の明示中間接続は、折れ・直線の分割、断面回転と折点での姿勢、各区間の実材軸・解析用長さ、接続自由度、端条件・剛域・パネル・継手・ハンチ・付帯情報の帰属を定める必要がある。梁天端を通る点列の長さを、そのまま図心軸の長さ・剛域除外長・解析要素長とする根拠は確認できていない。
- 共有節点にある節点荷重、元部材にある分布・集中荷重、自重・物理質量、支持先・階所属を保存して配分する方式は未確定。中間点のオフセットを外端値や剛域長へ併合すると、部材の折れや荷重の作用位置を表せず、荷重経路・応力・変形を変え得る。区間への機械的な複製や均等割りの安全性も確認できていない。元の1部材ID/GUIDと区間IDの対応を確定した上で、検定位置、断面力、結果表示・保存、再出力で元情報に戻せることを検証する。
- [親 #1361](https://github.com/hrntsm/SEPIKA/issues/1361) に従い、正式対応の設計・検証は両端偏心の [#1367](https://github.com/hrntsm/SEPIKA/issues/1367) の完了条件から独立する。今回の観測は同Issueの理由付き拒否を維持する根拠となる。[#455](https://github.com/hrntsm/SEPIKA/issues/455) は端オフセットに中間オフセットを併合しない論点の参照先で、旧実装指示は見送りで閉じている。製品実装の変更、分割後の解析実行と物理Validation、保存・再出力の意味的往復は本記録では未実施。
