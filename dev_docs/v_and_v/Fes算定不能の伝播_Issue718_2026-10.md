## 重心集計の演算不能の追補

## 剛心・ねじり剛性の実集計と利用側の追補

親監査の 4 列 `pos=(0,0),(.5,0),(0,0),(.5,0)`、全列 `dx=1, dy=10³⁰⁸`、重心 `(.25,7×10¹⁵²)` を実行した。
`cargo test -p sepika-design-jp --locked fes718_rigidity` は修正前 2 件失敗。
生ログ `issue718-design-rigidity-red.log` で core と実精算入口の双方が KR=5×10³⁰⁷、半径 X=3.5355339059327376×10¹⁵³、
正常な ReX=0.1979898987322333 を出力した。Y の Re は半径 0 による Err だったが、App は X の距離/半径から再計算できていた。
精算 fixture は同じ柱剛性に、質量重心 (.25,7×10¹⁵²) を与える質量節点を追加した人工静的結果である。

`center_of_rigidity` は実剛性合計・位置一次合計・座標除算を検査し、`eccentricity` は偏心距離・方向別剛性・KR・半径の実演算を検査して `Result` で返す。
方向の剛性合計 0 に対する座標 0、半径 0 に対する Re の算定不能、通常の物理式は維持する。
精算入口は core の失敗を層付き Err として返し、App が距離/半径を取り出して正常な Re を再生成する前に停止する。

共有 API の利用側 `sepika-job/src/lumped_mass.rs::build_spatial` の 2 呼出も、既存 `JobError` に層と理由を伝播する。
質点系の入力採用や物理式を変更せず、既存の動的質量・J の診断優先を維持した。
共有する剛心/KR の演算不能拒否は 3 次元質点系の準備の適用条件にも及ぶため、最終計算契約版を解析 35 / 検定 21 とした。
解析 34 据置の当初判断を撤回し、旧解析 34 / 旧検定 20 の失効へ製品文書と保存結果検証を追随する。
