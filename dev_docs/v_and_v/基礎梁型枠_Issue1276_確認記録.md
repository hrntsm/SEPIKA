# 基礎梁の型枠対象面と幅ハンチの確認

[Issue #1276](https://github.com/hrntsm/SEPIKA/issues/1276) · 2026-11-19

公共建築数量積算基準では基礎梁の側面を計上し、底面は必要時に計上する。施工面を決める情報がモデルにないため、
側面1面＋底面を一律に施工数量として使える範囲は確立できなかった。幅ハンチ係数1も、底面投影の幾何や
確認した積算規定からは導けない。[現行の算定条件](../../docs/calc_basis/10_数量積算/01_数量積算の算定式.md#基礎梁)
を明記し、実入力から連続して観測できる例で現行値を検証した。型枠数量としての妥当性確認と今後の採用判断が残る。

## 施工条件と概算の過不足

比較するのは打込み時に型枠を設ける側面・底面の面積。次の適否は条件を置いた面の拾い方を示す。
土に接していることや既設躯体が隣にあることだけで、打込み時にコンクリートを受けられるとは判定できない。
接続が部分的な場合は接続の位置・長さ・高さで面積が変わる。接続部の積算上の控除と、打込み順・せき板の実使用は個別に確認する。

幅0.30 m、せい0.60 m、内法6.00 mのハンチなし矩形梁では側面1面3.60 m²、底面1.80 m²となる。
床接触なしでの現行概算は5.40 m²。

| 打込み時の納まりの仮定 | 必要な面 | 比較面積 [m²] | 現行概算−比較 [m²] |
| --- | --- | ---: | ---: |
| 左右と底面とも別の受けがなくせき板が必要 | 両側・底面 | 9.00 | −3.60 |
| 一方の全側面を既設躯体等が受け、反対側と底面にせき板が必要 | 片側・底面 | 5.40 | 0.00 |
| 梁底全面を捨てコンクリートや先行底盤等が受け、左右にせき板が必要 | 両側 | 7.20 | −1.80 |
| 一方の全側面と梁底全面を別の部材等が受け、反対側にせき板が必要 | 片側 | 3.60 | ＋1.80 |

差が負なら数量を過小、正なら過大に拾う。両側だけが必要な場合の差は幅とせいの差×内法で決まり、幅がせいを超える矩形なら
総面積の符号は逆になる。この場合も、側面の不足と底面の過計上が同時に生じる。
既設面等に代替させる納まりは条件付きの幾何例であり、工法の適格性や実物件での使用は未確認。
施工数量での「過小・過大」は面積の比較で、構造安全性や型枠の強度・支保工の適否を保証しない。

## 独立追算と公開入口

上記の矩形を基準とする。水平投影において、端の幅が100 mm広がり、長さ1000 mmで線形に基準幅へ戻る。
加わる輪郭は、片側に拡幅する形状なら底辺1000 mm・高さ100 mmの三角形1つ、
左右対称なら同じ底辺で高さ50 mmの三角形2つ。いずれも面積の和は0.050 m²となる。
基礎梁が加える0.100 m²はこの投影面積の2倍であり、幅の100 mmは断面全幅の増分なので各側に100 mmずつ足せない。
せいが200 mm増す場合は、側面投影1面に別の三角形0.100 m²が加わる。せい増分は底面投影を増やさない。

| 端部の入力（長さ、全幅増分、せい増分）[mm] | 片側・底面の投影 [m²] | 基礎梁の現行値 [m²] | 大梁の現行値 [m²] |
| --- | ---: | ---: | ---: |
| ハンチなし | 5.400 | 5.400 | 9.000 |
| i端またはj端 (1000, 100, 0) | 5.450 | 5.500 | 9.050 |
| i端 (1000, 100, 200) | 5.550 | 5.600 | 9.250 |
| i端 (1000, 100, 200)、j端 (500, 60, 0) | 5.565 | 5.630 | 9.265 |

i端に幅・せいハンチがある例では、両側と底面が必要なら投影は9.25 m²で、現行値は3.65 m²不足する。
両側だけなら7.40 m²で1.80 m²不足し、片側だけなら3.70 m²で1.90 m²過大となる。
片側・底面の投影に対しては幅増分の0.05 m²だけ過大になる。いずれも投影の比較である。
実面積は勾配でも変わる。例えば幅を左右均等に広げ、上端を水平に保って下方に増せいする形状では、
ハンチ区間の側面1面の投影0.70 m²を幅勾配50/1000で、底面の投影0.35 m²を下端勾配200/1000で補正し、
非ハンチ区間の4.50 m²を加えると片側と底面の実面積は約5.558 m²になる。この例は実面積としての係数1も裏付けない。

公開入口 `sepika_design_jp::quantity::try_compute_quantity_takeoff` に、各端で柱面を350 mm控除する
節点間6700 mmのRC架構を与えた。[公開APIの統合テスト](../../crates/sepika-design-jp/tests/foundation_formwork.rs) の
`foundation_formwork_width_increment_counts_twice_the_bottom_projection` で大梁・基礎梁の分類と
表の現行値を観測する。許容差は1e−9 m²。
[既存の数量走査テスト](../../crates/sepika-design-jp/src/quantity/tests.rs) の
`beam_contact_direct_support_span_secondary_and_vertical_union` は床が接する基礎梁で公開入口が理由付きのエラーを返すことを確認する。

分類に用いる標高・節点、梁内法、断面、端部ハンチと床接触の幾何は入力から確認できる。
現行の基礎梁分岐は `quantity::beam_quantity` から `quantity::member::foundation_girder_formwork_area` を呼び、
施工の左右・底面や打込み順を受け取らない。床接触がある場合は対象側面を特定できず、型枠を含む全体数量が未算定になる。
床が接しない場合の有限値も、地業や底盤・山留め等の施工面が確認できたことを表さない。

Windowsで `cargo test -p sepika-design-jp --locked --test foundation_formwork`、
`cargo test -p sepika-design-jp --locked`、
`cargo clippy -p sepika-design-jp --all-targets --locked -- -D warnings` は成功した。
`check-docs`、`mdbook build docs`、基礎梁節の生成HTMLとV&V索引リンクの静的確認も成功した。
ブラウザの組版・画面操作は確認していない。

## 維持範囲と後続の判断

現行値は既存の概算として残し、施工数量は施工図・施工計画から必要面を確認して拾う。
側面の不足を幅増分の過大で相殺する根拠は確認できず、係数1/2に変えても左右や底面の採否は解決しない。
後続で施工数量を扱う場合は、施工図で左右・底面の必要範囲、底盤等の接続面、打込み順を確定し、
その指定を使う面別集計と、条件不明時の未算定・診断を設計する。勾配の実面積と規定上の投影・控除は
適用する積算条件で区別し、対象面と各控除の独立期待値を使って公開入口と各表示を検証する。
既存出力への概算範囲の注記は [#1460](https://github.com/hrntsm/SEPIKA/issues/1460) で追跡する。
現行値の表示を概算用途に制限するか、施工条件未入力時に抑止するかは仕様判断として残る。
片面・底面の実施工照合、係数1の原出典、全基準適合、採用方式変更は未確認・未実施。
