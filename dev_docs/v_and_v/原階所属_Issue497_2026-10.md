# 原階所属 — Issue #497

対象は [Issue #497](https://github.com/hrntsm/SEPIKA/issues/497) の原階・標準節点識別子供給、解析所属との分離、明示編集・削除の復元。2026-10-10 に Verification を実施した。構造応答の Validation、全 STB 相互運用、全材料解決の完了を示すものではない。

## 参照解・資料固定

属性と階条件は [公式PDF 2.0.2（2022-06-15）](https://www.building-smart.or.jp/wp-content/uploads/2022/06/ST-Bridge_XML%E4%BB%95%E6%A7%98%E8%AA%AC%E6%98%8E%E6%9B%B8%EF%BC%88ver.2.0.2%EF%BC%89_20220615.pdf) 本文57–58、Fcの順序は本文20を参照した。height は GL から意匠 FL の mm。Fc は N/mm²。

採用 XSD は [公式2.0.2 ZIP（2026-04掲示）](https://www.building-smart.or.jp/wp-content/uploads/2026/04/ST-Bridge_v202.zip)。Issueで固定されたZIP SHA256は `f69d4ee1c4b162f50a1a05ba13c948996d743924f1eeebd7016de866a5b4da8d`。本実行で公式URLはHTTP403だったため、[公開固定mirror](https://raw.githubusercontent.com/Code-Hex/go-bim/ad8c8a96705b1dd6e8d633963af70d7c3cae1bc3/stbridge/reference/xsd/ST-Bridge_v202.xsd)から取得した原本331047 bytesのSHA256が採用原本の `56cc1b80062c2385c15f8ab0745f4e96ac5b9400a4743307031e813d0253a1fa` と一致することを確認した。先頭ASCII `o;?` の3 bytesだけを除いた検証用派生のSHA256は `d854bf431d395ace4a7917a63ebed431d251e5bb2fbf7fbea26e9e195fdfa2b6`。lxml 6.1.1 / libxml2 2.14.6でcompile・検証した。

## 公開fixtureと意味的往復

公開構造モデルの固定 [原本URL](https://raw.githubusercontent.com/hrntsm/HoaryFox/f991f97df99e307c449c4c0bc0cb85b514cc5e8c/Samples/SampleBuilding.stb)、SHA256 `83d35a8eeb57177d409766804e36288ff325d141d05a7cba4b58fff221257629`、83288 bytes。原本の全XML schema検証は StbCommon.app_version 欠落により不合格。原本が標準適合したとは扱わない。

本件に対応する [fixture](../../crates/sepika-app/tests/fixtures/public_source_stories_497.stb) は原本の StbNodes（126節点）・StbStories（6階）を切り出し、envelope と必須 StbCommon 属性だけを検証用に作成した派生物。原階属性・節点座標・明示列・ID/GUIDを変更していない。部材・断面は含まない。派生fixture SHA256は `94aff5d2e84e2a1fd60a2e0fdc7d332468cb2a279f992b0748f081e9b500969d`。

この派生fixture **全XML**とSEPIKAの出力 **全XML**を採用XSDで検証し合格した。StbStory部分だけのschema検証ではない。元属性・明示列、節点ID/GUID/座標を独立XML比較し厳密一致、実import→export→importでも原階テーブル・節点識別子が一致した。連続無編集exportも同一文字列。再現:

```bash
cargo run -p sepika-io --example roundtrip_stories --locked -- \
  crates/sepika-app/tests/fixtures/public_source_stories_497.stb /tmp/497-source-fixture-export.stb
python dev_docs/v_and_v/validate_source_story_497.py /tmp/ST-Bridge_v202.xsd \
  crates/sepika-app/tests/fixtures/public_source_stories_497.stb /tmp/497-source-fixture-export.stb
```

検証スクリプトは原本/派生XSD・fixtureの固定hash、全XML schema、原属性の意味的比較を個別に検査する。

## 編集・再生成・独立数値検証

[直接統合試験](../../crates/sepika-app/tests/source_story.rs) の入力はID50/80/20/5/2とheight9000/-3000/0/3000/6000、地下/塔屋/屋上/従属階と Z3100の段差節点。ID大小を高さ順として使わない。許容差は属性・識別子・所属の厳密一致、Fc数値の厳密一致。

- prepare2回と移動→prepare→exportで元テーブル・GUID・外部節点ID・Fc27参照が不変。解析推定との差を別診断。
- 節点削除で原所属・分析所属・識別子参照を同transactionで除去し、undo/redo・内部節点再採番でも復元。新規階/節点の正整数IDは編集時に保存、undo/redoと削除後でも保持。未採番nativeの初回削除でも残存節点の標準ID2/3/4/5が変わらず、undoで元の未採番保存状態に復元。
- 所属変更undo/redo、OVIKA保存復元、snapshot後編集が元snapshotを変えないこととrevision増分を確認。
- 同height、DEPENDENCE欠落/不明/自己/循環、未知節点、多重所属を生成入口・共通precheckで診断。必須属性欠落をimportで拒否。
- 原階FC27/FC24・共通21の入力に対し、明示部材36→36、断面30→30、両省略→原階Fc競合。共通21への迂回を拒否。未知原階gradeも下位へ落とさない。上位Fc確定でも階依存所属のエラーは独立に残る。

これは #497 の **供給API** への独立数値試験である。部材/断面/common元指定の全保存や element_material の動的な材料消費接続は [#520](https://github.com/hrntsm/SEPIKA/issues/520) に残る。STB kind は Frame/WallBuilding を推定しない。現行に階別設計法型がないため、#492の新機能を追加していない。

## GUI/MCP・入力世代

GUIの準備計算パネルとMCP `SetSourceStoryNodes` は同じ編集コマンドを使用。GUI pending操作とMCP edit実入口の試験で有効編集・未知節点拒否理由・共通診断の一致を確認。GUI結果input bytesは所属編集で変わり、undoで元値、redoで変更値に戻る。拒否編集はrevisionを増やさない。

MCPのモデルclone snapshotは後続編集の原テーブルから独立する。非同期結果を現在モデルへ公開する際の世代照合は本件で再設計しておらず、[#463](https://github.com/hrntsm/SEPIKA/issues/463)/[#464](https://github.com/hrntsm/SEPIKA/issues/464)/[#502](https://github.com/hrntsm/SEPIKA/issues/502) の残課題。snapshot保存と結果fresh/staleを混同しない。

## Scope外の実出力不合格

公開原本に app_version だけ追加した全構造検証用派生（SHA256 `a37f1e9e9b12035c00a921b10c445b22690fb75264872d6b152f5c39f7ee8ca4`）は入力全schema合格。SEPIKA全構造出力 `/tmp/497-public-model-export.stb` は元6階/126節点識別子の意味的往復が合格する一方、**全schemaは不合格**。

- RC梁の pitch_stirrup/N_stirrup=0と必須主筋属性欠落：[#507](https://github.com/hrntsm/SEPIKA/issues/507)。
- Sブレースのliteral `\n` が要素本文に出る：[#550](https://github.com/hrntsm/SEPIKA/issues/550)。

これらを部分fixtureの合格で代用せず、標準STB完全出力の未完として残す。
