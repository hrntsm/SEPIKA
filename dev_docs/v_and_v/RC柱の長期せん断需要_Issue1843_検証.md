# RC柱の方向別長期最大せん断力（#1843）

状態🔶。矩形・円形の通常の長期保存組合せで、方向別の最大せん断力と位置を独立釣合いと照合した。本文・解説・構造設計例から採用区間を判断した経緯と、従来の通常検定が最大値を見逃す条件は [#1836の照合記録](RC柱の長期せん断需要_Issue1836_照合記録.md) に保持する。現行の適用条件は [RC柱のせん断検定](../../docs/calc_basis/06_一次設計/02_04_RC柱のせん断検定.md#長期せん断の検定位置) を参照する。

## 原典と採用境界

日本建築学会『鉄筋コンクリート構造計算規準・同解説』2024年版の第15条2項(1) ii)（p.20）、柱の設計目標と設計用せん断力の解説（pp.177–178）、計算例2（p.205）、付2の断面設計(1)（p.438）の原画像を2026年11月22日に確認した。第15条は最大値を要求する。付2は断面算定用の長期内力に材端フェースを採り、計算例2は長期75 kNを許容661 kNと比較する。両フェースで柱区間を定める採用判断は [ADR 0145](../adr/0145-rc-column-long-term-shear-span.md) に記録した。

## 独立期待値と通常検定

節点芯間3,000 mmの片持柱の柱脚に幅300 mm×せい600 mmの水平RC梁を接続した。柱は矩形400×600 mmと円形D600、普通コンクリートFc24 N/mm²。荷重は保存組合せDL＋LLによる。局所yに柱頭荷重12 kNと、柱に全長1 N/mmを与える。既定の部材検定位置はi端から300、1,500、3,000 mm。個別の検定位置の軸力・曲げは、その位置の解析内力に一致することも確認した。 [共通のモデル入力](../../crates/sepika-design-jp/tests/fixtures/rc_column_long_term_shear_model.rs)

基準例で、切断面より上の鉛直片に作用する局所y荷重の和は 12,000＋(3,000−x) N。材端フェースx=300 mmで14.7 kN、除外する柱脚節点芯では15.0 kNとなる。局所yに−6,000 N/mmと＋6,000 N/mmを50 mmずつ連続して載せる例では、間の切断面の上に300 kNが加わる。各算定結果から局所yとzを別々に確認した。

| 条件 | 独立な最大需要と位置 | 通常のせん断比・判定 |
| --- | --- | --- |
| 矩形、基準 | Qy 14.700 kN、300 mm | 0.106446、3行OK |
| 円形、基準 | Qy 14.700 kN、300 mm | 0.091650、3行OK |
| 矩形、1050–1150 mmの相殺分布荷重 | Qy 313.900 kN、1,100 mm | 2.273028、3行NG |
| 円形、同じ相殺分布荷重 | Qy 313.900 kN、1,100 mm | 1.957064、3行NG |
| 矩形、回転梁、基準 | Qy 14.850 kN、150 mm | 0.107533、3行OK |
| 矩形、回転梁、175–275 mmの相殺分布荷重 | Qy 314.775 kN、225 mm | 2.279364、3行NG |
| 矩形、梁の上面と柱脚節点芯が一致 | Qy 15.000 kN、0 mm | 0.108619、せん断OK |
| 矩形、二方向に分布荷重 | Qy 313.900 kN、1,100 mm。Qz 36.000 kN、1,600 mm | 方向別 2.273028 / 0.275869、3行NG |
| 矩形、同じ二方向例のz方向荷重を8.3倍 | Qy 313.900 kN、1,100 mm。Qz 298.800 kN、1,600 mm | 方向別 2.273028 / 2.289714、Qz比で3行NG |

回転梁では90°回転により梁の幅300 mmが鉛直方向となる。柱脚節点芯から150 mmが実フェースで、準備計算の公称フェースと既存の検定行は300 mmのままである。ピークの225 mmは150–300 mmの間にあり、実フェースから探索しない場合は見逃す。斜めに回転した梁で一つの断面位置を確定できないモデルは、理由付き未算定を確認した。

梁の材軸を鉛直方向に−300 mm移した例では、梁の上面が柱脚節点芯ちょうどに接するので、柱軸上の探索は0 mmから始まる。−320 mm移した対照では柱脚と梁に20 mmの隙間が生じ、接合境界を確認できない理由を出した。接続梁が複数ある場合は、実フェースがともに300 mmなら14.700 kNを採り、150 mmと300 mmの候補に分かれる場合は理由付き未算定となった。同軸で反対向きに続く柱を加えた対照は14.700 kN。同軸で検定柱の区間に重なる柱を加えた例は理由付き未算定となった。

二方向の例では固定荷重係数0.25と0.75を合成する。局所zには800–2,800 mmの固定荷重＋50→−50 N/mmと積載荷重−10 N/mmを与えた。合計強度は1,600 mmで0となる。この位置から分布の終点までの三角形の面積は 1,200×60/2 = 36,000 N。z方向の荷重を8.3倍した例では、Qzの最大値はQyより小さい。対応する許容値が小さいため、Qzの検定比が支配することを確認した。

## 集中荷重と未算定

集中荷重の独立値は切断面の柱頭側に残る節点荷重・部材集中荷重・分布荷重の合力で求め、定義した切断側で照合した。

| 位置 | 採用した側 | 最大 Qy |
| --- | --- | ---: |
| i端側フェース、300 mm | j端側 | 27.400 kN |
| j端側フェース、3,000 mm | i端側 | 10.000 kN |
| 柱区間の内点、1,000 mm | j端側 | 314.000 kN |
| 柱区間の内点、1,100 mm | i端側 | 310.100 kN |

300 mmの材端フェースから10⁻¹¹ mmだけ離れた400 kNの集中荷重では、位置関係を確認できない方向とその理由を表示した。

保存荷重組合せの由来を渡さない場合は長期せん断を未算定とし、独立な軸力・曲げのNGを確認した。引張専用ブレースの反復を有効にした保存組合せでも、各ケースを合成した解を確定扱いしない。解析結果の一方向だけを意図的に変更した場合は、同方向の釣合いが成立しない理由と、もう一方向で確定したせん断NGを併記した。柱全体の内力欠落、フェースの未算定、材端偏心、仕口パネル、壁側柱の診断も確認した。壁側柱は共通検定へ渡す入力に壁要素を追加して診断を確認した。ファイバー・マルチスプリングは標準準備でフェース距離が得られず、部材の長期せん断を未算定とした。明示された単独長期ケースでは従来の局所せん断を確認した。

両材端フェースが節点芯より内側の柱で、通常の検定断面の内力を除き、節点芯2点の内力を渡した。局所軸力・曲げと許容値を決めるαの参照が不足する理由を表示した。照合済みの局所y最大需要313.9 kNは、α=1.5で求める長期許容上限を超える。矩形の上限207.1466 kNに対して検定比の下限は1.515352、円形の240.5900 kNに対して1.304709。両形状で位置1,100 mmの独立したせん断NGを保持した。上限に達しない対照では適否を確定しなかった。

同じ柱IDの内力系列を複製し、片方の局所yせん断力の全断面に500 kNを加えた。部材荷重との釣合いを満たす系列が複数あっても、一意性を確認できない旨を表示した。別柱については重複入力の前後で結果が一致した。

## 再現と検証範囲

[公開解析・通常検定の統合試験](../../crates/sepika-job/tests/rc_column_long_term_shear.rs) をWindows x86_64-pc-windows-msvc、Rust stable 1.100.0で実行し、16件が成功した。独立釣合いとの許容差はせん断力10⁻⁵ N、曲げ10⁻² N·mm。表示した需要・位置・切断側と、軸力・曲げの既存局所需要も照合した。

```text
cargo +stable test --locked -p sepika-job --test rc_column_long_term_shear -- --nocapture
```

[アプリの通常検定・保存の統合試験](../../crates/sepika-app/src/app/rc_column_boundary_tests.rs) は、両断面の保存長期組合せで313.9 kNと採用位置を確認した。解析版108の保存内力を用い、保存検定版102、103の旧検定を破棄した。保存検定版104の対照は読込直後から利用できる。いずれも明示的な再検定後の内力と検定結果全体が新規検定に一致した。GUI機能を有効にした自動試験で確認した。

未確認の範囲は、長期許容せん断力のαの採用条件、二方向の相関、適用外とした接合条件、実験Validation。既存の局所検定位置に関しては、材中央を越えるフェースを [#1845](https://github.com/hrntsm/SEPIKA/issues/1845)、回転した梁が接続する柱を [#1846](https://github.com/hrntsm/SEPIKA/issues/1846) で扱う。ファイバー・マルチスプリングの準備でフェースを取得する条件は [#1532](https://github.com/hrntsm/SEPIKA/issues/1532) に既報。αの選定は [#1841](https://github.com/hrntsm/SEPIKA/issues/1841) で追跡する。
