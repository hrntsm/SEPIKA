## 固定標準と撤去経路の照合

根拠はbuildingSMART Japanの[公式2.0.2 XSD配布](https://www.building-smart.or.jp/wp-content/uploads/2026/04/ST-Bridge_v202.zip)。
今回使用する固定XSDは `ST-Bridge_v202-normalized.xsd`、SHA-256は
`d854bf431d395ace4a7917a63ebed431d251e5bb2fbf7fbea26e9e195fdfa2b6`。
原本XSDのSHA-256は `56cc1b80062c2385c15f8ab0745f4e96ac5b9400a4743307031e813d0253a1fa`。
名称だけで独自形式と判定せず、同じ要素名・属性名・階層を照合する。

| 旧入力経路 | 固定XSDの根拠と残す標準入力 |
|---|---|
| 独自 `StbMaterial` と `id_material` / `id_material_concrete` / `id_material_rc`、部材から断面への材料参照救済 | `StbModel` の子は `StbNodes` / `StbAxes` / `StbStories` / `StbMembers` / `StbSections` / `StbJoints`。独自材料表を持たず、対応部材・断面等の `strength_concrete`、部位別強度と共通径別強度を残す |
| `StbSecRaw` の物性直読と標準断面参照の救済 | `StbSections` の標準断面系列に `StbSecRaw` はない。Raw入力を認識せず、そこへの断面参照は通常の参照不正となる。内部のRaw中間型を名称だけで削除しない |
| RC/SRC図形の寸法別名、床・壁の親属性からの厚さ救済 | 柱矩形は図形子の `width_X` / `width_Y`、円形は `D`、梁は `width` / `depth`。床は `StbSecFigureSlab_RC/StbSecSlab_RC_Straight@depth`、壁は `StbSecFigureWall_RC/StbSecWall_RC_Straight@t` |
| 形鋼の寸法・タグ・非対称Hの独自別名 | `StbSecSteel` の圧延/組立Hは `A` / `B` / `t1` / `t2`、圧延BOXは `t`、組立BOXは `t1` / `t2`、鋼管は `StbSecPipe@D,t`。`StbSecRoll-Pipe` / `StbSecBuild-Pipe` / `StbSecBuild-T`、`B2` / `t2_lower` は該当標準要素・属性でない |
| 鋼断面親の強度、`shape_start` / `shape_center` / `shape_main` 救済 | 対応する鋼材図形子の `shape` と `strength_main` を使う。CFTの鋼管強度 `strength` と区別する。SRC親の `strength_steel` / `strength_main_S` は標準属性でなく、標準の内蔵鋼材子の強度を残す |
| 配筋の `dia_*` / `cover` / `kaburi`、柱帯筋と梁あばら筋の別名共有、任意段数・合算本数救済 | 梁は `SecBarBeam_RC_Same` 等の属性群の `D_main` / `N_main_top_1st`〜`3rd` / `N_main_bottom_1st`〜`3rd` と `D_stirrup` / `N_stirrup` / `pitch_stirrup` / `strength_stirrup`。矩形柱は `N_main_X/Y_1st/2nd` と `N_band_direction_X/Y`、円形柱は `N_main`、柱帯筋は `D_band` / `N_band` / `pitch_band` / `strength_band`。`StbSecBarColumnXReinforced` の `N_main_X` / `N_main_Y` / `N_main_total` は標準なので残す |
| 配筋子へ置いた `depth_cover*` / `center*` の救済 | 正式なRC/SRC梁・柱の4つの `StbSecBarArrangement*` コンテナにある任意長さ属性であり、14種の配筋子の属性ではない。正しいコンテナとApply条件の実効属性を経由する読取・原保存は維持する |
| 通常の節点・断面・必須形鋼参照欠落を警告だけで継続 | 既存の組立結果伝播で取り込み全体を失敗させる。床・壁で明示された参照の不存在も対象。既存の断面参照省略や真未割当壁の取付き変換を一律拒否に変えない |

`ST_BRIDGE` 直下の `StbExtensions` / `StbCalData`、解析モデル配下の `StbAnaMaterial` は標準に存在する。
名称を根拠に旧形式と断定せず、専用検出器を作らない。これら全情報の利用・保存を保証したものでもない。

### 独自形鋼タグと既存の標準未対応

`StbSecSteel` の正式タグは `StbSecFlatBar`（`B,t`）、`StbSecRoundBar`（`R`）、`StbSecLipC`（`H,A,C,t`）。
旧 `StbSecRoll-*` / `StbSecBuild-*` の平鋼・丸鋼・リップ溝形別名は撤去する。
正式3タグの既存の取込接続不整合は[#700](https://github.com/hrntsm/SEPIKA/issues/700)へ分離し、今回対応済みとはしない。
特にLipCの `H` と `A` は同じ寸法の別名ではない。

## 独立入力と観測契約

- `crates/sepika-io/tests/stbridge_standard_input.rs`：exportから生成しない標準XMLで疎なID、H/組立H/鋼管、RC寸法とgradeを両公開import入口に渡す。通常の節点・断面・形鋼参照不正と、小梁・床・壁の参照不正を同じ入口で拒否する。
- `crates/sepika-io/tests/stbridge_standard_rebar.rs`：RC/SRC梁、矩形RC/SRC柱、円形RC柱の標準配筋、正式コンテナのcover/center、Apply要素の不在/false/true、部材Fc36・断面Fc30・共通Fc24の優先と鉄筋gradeを観測する。原コンテナ属性・XReinforced・SRC鋼材子の保持とOVIKA保存/再読込も対象とする。
- `crates/sepika-io/src/stbridge/{tests,rebar_tests,strength_tests}.rs`：旧互換だけを目的とした入力期待を整理し、独立標準入力または内部編集で既存の観測契約を維持する。標準入力の失敗をskip/ignoreや期待値緩和で隠さない。
- `crates/sepika-app/src/app/reference_identity_acceptance_tests.rs`：実App読込の失敗時にモデル・Undo・結果世代を変更しないことと、内部編集・OVIKA再採番の保持を対象とする。

両公開入口は `import_stbridge` と `import_stbridge_with_report`。XMLのXSD適合、公開importの受理/拒否、App状態保持は別の証拠とする。
固定XSDへ適合することだけで、製品の数値解釈・全標準対応を確認済みとしない。

## 維持する境界と未検証範囲

内部の任意物性・強度・編集とOVIKAは撤去対象でない。STBのFc優先順位、部位別鉄筋強度、標準gradeと明示材料数値の区別を維持する。
解析契約25・検定契約17・OVIKAスキーマ1を本件では変更しない。
exportコード・出力fixture・Raw出力契約は変更せず、開発中・機能不足表示を維持する。Rawの出力再読込成立を受入に使わない。

具体的断面系列＋数値IDの全接続・系列間ID重複は[#571](https://github.com/hrntsm/SEPIKA/issues/571)、
L/Cの既存寸法・向き等は[#613](https://github.com/hrntsm/SEPIKA/issues/613)、
組立BOXの `t1/t2` と内部一様板厚の不整合は[#683](https://github.com/hrntsm/SEPIKA/issues/683)に残る。
位置別配筋、面別cover/center、未対応の鉄筋座標等を新しい近似で補わない。今回の互換撤去は既存の数値近似の安全性確認を意味しない。
全STB標準対応・全ファイルのXSD適合・完全な相互運用・実験Validationは未確認。
MCPにはSTB公開入口がなく、新しいMCP専用受入は設けない。desktop手動GUI・利用先での出力確認も未実施。
