# 外部ID入力拒否（Issue #603）

## 対象と独立期待

[Issue #603](https://github.com/hrntsm/SEPIKA/issues/603) の外部整数ID拒否契約を検証する。基準mainは `a42f3631dd3736ec4137e212568cbca360d75904`、対象コードSHAは `1d9068c26f36e9139576f07beccf4c6f37fb2f34`。

独立期待はu32の表現範囲 `0..=4294967295` とJSON/XMLの型仕様に置く。`4294967296` は床0の別名ではない。負数・小数・JSON文字列・null・型不正・必須省略は拒否し、任意IDの省略/nullだけを未指定とする。XML属性は数値文字列を受理し、存在する不正属性は省略扱いや別alias/グレードに逃がさない。範囲内IDの存在・0の個別有効性は従来どおり別の条件で判断する。

解析契約版6・検定契約版3、OVIKA schema1を維持する。入力拒否だけの変更で、正常モデルの計算式・解析準備・成果生成入力を変更しないため、[#587](https://github.com/hrntsm/SEPIKA/issues/587) の成果版更新条件に該当しない。[ADR0014](../adr/0014-schema-compatibility.md)に従い旧不正入力を互換受理しない。

## 到達経路の棚卸し

| 入口/対象 | 必須・任意 | 読取契約 |
|---|---|---|
| 手書きMCPの壁版/床板 | `id` 必須 | Delete、Section、Attrs/Usage/OneWay、Extent、AnchorのIDを共通serde u32で検査 |
| 手書きMCPの割当領域 | `region` 必須 | Assign、NoPlate、Unsetの床/壁共通検査 |
| 手書きMCPの床/壁領域 | `id` / `floor_region` / `wall_region` / `region` 必須 | Name、SecondaryBeams、Posts、Place。既存alias優先順保持、不正primaryをfallbackしない |
| 手書きMCPの二次部材 | `member` 必須 | Delete、Ends、EndSupport、PostGravityEndShares |
| 手書きMCPの断面 | `section` 任意 | 未指定/null=None、不正指定値は拒否 |
| 型付きserde | 各ID型・SecondaryMember・RegionAnchor・SlabPlate | u32の既存Deserializeで型/範囲拒否、親fieldを診断 |
| STB節点/材料/断面定義 | `id` 必須 | 既存get_u32のまま範囲検査 |
| STB柱/梁/ブレース/小梁/間柱 | 端点必須、断面/材料/source id任意 | 指定値をget_opt_u32で検査、None化や切り捨てなし |
| STB床/壁 | section/source id任意、壁のmaterial任意 | strength保持経路を含め指定属性を検査 |
| STB RC/SRC/CFT断面の材料 | `id_material` / `_concrete` / `_rc` 任意 | 全存在値を検査後、従来の優先順位で選択。省略時だけstrength_concreteへ代替 |
| STB床/壁境界 | StbNodeIdのid必須、StbNodeIdOrderの各トークン | 不正IDを捨てず全文書読込を失敗。Orderは順序整数ではなく節点ID列 |
| STB出力の未割当線材断面 | 参照なし | 属性省略。負数sentinel -1を出さない |

STB全書類入口は `import_stbridge` と `import_stbridge_with_report` をそれぞれ呼ぶ。parserが拒否した時点でassembleへ進まず、部分モデルは呼出側へ返らない。GUIのSTB読込は成功モデルを受け取ってから差替える既存構造で、今回はGUIコードを変更しない。

ログは `/workspace/issue603-workflow/logs/` に保持する。`CARGO_BUILD_JOBS=1`、`CARGO_INCREMENTAL=0`、追加RUSTFLAGSなしで実行した。

- `io-test-01.log`: 初回sepika-io単体は158成功/5失敗/1ignored。正常roundtripの5失敗は未割当断面の製品exportがid_section=-1を出したため。fixtureを変えず、出力の任意参照を省略にする接続修正を行った。
- `mcp-external-ids-01.log`: 初回新規4試験成功。最終版では実model_edit試験をserver内に移し、実状態比較を強化した。

## 限界・残る検証

- fresh独立レビュー・最終head全CI・通常mergeは進行担当の後続ゲートであり、ローカル成功と区別する。
- MCP ServerStateには選択状態が存在しないため、選択の実比較対象はない。GUIの選択操作実行は未実施。`app/mod.rs` のUiModelScoped.selectionと `app/actions/io.rs` の成功時load_model/失敗時report_errorの分岐は読取のみで確認した。MCP拒否は編集コマンド作成前に終わる。
- 実model_editの公開handler、EditArgs/bodyのDeserialize、実ServerStateを直接実行した。stdio/JSON-RPC transportを起動した通信試験は未実施。
- STB系列別ID名前空間は[#571](https://github.com/hrntsm/SEPIKA/issues/571)で別管理。全標準適合、他社相互運用、任意未対応属性の解釈は本件で検証しない。StbSlabのid_materialは既存未対応属性で、材料参照への変換経路がないため今回も扱わない。
- 実験Validation・ID全64bit化・汎用入力基盤は対象外。正常式の再計算精度を変更したという主張はしない。
