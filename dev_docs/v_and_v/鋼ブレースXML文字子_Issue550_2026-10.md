## 対象と参照解

標準ST-Bridge 2.0.2の鋼ブレース一様断面について、公開exportの全体XMLを検証する。
修正は `section_std::steel_brace` の4箇所の文字列行継続だけであり、Same以外の形状、RC配筋、
材料解決、原階、汎用writerは変更しない。

- [buildingSMART Japan公式2.0.2 XSD](https://www.building-smart.or.jp/wp-content/uploads/2026/04/ST-Bridge_v202.zip)：`StbSecBrace_S`、`StbSecSteelFigureBrace_S` は `mixed` のない複合型。Sameの `shape`・`strength_main` は必須。
- [W3C XML Schema Part 1 §3.4.4](https://www.w3.org/TR/xmlschema-1/#cvc-complex-type)：element-onlyの文字子に許されるのはXML空白。
- [Rust Reference / string continuation](https://doc.rust-lang.org/reference/tokens.html#string-literals)：literalバックスラッシュと行末バックスラッシュによる文字列継続の区別。

配布原本 `ST-Bridge_v202.xsd` のSHA-256は
`56cc1b80062c2385c15f8ab0745f4e96ac5b9400a4743307031e813d0253a1fa`。
原本の先頭ASCII `o;?` の3bytesだけを除いた `ST-Bridge_v202-normalized.xsd` は
`d854bf431d395ace4a7917a63ebed431d251e5bb2fbf7fbea26e9e195fdfa2b6`。
原本の4byte目以降と派生の全bytesの一致を確認し、Schema宣言は変更していない。

過去の発見は[#550](https://github.com/hrntsm/SEPIKA/issues/550)に記録された公開モデルの
import→exportとlxml検証である。以下はmain `f3f50cbf68d75b2cafeb3fbc69a30dc0b0feee1a` からの
修正後に2026-10-12に新たに実行したVerificationであり、過去の再現結果の転記ではない。

## 独立fixtureと公開入口

`crates/sepika-io/tests/stbridge_brace_content.rs` の `brace_model`：2節点座標[mm]
`(0,0,0)`、`(6000,0,3000)`、外部STB ID `41`・`99`、1鋼ブレース、1断面、1材料。
H形の高さ300、幅150、ウェブ厚6.5、フランジ厚9、フィレット半径10 [mm]。
材料名SN400B、fy=235 [N/mm²]、用途Brace、断面名BR550、floor=1F、両端PIN、引張専用。
RC/SRC・原階・他部材は含めない。別fixtureの断面名は `BR&"\550` とする。

| 常時回帰 | 観測契約 |
|---|---|
| `steel_brace_export_has_only_xml_whitespace_between_children` | public `export_stbridge` のBrace/Figure直属文字子（最初の子の前と各子のtail）をquick-xmlで検査し、空白・TAB・CR・LFだけを許す。両対象が1回ずつ存在することも確認 |
| `steel_brace_export_preserves_escaped_attribute_characters` | 別名称fixtureの `&`・引用符・正当なU+005Cが属性から復号され、public import後も完全一致する |
| 両試験の `assert_brace_meaning` | XML属性の `shape`→形鋼名、寸法、`strength_main=SN400B`、`id_section`→断面ID、節点参照41/99を独立期待値で照合。public `import_stbridge` でBrace用途、H全寸法、floor、材料名/強度、部材→断面→材料と節点座標/外部IDを再照合 |

内部IDとSTBのID字句を直接等置せず、正整数の断面IDと参照先の意味を確認する。
自己roundtripだけでSchema適合を判定しない。

## 全体XMLと外部XSD検証

出力用ignored testは製品の永続出力機能を追加せず、同じ公開fixtureと検査を使って全体XMLを保存する。

```powershell
$env:SEPIKA_BRACE_XSD_OUTPUT = Join-Path $env:TEMP 'sepika-550-verification'
cargo test -p sepika-io --test stbridge_brace_content --locked -- --include-ignored
```

検証器はPowerShellの.NET **10.0.12**、`System.Xml.Schema.XmlSchemaSet` と
`XmlReaderSettings.ValidationType=Schema`。採用派生XSDをnamespace
`https://www.building-smart.or.jp/dl` に登録し `Compile()`、各全体XMLをEOFまで読む。
生成positive/escaped XMLは検証前に編集しない。`XmlDocument.PreserveWhitespace=true` で
整形式を独立確認し、Brace/Figureの直属Text/Whitespace/SignificantWhitespace/CDATAを検査した。
Braceのtext/tailはLF＋8空白／LF＋6空白、FigureはLF＋10空白／LF＋8空白だけだった。

negativeは各回positiveを新しく読み、指定要素に
`PrependChild(CreateTextNode([string][char]0x5c))` を1回適用して別ファイルに保存した。
BraceとFigureを同時に変更しない。検証eventを収集し、positiveは0件、negativeは指定要素のError1件を要求した。

| 全体XML | 整形式 | Schema | 診断 |
|---|---|---|---|
| `positive.stb` | 成功 | 成功（0件） | 2節点1ブレース |
| `escaped.stb` | 成功 | 成功（0件） | 名称中のU+005Cを保持 |
| `negative-StbSecBrace_S.stb` | 成功 | 失敗（Error1件） | 15行53列、`StbSecBrace_S` cannot contain text。期待子はFigure |
| `negative-StbSecSteelFigureBrace_S.stb` | 成功 | 失敗（Error1件） | 16行35列、`StbSecSteelFigureBrace_S` cannot contain text。期待子はSame/NotSame/ThreeTypes |
