# 節点・材料直接入力の有限判定（Issue #546）

## 対象と出典

基準mainは `3c99fe63f8fe1a457ca2a5a5d0bd716220dc0ab7`、対象コードSHAは `e32ccef9be614a0426d22e3c282beff88d6fa929`。
解析契約12・検定契約5を維持する。節点追加XYZ、材料直接追加のE/ν/ρ/Fc/Fy/割増、材料一覧の
単一TextEdit失焦が対象である。既存節点グリッド・TSVは[#615](https://github.com/hrntsm/SEPIKA/issues/615)の別責務であり、
[#480](https://github.com/hrntsm/SEPIKA/issues/480)・[中止されたPR #548](https://github.com/hrntsm/SEPIKA/pull/548)の材料TSVを追加していない。
[#434](https://github.com/hrntsm/SEPIKA/issues/434)のSRC診断と[#439](https://github.com/hrntsm/SEPIKA/issues/439)の解析前診断を維持する。

一次根拠はRust標準ライブラリ1.99.0の[f64::is_finite](https://doc.rust-lang.org/std/primitive.f64.html#method.is_finite)と
[FromStr](https://doc.rust-lang.org/std/primitive.f64.html#impl-FromStr-for-f64)。新しい材料規準・物理範囲・全モデルvalidatorは設けていない。
製品仕様の正本は[テーブル編集とグリッド操作](../../docs/model_edit/07_テーブル編集とグリッド操作.md#節点追加材料の直接数値入力)。

## 修正前の実入口再現

`logs/baseline-probe.rs` はmainに一時追加して保存したegui試験の原本であり、誤受理を成功期待するprobeを最終製品testsには残していない。
`nodes_table` の「+ 追加」クリックでNaN座標、`materials_table` の直接追加でFc=abcがNone、同表のE TextEdit失焦でNaNを受理した。
probeはbaseline attempt2で追加2入口、attempt3で3入口すべてを実行した。

## 独立期待値と実入口

`crates/sepika-app/src/tables/direct_input_tests.rs` の `issue546_*` は実 `nodes_table/materials_table` を
`egui::Context::run_ui` で描画し、追加・重複確認のボタンにPointerButton入力、各数値TextEditに
Ctrl+A/Text/Backspaceと表外クリックによる失焦を送る。直接適用だけの代用ではない。

| 受入 | 試験の期待値と検証範囲 |
|---|---|
| XYZ各3欄、材料追加・単一編集各6欄 × 12不正表記 | `NaN/nan/inf/-inf/Infinity/∞/1e309/-1e309/abc/=1+2/1,234/10 mm`を拒否。XYZ最後のみ・材料割増最後のみ不正でも全体無変更 |
| 正常指数と単位 | XYZ `[1e3,-2.5e2,空欄]`→`[1000,-250,0]`mm、E/ν/ρ/Fc/Fy/倍率=`205000/0.3/7.85e-9/24/235/1.1` |
| 有限対照 | 前後空白、正負0（bitも照合）、有限負値、最小subnormal `5e-324`を全対象欄で保持。各単一セルは一度2へ変更し、その後対照値を直接確定する。最終追加の各欄bit照合assertはローカル未実行、CI後続 |
| 空欄 | XYZのtrim空欄→0。材料追加必須3欄の空欄は追加不可、任意3欄はNone。単一必須空欄は理由付き旧値保持、任意の明示空欄はNoneへクリア |
| 対象再検査 | 実TextEdit編集中の材料削除→参照不明、Concrete/Normalへ変更→E編集不可。入力を保持し、モデル・履歴は無変更。直接入力Concrete/UserDefinedのEは変更可能 |
| 重複確認 | 正常な同一座標を確認クリックで追加。保留座標の各成分をNaNへ差し替えた確認は拒否し、保留値と履歴を保持 |
| Undo/Redoと結果識別 | portal_frameで実準備＋線形解析を実行しinput_records非空を確認。実成功追加/セル変更→UndoでRedoを持つ状態で不正matrixを繰返し、最後に本来Redoのモデル直列化を復元 |
| 拒否/Noopの不変 | モデル全体のMessagePack直列化（ID/参照/世代も含む）、Undo revision・undo/redoラベル、未保存・全stale、準備結果、解析bundle（入力記録含む）を前後一致で照合。正常成功は全staleと未保存を更新 |
| STB Fc24と省略 | 実Fc欄NaN/abc拒否は材料/grade/common/source stories不変。明示空欄はgrade/common/明示storyへ反映、Undo/Redoでモデル全体を復元。別fixtureで原story省略Noneの復元を確認 |
| 意味Noopと強度変更 | 数値表記のみ `2.05e5`等では履歴/stale不変。材料Fc=Noneでもgrade=Fc24の明示クリアは実変更。正常Fy=235はnative overrideの解決値235へ反映 |

`materials.rs` の追加適用試験は確定直前のID/編集可否を直接照合し、`sepika-edit/src/tests.rs` は
数値コマンドでのNaN/±∞、必須None、任意欄最後だけ不正、NoopのRedo保持を照合する。

## 既存診断試験の接続

GUI全lib attempt1（711成功/1失敗）とdefault lib attempt1（297成功/1失敗）は、既存
`src_loaded_and_edited_materials_never_use_provisional_analysis_properties` がSetMaterialFieldでNaNを
注入できる前提だったため失敗した。新契約では拒否と元モデル保持を確認し、その後は不正raw fixtureを
保存・読込して同じSRCの合成特性・剛性・要素生成・準備計算の拒否を検証する。
有限の物理範囲不適合値・Fc欠落は従来どおり実編集とUndoを通す。診断の範囲を削除していない。
