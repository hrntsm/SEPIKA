# RC鉄筋の径区分と未指定材料強度の照合（Issue #947）

## 目的・判定範囲

2026-10-27、[Issue #947](https://github.com/hrntsm/SEPIKA/issues/947)について、鉄筋の呼び名・公称直径と許容値の境界、材料未割当と明示材料の不足診断を調べた。初回調査の対象HEADは `99ba3feb488ecc89cd30c8d482e78134d852e6bd`、追加のnative径API実行は `7a2bb05dd43ceb90e077f0e81be6855fad890a7e`。[#881の限定照合](RC材料構造細則_Issue881_原典照合.md)を補足する調査であり、計算式・入力受理・診断は変更しない。現在仕様の正本は[材料の許容応力度](../../docs/calc_basis/06_一次設計/01_材料の許容応力度.md#鉄筋径区分に注意)。原典照合、ソース読取り、公開入口の実行を区別し、全規準適合・実験Validation・手動GUIの保証には拡張しない。

## 原典と数値境界

利用者指定の2025年版建築物の構造関係技術基準解説書（第2版第1刷。版刷の確認履歴は[#881](RC材料構造細則_Issue881_原典照合.md#原典版刷公開訂正)）の9.2本文p567（分割PDF2頁）とp572（同7頁）の原画像を再確認した。本文抽出は文字化けを含むため表の判断には用いず、画像・本文抽出はリポジトリへ保存しない。

- p567令90条表2は異形鉄筋の径を28 mm以下／28 mm超で分ける。主筋の長期引張・圧縮はそれぞれ `min(F/1.5,215)`／`min(F/1.5,195)` N/mm²。せん断補強の長期は径によらず `min(F/1.5,195)` N/mm²。
- p572告2464の基準強度はSD295A/Bが295、SR235が235 N/mm²。したがってSD295主筋の小径側は196.666…、SR235補強筋は156.666… N/mm²になる。現行195／155はともに1.666… N/mm²小さい。法令表にこの整数値への丸めは確認できず、別規準・丸めの採用原典は未取得。許容応力度だけの比較では小さい側だが、別式採用の根拠を確認済みとはしない。
- [製造者公開のJIS G 3112寸法表](https://www.nipponsteel.com/product/construction/handbook/pdf/5-3.pdf)（2026-10-27公開確認、PDF1頁）は呼び名D25の公称直径25.4 mm、D29の28.6 mmを示す。D25は法令の小径側、D29は大径側となり、GUIの標準呼び名を29で分ける結果と一致する。呼び名29と公称直径28.6を同じ数値としては扱えない。

JIS G 3112の発行済み規格本文そのものの全条件は未取得。[鉄鋼連盟の公開資料](https://www.jisf.or.jp/business/standard/jis/documents/docs_kouzai_0700_JISG3112_20241220.pdf)は改正案（表題G 3112:9999）であり、発行済み規格の代用にしない。上記寸法の対応は製造者の公開表で有限確認した。任意径のJIS適合や認定品の適用可否は未確認である。

## 強度補完と不足診断の読取り

許容応力度表の材種選択と終局・非線形の降伏強度を分ける。前者は材料名、後者は明示材料のfyを用いる。取り込み時の標準名からの材料生成は内部での未指定補完とは別である。

| 経路 | 未指定・明示材料の区別と確認結果 |
| --- | --- |
| 共通resolver `material_grade::{rebar_yield_strength,shear_rebar_yield_strength}` | 材料なし／fyなしはNone。名称からfyを推定しない。主筋345をここで補わない。補強筋既定定数 `SHEAR_REBAR_DEFAULT_FY=295` は未割当用の代表値で、法令が未知材へ295を指定する意味ではない |
| 非線形入力検査 `sepika-element/src/factory/input_check.rs::member_strength_issue` | コンクリート系で梁・矩形柱・円柱配筋を持つ断面は主筋強度未解決をエラーにする。弾性壁上梁は別の弾性入力診断へ分岐する。補強筋未割当は既存契約上停止せず、明示材料の未知グレード／fy未設定・0以下は `shear_rebar_material_issue` で停止する。これを線形解析全入口での必須停止とは読み替えない |
| 一次断面検定 `sepika-design-jp/src/rc/mod.rs::RcDesign::check` | 配筋未入力・形状判定後、主筋と補強筋のいずれの未割当も理由付きSkipped。補強筋の明示材料不備もSkipped。主筋のfy不足を同じ条件で判定する処理はこの入口にはなく、許容値名の判定と主筋fyを使う計算の保証を混同しない |
| 既存終局・内部helper | `core/rc_capacity.rs::rc_capacity_input_from_rect` と `core/flexural_strength.rs::rc_flexural_yield_moment` は主筋resolver→本体材料fy→345の補完を残す。`element/frame/fiber/mod.rs`にも345が残る。resolverで既定値を廃止したことは全helperからの除去を意味しない。通常非線形入口の不足診断を迂回した直接呼出しと区別する。補強筋295も明示材料fy欠落時の保護を呼出側に依存する箇所がある |
| 終局検定 `design-jp/ultimate/rc_check.rs` | 補強筋不備を先に拒否し、未割当時はoptionsの値を用いる。主筋強度を解決できなければErr。すべての終局計算へ一律345/295を使うという仕様ではない |
| 壁 | [#503の検証](壁横筋入力と終局割線骨格_Issue503_2026-10.md)と[現在仕様](../../docs/calc_basis/06_一次設計/01_材料の許容応力度.md#鉄筋の材料はどこで指定するか)を参照。材料役割不足を未検定とする別契約で、梁柱の未割当補強筋295を壁へ一般化しない |

未指定主筋を345と仮定すると、実材SD295に対する耐力を過大評価し得る。未指定補強筋295も実材SR235と比較すれば強度が約25.53%大きく、常に安全側の仮定ではない。代表値の法令上の根拠は今回の表からは得られない。既定値の全面廃止・新診断の導入は本調査の対象外で、根拠・適用条件の追跡所在は本記録の「未確認・再判定条件」とする。明示fy未設定を未割当と同一視しない。

## 独立期待値と公開入口の実行

独立期待値は原典の径28境界と上限195/215から先に決めた。検証用コードはworktree内の一時Cargoプロジェクトで公開STB取込みと公開RC検定を呼び、実装式をコピーして期待値を作らない。既存の非整数径STB試験の独立XMLを基に、主筋径を置換し、全径の収まりと主筋中心を解決できるよう断面800×800 mm・4面の主筋中心位置65 mm・帯筋間隔100 mmとした。Fc24、主筋SD345、補強筋SD345、STB主筋本数X4/Y6、帯筋6.35 mm。柱の断面力はN=-100 kN、Mz=1 kN·m、他0、長期、中央位置とする。

| STB主筋径入力 | 保持値 | 材料関数の観測ft [N/mm²] | 公開柱検定の観測 |
| --- | --- | --- | --- |
| D25 | 25 | 215 | Checked、軸曲げ合成比0.01666765022 |
| D29 | 29 | 195 | Checked、軸曲げ合成比0.01586382095 |
| 28 | 28 | 215 | Checked、軸曲げ合成比0.01606831509 |
| 28.001 | 28.001 | 215 | Checked、軸曲げ合成比0.01606811160 |
| 28.6 | 28.6 | 215 | Checked、軸曲げ合成比0.01594584965、MA_z=628,311,150.3 N·mm |
| 29 | 29 | 195 | Checked、D29と同値 |

上記6条件の `stb_rebar_analysis_diagnostics()` はすべて空。帯筋比0.2%未満の警告は別に出るため、このCheckedを建物の全規準成立としない。材料関数のft観測と公開検定の合成比観測は区別し、合成比の独立正解を得たとはしない。

**STB経路の条件付き評価**：入力28.001／28.6を公称直径mmと解釈すれば、令90条表のftは195であり観測215は20 N/mm²（195に対し約10.256%）大きい。ただしST-BridgeのD_mainが公称直径mmとして正当に入力できるという規格上の意味は未確認。標準呼び名以外の文字列を保存・数値化できることと、法令表への正しい対応は別である。STB経路での観測を実建物の法令誤判定へ拡張しない。一方、以下の公開APIのmm契約による独立実行では、STBの意味に依存しない許容値選択の不整合を確定した。

最初の既存非整数fixture（450×650 mm、かぶり40.5 mmのみ、帯筋間隔133.3 mm）は、大径化すると収まり不足でSkippedになり、STB主筋中心未解決診断も出た。この失敗を採用結果から隠さず、上記6条件の結果と区別する。

### 公開配筋APIのmm契約による独立実行

STBを依存に含めない一時Cargoプロジェクトで、`RcRectColumnRebar`を直接構築し、`SectionShape::RcColumnRect::to_section`から公開`RcDesign::check`へ渡した。前のSTB6条件や次の材料不足5条件の結果をnative径の証拠に読み替えず、追加で実行した3条件である。公開型の`main_dia`は主筋径[mm]という契約であり、標準D29の公称直径28.6 mmを直接指定できる。

断面800×800 mm、Fc24、主筋・補強筋とも名称SD345・fy345 N/mm²。公開型の本数は`x=[6], y=[4]`（STB表記X4/Y6相当）。帯筋径6.35 mm、間隔100 mm、両方向2脚。4面の主筋中心65 mmを保つため、かぶりを`65−6.35−主筋径/2` mmとし、28／28.6／29 mmで44.65／44.35／44.15 mmとした。断面力・長期・位置はSTB経路と同じ。モデルやSTB標準強度表は作らず、コンクリート材料と材料2役を公開検定へ直接渡した。

| 公開主筋径 [mm] | 法令表の独立期待ft [N/mm²] | 幾何検証／公開柱検定 | 観測ft [N/mm²]・合成比 |
| --- | --- | --- | --- |
| 28 | min(345/1.5,215)=215 | Ok(())／Checked | 215・0.016068315094884794 |
| 28.6 | min(345/1.5,195)=195 | Ok(())／Checked | 215・0.01594584964770917 |
| 29 | min(345/1.5,195)=195 | Ok(())／Checked | 195・0.015863820948301858 |

28.6 mmで`MA_z=628311150.3 N·mm`を観測し、前のSTB入力と同じ数値になった。合成比・耐力自体の独立正解は未確認で、これらの誤差率を許容値の差から代用しない。3条件とも帯筋比の別警告があり、Checkedは全規準成立の保証ではない。

**確定した不整合と安全性**：公開配筋APIのmm契約で28.6 mmを指定すると、柱検定が呼び名基準の29分岐で長期ft215を選ぶ。法令表の独立期待195に対し20 N/mm²、約10.256%過大であり、材料許容値の選択は危険側である。これはSTB径の規格上の意味とは独立した具体的再現で、修正を[#961](https://github.com/hrntsm/SEPIKA/issues/961)へ分離した。GUI全体・STB規格上正当な入力・全材種/断面・実建物の耐力と全体安全性の誤判定まで確定したものではない。修正方法や幾何・数量・保存結果への波及は同Issueで確認する。本調査では計算・診断を変更しない。

### nativeモデルの材料不足診断

材料不足は、取込み済みモデルのSTB標準強度指定を解除したnativeモデルで主筋・補強筋の材料IDを分け、公開resolverと `sepika_element::factory::nonlinear_input_issues` を実行した。STB標準強度が残るモデルでは断面の材料参照だけを外しても標準強度から解決されるため、未割当の検証にならない。これも未指定と明示入力を区別すべき入力経路である。

| native入力の変更 | 主筋／補強筋resolver [N/mm²] | 公開非線形入力検査の観測 |
| --- | --- | --- |
| 主筋材料なし | None／345 | 主筋材料不足エラー |
| 主筋材料あり、fyなし | None／345 | 主筋材料不足エラー |
| 補強筋材料なし | 345／None | このモデルの材料不足診断なし |
| 補強筋SD345を明示、fyなし | 345／None | 補強筋fy不足エラー |
| 補強筋SR235、fy=235を明示 | 345／235 | このモデルの材料不足診断なし |

この実行は入力診断のVerificationであり、solver実行・補完295を用いる終局耐力の数値Verificationではない。全fy範囲・全グレードを検査したとも扱わない。SD295主筋195とSR235補強筋155は公開材料関数の既存[#881の数値Verification](RC材料構造細則_Issue881_原典照合.md#独立数値と境界のverification)を参照し、今回のp567/p572再照合と区別する。
