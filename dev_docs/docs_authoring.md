# 製品ドキュメントの執筆・検証

文書の読者・責務・配置は [文書配置ルール](README.md#ドキュメント配置ルール正本) に従う。
本書は `docs/` を執筆・確認する際の詳細な規約と手順の正本とする。

## 本文

利用者が設計・検討の判断に必要とする情報を説明する。

- 採用する理論・計算モデル、式・算定方法・仮定
- 入力値の意味・適用範囲、既定値と根拠
- 制約・非対応事項、結果の意味・読み方・設計上の注意事項
- 必要な規準・文献・出典、GUI の現在仕様・操作上必要な情報

内部 API の振る舞い、GUI から見えない処理順序・データ構造、実装上の回避策、
リファクタリングや旧実装との差分は利用者向け本文に書かず、コード・ADR・handoff に置く。

## 実装参照

説明した理論・仕様に対応するコードを、既存の共通表示で示す。

```html
<div class="impl-ref">

**実装参照**：`sepika_xxx::module::item`（`crates/...`）が実装します。

</div>
```

- 参照先はコードを検索して実在を確認する。private / `pub(crate)` の実装位置も示してよい。
- 行番号を使わず、モジュール・関数・型・ファイル等の安定した入口を示す。
- 入口は必要最小限（目安 1〜2 個）とし、独立した役割が複数ある場合は必要に応じて増やす。
- 説明節の直後や節末に置く。既に参照がある場合は重複させない。
- ページ末尾の `## 実装参照` にまとめる既存方式も維持し、節ごとの参照と二重に管理しない。
- 実装の詳細や設計経緯は展開せず、コード・ADR・handoff 等を正本とする。

## ページ構成

- ページを追加・削除したら [SUMMARY.md](../docs/SUMMARY.md) と章の README の一覧を更新する。
- 章は章ディレクトリと小項目ページで構成する。
- 章・節番号は mdBook が自動採番するため、SUMMARY のタイトルやページ見出しに番号を手書きしない。
  本文の節参照には、番号ではなく見出しタイトルへのリンクを使う。
- 数式は MathJax 用の `\\(...\\)` / `\\[...\\]` で記述する。
- 章の追加や表示・フッターを変更する場合は [book.toml](../book.toml)、
  [実装参照の表示](../theme/impl-ref.css)、[footer.js](../theme/footer.js) と
  [footer.css](../theme/footer.css) の設定・実装を確認する。redirect やアンカーの取り決めはこれらを正とする。
- 公開・API リファレンス生成の処理は [docs workflow](../.github/workflows/docs.yml) を正とする。

## ローカルでの確認

[mdBook](https://rust-lang.github.io/mdBook/) が必要。未導入の場合は `cargo install mdbook` で導入する。
リポジトリルートで以下を実行する。

```bash
# リンク切れと実装参照パスの実在を確認する
cargo run -p xtask -- check-docs

# 静的 HTML のビルド
mdbook build

# プレビュー（変更を自動リロード）
mdbook serve --open
```

`check-docs` の対象は `docs/` のため、開発者向け文書を変更した場合は、変更した文書の
リンク先・見出しアンカーも確認する。
