## 調査の位置付け

#678 で共用した既存の構造参照検査に、階・拘束・節点荷重・生成記録の参照が網羅されていなかった。
未完成入力の保存を保ったまま、存在しない明示参照を受け入れる必要があるかを調べた。
基準は main `69bdd81a8572e09ac44234f3a4bab8fb7dc92202`。
以下は実装前の調査担当による実観測を文書担当が raw 出力と照合した記録であり、文書担当による再実行ではない。

- 公開モデル API・参照検査・全モデル検証・ダンパー専用検査・保存・独立作成した正しい manifest/hash の読込を、
  17 参照箇所の正常・不在・範囲外・未設定の計 68 条件で比較した。既存の一般参照検査では、対象の不在参照も通過した。
- 公開解析入口では、正常対照と未使用の自動代表節点を含む別の 17 条件群について、各 4 対照の計 68 条件を調べた。
  IO 調査とは参照役割の集合が異なり、生成記録の剛床は 1 条件群にまとめている。現用拘束の不在節点は既存の解析前チェックが拒否した。
  一方、当該片持柱モデルの手入力・自動生成の節点荷重は、不在節点を指定しても通常静解析が成功した。
  正常な 1000 N 荷重時の変位は約 0.003658536585 mm、不在節点指定時は荷重合計も応答も 0 だった。
  これは特定入力で荷重が失われた実到達の証拠であり、全解析の誤差率や物理的 Validation ではない。
- 自動代表節点の記録に実在節点と不在節点を混在させると、公開階生成で配列アクセスの panic が発生した。
  範囲外 ID 単独では不正 ID を生成結果へ返す条件もあった。実在するが拘束・階所属から使われていない代表節点は再利用できた。
- 地震重量生成記録の参照先が不在でも、後から同じ ID の利用者節点・階・拘束を追加すると、旧記録と誤照合する条件があった。
  入力・出力の識別が古い記録でも成立した。全参照先が実在して値だけが古い対照は正常に保持できた。

調査用の入力・raw・終了状態・ハッシュ索引は作業時 TEMP に保存した。
`sepika681-source-probe-v2`、`sepika681-solver-probe-v2`、`sepika681-lifetime-probe` が各 probe の接頭辞、
`sepika681-probe-evidence-hashes.json`・`sepika681-lifetime-evidence-hashes.json` が照合索引である。
これらの一時成果を恒久テストや最終ゲートの証拠の代用にはしない。

## 最小境界を選んだ理由

生成記録は表示専用の過去履歴ではなく、次の生成で自動値と利用者設定を区別する照合にも使う。
静的な寿命調査では、記録内の節点・階は現在のモデルと同じ ID 空間を使い、正式な削除・再採番で追従・除去される経路を確認した。
不在 ID の保持を許すと後から追加した別実体を自動生成物と誤認し得るため、明示された参照先の実在を要求した。

一方、利用者が剛床の重量・Ci・所属節点・代表節点拘束を編集した際の旧比較値や、準備失敗後の古い生成記録は正常に残り得る。
現在の拘束との一致、記録値と採用重量との一致、入力・出力の識別の新しさまで保存条件にすると、これらの未完成・再生成前状態を失う。
このため、一般参照検査と採用前の鮮度・完成度検査は分けた。

実装先は `Model::validate_reference_ids`（`crates/sepika-core/src/model/aggregate.rs`）。
同検査を共用する保存・読込・アプリの状態変更前検査と、`Model::validate` を通る解析前検査に適用する。
保存へ全モデル検証を追加する方式や、ID 修復・参照削除・値の推定による受入れは採らない。

直接の階生成は未完成モデルも扱うため、`generate_stories_impl`（`crates/sepika-load/src/story_gen/generate.rs`）で
入力の `generated_masters` の実在と ID の本人一致だけを追加確認する。
全モデル検証や一般参照検査全体をこの入口へ追加しない。

## 所有と版

原階・STB 元入力・ダンパー生成記録等の専門検査を、今回の地震重量生成記録と一律に扱わない。
