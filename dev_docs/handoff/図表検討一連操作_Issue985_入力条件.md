# 図表検討の専用入力条件の確定履歴（#985）

作成日: 2026-10-30

#985で#973の代表モデルを実行するために明示した条件の履歴である。現在の製品仕様は[断面案の検討](../../docs/model_edit/10_断面案の検討.md)、検証状態と未確認は[V&V](../v_and_v/図表検討一連操作_Issue985_確認記録.md)、未完了の開発作業は[#985](https://github.com/hrntsm/SEPIKA/issues/985)を正とする。

## 壁版の有無

既存実モデル用の階・配置・配筋中心の完成処理だけでは、床板領域0件・壁版領域62件が未設定だった。非GUIの計算は進むが、GUI所有の検討は人の確認待ちで止まることを実通信で観測した。既往の警告続行に対するautomatic approval reviewの拒否を再試行していない。

壁剛性・自重が解析へ入らず応力・変形・重量の過小評価となり得る影響を説明したうえで、利用者は「専用検証モデルは全62領域とも壁なしとする」と明示した。専用fixture生成でR0〜R61を「壁なし」として入力完成し、確認済み状態の注入・警告続行・領域削除はしない。実建物の条件や一般の既定値へ拡張しない。

## 候補断面と数量

候補b6は原本が大梁用途を明示している。未使用断面の宣言が取込で失われたため、取込を最小修正し、候補置換やfixture後書換えで救済しない。

全62壁なしの明示後、全体数量は基礎梁の型枠対象側面を特定できず停止した。現行入力には側面指定欄がなく、数量未確定を0へ補完しない。独立Advisorの検討後、固定S鋼材だけを既存と共通の明細生成で取得し、全体未算定理由を併記する最小経路を採用した。[ADR0095](../adr/0095-fixed-steel-quantity-evidence.md)を判断の正本とする。幾何・型枠条件の推定や、全体数量の拒否緩和はしていない。

## 実AI・代理GUI操作の範囲

Computer Useの物理Escape停止後はGUI入力と実AIを保留し、利用者の明示再開後に、新しい専用依頼から実施した。専用サンプル全モデル・条件・候補・結果をOpenAIへ共有する既存ChatGPT認証Codex CLI一時sessionだけが承認対象であり、実ユーザープロジェクトや常設CLI設定・資格情報は対象外とした。

auto-reviewで停止した各操作は、具体的な方法と範囲を示した次の利用者原文による追加承認後に安全再評価した。汎用の承認回避や別UIへの迂回はしていない。

- 「この専用ツール1件の一時設定を許可する」: 専用MCPのgui_requestだけを一時approveにし、GUI側の人向け検討・権限確認を維持する。
- 「この専用検討の旧版閲覧を許可する」: 同じ検討の基準・A・Bの保持入力と結果を読取る。編集・計算・本案更新・採用は許可しない。
- 「この1ファイルへの検証中の保存・再読込みを許可する」: `C:\Users\hiroa\Desktop\ikkan\.worktree\issue-985\target\issue985-cu-prepared.ovika` 一件だけの各段階保存と再読込。
- 「この専用モデルでの採用・Undo／Redo・保存試験を許可する」: G43のGY1→A GY2の通常GUI操作をエージェントが代行し、直後Undo・後続試験編集・Undo/Redoを確認する。実AI client自身の採用は引続き禁止し、構造安全性の承認とはしない。

再読込後の接続状態の折畳み見出しは、表示だけである静的根拠を示した再評価も拒否されたため停止した。別の有効化ボタンや別UIへ迂回していない。旧endpoint/sessionによる読取要求の接続不能を独立して記録し、GUIで接続状態欄を読めたとは書かない。

## 画面配置と残る制約

通常画面、実800×600の画面と1280×800指定への再起動復帰を専用exampleで確認する。native窓寸法はexampleだけのoptional `--size` と `persist_window=false` で指定し、製品の既定寸法や保存契約を変えない。

配置の保存先はOVIKAではなくアプリの利用者設定である。最初のexample起動では配置読込を呼んでいなかったため、配置の再起動保持成功とは扱わない。Appが通常の保存先へ自動保存した可能性はあるが、常設設定の実ファイルは読取・逆変更・復元していない。以後の配置確認は子processのLOCALAPPDATAだけを専用targetへ隔離し、製品と同じ配置読込入口を呼ぶ。global環境変数・OS設定・常設CLI設定は変更しない。

荷重ケース名称が入力直後に戻る問題は[#1005](https://github.com/hrntsm/SEPIKA/issues/1005)へ分離し、今回修正していない。荷重の数値フォーム入力・取消と注記IMEの変換確定は別の正常導線で確認した。
