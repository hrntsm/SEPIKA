# 主架構線材の断面用途

主架構線材の設計上の用途は、断面に指定する `FrameSectionUse` で決まります。`Girder`、`Column`、`Brace` のいずれかを明示し、断面符号や部材の角度から推定しません。

`ElementKind::Beam` は柱・大梁を含む曲げフレーム要素の解析定式化です。`ElementKind::Brace` はトラス定式化と `tension_only` を表し、Brace 用途の断面だけを割り当てられます。Beam 要素には Girder または Column 用途を、Brace 要素には Brace 用途を割り当てます。不整合や用途未設定は拒否します。

床・壁・二次部材の断面に主架構用途は要求しません。二次部材は `SecondaryMemberKind::{Beam, Post}` が正であり、断面の `frame_use` は `None` でも構いません。二次部材の断面用途は主架構の用途整合とは別に扱い、`frame_use` の値だけを理由に二次部材を拒否しません。

断面の同一性は断面符号と階の組で決まり、用途違いを暗黙の使い回しで解決しません。形状編集と複製では用途を保持します。幾何判定は局所座標・接続関係・式の適用条件の確認に限り、用途を変更しません。仕口パネルも用途で柱梁候補を抽出し、適用可否は別の幾何条件で判断します。

OVIKA は用途を保存します。ST-Bridge の `StbColumn`、`StbGirder`、`StbBrace` の主架構部材文脈を用途へ写し、`StbBeam`・`StbPost` は用途を決めません。同一断面を大梁と小梁、または柱と間柱が共有する場合も内部断面は複製しません。主架構用途の競合は入力エラーとします。旧形式からの移行や用途復元の fallback はありません。

この用途は RC・S・SRC・CFT の柱梁検定、`ForceRegime::Auto`、`no_long_axial_column`、数量積算でも共通して参照されます。

CFT（`CftBox`・`CftPipe`）は `FrameSectionUse::Column` 専用です。用途は部材角度ではなく `FrameSectionUse` を正とし、`Girder`・`Brace`・`None` の断面作成・割当は拒否し、既存データは解析前チェックでエラーにします。小梁・間柱の二次部材には、断面用途を Column にしても CFT を使用できません。床・壁の領域内と所属未割当のどちらも、編集・モデル検証・保存・読込・数量積算・解析のすべての入口で拒否します。不正入力を受け入れるための鋼材への置換や削除は行いません。この制限は本製品の対応範囲です。`Beam`・`Fiber`・`MultiSpring` の主架構線材で Column 用途を持つ場合に限り割り当てます。

主架構線材 `Beam`・`Fiber`・`MultiSpring`・`Brace` は、異なる NodeId のちょうど2節点だけに対応します。断面未割当の床境界線、柱・大梁・ブレースの用途、床接触の有無によらず同じ条件です。0・1・3節点以上、同じ NodeId の二重指定は、ElemId・kind・実節点数・期待2・入力NodeId列を含む診断で拒否します。先頭2節点の採用、自動分割、節点削除による救済はしません。部材追加の拒否ではモデル・領域割当・結果鮮度・Undo/Redo履歴を更新しません。

これは現SEPIKAの対応入力契約であり、多節点梁の構造理論を否定するものではありません。Shell・Wall・PanelZoneの節点数、NodalSpring・Isolator・Damperの独立した2節点・零長契約、二次部材の支持アンカー/座標の契約は別に扱います。
