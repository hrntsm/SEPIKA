# ST-Bridge 形式（.stb / .xml）

[ST-Bridge](https://www.building-smart.or.jp/meeting/buildingsmart/st-bridge/)は他ツールとのモデル受け渡しに使います。**書き出しは開発中**です。全標準要素への対応・全文XSD適合・完全な往復は保証しません。

日常の保存には[OVIKA](01_プロジェクト形式_ovika.md)を使用してください。支点・質量・任意材料物性・解析／設計条件・結果はST-Bridgeで保持できません。本案の結果と検討履歴の保存条件は[OVIKAの保存対象と再読込](01_プロジェクト形式_ovika.md#保存対象と再読込)を確認してください。

## 取込前：GUIから読み込む

「ファイル」メニューから読み込みます。編集中のモデルを残す場合は、先にOVIKAへ保存してください。

| メニュー | 動作 |
|---|---|
| 📥 **ST-Bridge 読込…** | `.stb`（または `.xml`）ファイルを選び、モデルへ取り込みます。取込結果の検証に成功してから現在のモデルと差し替わります |
| 📤 **ST-Bridge 書出（開発中）…** | 標準 ST-Bridge 2.0.2（`StbSecColumn_S` 等＋形鋼ライブラリ）で書き出す。BIM・他ソフト向け |

「ファイル」メニューの書き出しボタン直下には、操作前に次の説明を表示します。

> ST-Bridge書き出しは開発中です。一部の形状・属性・断面性能を正しく出力できない場合があります。出力内容は利用先で確認してください。モデルの保存にはOVIKAを使用してください。

- ファイル選択ダイアログの拡張子フィルタは `.stb` / `.xml`。
- ST-Bridge 読込は `.ovika` プロジェクトとは別系統であり、読み込んでもプロジェクトの保存先パスは設定されません（新規モデルとして開く扱い）。保存するとネイティブの `.ovika` として保存されます。
- 書き出しは ST-Bridge 2.0.2 の標準要素を用いる1形式です。全断面・部材の標準適合は未完了で、RC梁の配筋入力不足と一部ブレースの出力には制約があります。受け渡し先での検証を確認し、モデル・任意物性・解析／設計条件の保存には `.ovika` を使います。

## 取込直後：注意とモデルを確認する

1. 「⚠️ ST-Bridge 取り込み時の注意」を読み、下ドックの「ログ」タブで属性ごとの取込件数を確認します。注意があっても取込が完了する場合があり、取込成功だけでは解析・検定に使えるとは限りません。
2. モデルタブの「境界条件」で自動設定された柱脚ピンを確認し、実際の支持条件へ変更します。[自動設定の仮定](#支点の自動設定取り込み時)を確認してください。
3. 準備計算の「STB強度指定と採用元」で未解決の強度・元の省略・採用元を確認し、元指定または明示材料を修正します。[標準強度の解決と編集](#標準強度の解決と編集)に従ってください。
4. 「床」タブの小梁（二次部材）一覧、モデルタブの「壁版」一覧で、支持・断面・配筋・荷重伝達先を確認します。[要素別変換状況](03_ST-Bridge_要素別変換状況.md#部材)に、警告後の修正箇所と解析の制限を示します。
5. 解析前チェックで停止理由を解消し、OVIKAへ保存します。取込で失われた情報は元ファイルと照合して補います。

読み込みに失敗した場合は、現在のモデル・Undo履歴・解析結果・保存先を置き換えません。元ファイルの診断対象を修正して再度読み込んでください。成功時は新規モデルとして開くため、編集中のモデルは取込前にOVIKAへ保存してください。

## 再出力：受け渡し先と再読込で確認する

「ファイル」→「ST-Bridge 書出（開発中）…」から出力します。書出時の通知・エラーは画面のメッセージと下ドックの「ログ」で確認します。断面未割当なら診断対象へ実在断面を割り当て、二次部材の端点が節点と一致しない場合は受け渡し用モデルの構成を見直してください。架空の断面や材料で補完しません。

受け渡し先で断面形状・強度・配筋・部材数・床壁の範囲を確認し、必要に応じて出力ファイルをSEPIKAへ再読込して比較します。再読込は現在のモデルを置き換えるため、先にOVIKAへ保存します。[要素別表](03_ST-Bridge_要素別変換状況.md)の読込・書出・再読込の制限を合わせて確認してください。再読込成功も、元入力の完全保持や受け渡し先での計算妥当性の保証にはなりません。

変換時の拒否では出力先を作成・上書きしません。ファイル書込自体のエラーは変換の拒否と異なるため、出力先の状態を確認してください。

## 形状ごとの取込・書出条件

単一リップ溝形は、H/B/C/t [mm] がすべて有限の正値で、\\(t < C < H/2\\)、\\(t < B/2\\) を満たす必要があります。満たさない場合は編集・書き出しを断面番号・符号・寸法と原因付きで拒否します。
上下リップの接触・重複、ウェブとリップの接触・重複、非有限の派生性能も対象です。
自動C切詰め・微小隙間補完・閉断面Jへの読み替え・0質量化は行いません。
[寸法と総断面性能](../preparation/07_断面性能.md#単一リップ溝形の寸法と総断面性能)を参照してください。正式なリップ溝形タグの取り込みは未対応です。

## 組立BOXの読み込み

組立BOXは外高さA、外幅B、左右の板厚t1、上下の板厚t2をmmで指定します。
取り込む断面が参照する組立BOXは、部材がまだ割り当てられていない断面も含め、次を検査します。

- A・B・t1・t2がすべて存在し、有限の正値であること。
- 内法高さ \\(A-2t_2\\)、内法幅 \\(B-2t_1\\) が有限の正値であること。

正常な組立BOXは、同厚・異厚とも左右と上下の板厚を保持した角R=0の鋭角断面として取り込みます。
板厚差が微小でも丸め・平均による置き換えは行いません。CFTの充填鋼管にも同じ条件を適用します。
同じ符号・階・用途でも上下板厚が異なる断面と部材の参照先を区別し、OVIKA保存・再読み込みでも保持します。
どの取込断面からも参照されないライブラリ内だけの定義は、寸法不正だけでは読み込みを止めません。
圧延BOXの条件は別です。現行のST-Bridge書出は正の角半径を要求するため、読み込んだ角R=0の組立BOXは書出を拒否します。両板厚と直角を保つ保存にはOVIKAを使用してください。

断面積・断面二次モーメント・材料別重量は両板厚で算定します。
異厚のねじり定数・せん断性能とCFT等価剛性は理由付き未算定です。
入力の受理は、これらを必要とする解析・検定の成功を保証しません。
[組立BOXの断面諸量](../calc_basis/03_断面性能/02_断面諸量.md)を参照してください。

診断には形鋼名、参照断面の識別情報、不足・不正な属性と入力値、停止理由を表示します。
該当部材や断面を除いて読み込み成功にはしません。
失敗した読み込みによって、現在開いているモデル・結果・保存先は置き換わりません。

## 対応バージョン

- **ST-Bridge 2.0 系のみ**を受け付けます（ルート要素 `ST_BRIDGE` の `version` 属性が `2.` で始まること）。
- 要素の名前空間は `https://www.building-smart.or.jp/dl` に限定します。同じURIなら既定名前空間と接頭辞付きの記述を同じものとして扱います。名前空間なし・異なるURI・未宣言の接頭辞は拒否します。属性の接頭辞を外して標準属性へ読み替えることはありません。
- 1.x 系や ST-Bridge でない XML は読み込みエラーになります。
- 読み取る ID 定義・参照は、XML の数値文字列として `0`〜`4294967295` の整数を検査します。負数・小数・範囲外・数値でない値は項目と理由を付けて拒否し、取り込み全体を失敗させます。節点境界列の不正 ID も捨てません。標準節点 ID の書出しなど、個別の正整数条件は別途適用します。
- 柱・大梁・ブレース・小梁・間柱は、端部節点と断面の参照先が実在することを要求します。床・壁も指定された境界節点と断面の参照先が実在しなければ、理由を示して取り込み全体を拒否します。参照先の欠落を部材の省略や断面リンクの解除で処理しません。床・壁の断面参照の省略など、既存の未指定入力の扱いは[要素別変換状況](03_ST-Bridge_要素別変換状況.md)を参照してください。
- 出力できる範囲と近似・欠落は要素別表で確認してください。未割当断面や必須属性の欠落を許容する方針ではありません。主架構部材・ブレース・小梁・間柱に断面未割当がある場合、必須の断面参照を出力できないため書き出し全体を拒否します。診断の部材区分・対象番号・二次部材名を確認し、適切な実在断面を明示的に割り当てて再出力してください。拒否時は出力先を作成せず、既存ファイルも上書きしません。未割当をダミー部材へ変更したり、架空の断面・材料を補ったりはしません。断面が割当済みでも形状が未設定の場合は、拡張要素 `StbSecRaw` へ出力し、再読込を保証しません。
- ファイルの文字コードは、BOM 付き UTF-8・UTF-8・Shift_JIS（Windows-31J）の順に判定します。

**実装参照**：文字コードは `sepika_io::stbridge::read_stbridge_file`（`crates/sepika-io/src/stbridge/import/mod.rs`）が判定し、`version` 属性の検証は `sepika_io::stbridge::import::parser::parse`（`crates/sepika-io/src/stbridge/import/parser.rs`）が行います。

## 標準入力と保存の範囲

### 断面系列と数値ID

断面は、採用名前空間・具体的な断面系列・元の数値IDの組で識別します。
例えば `StbSecColumn_RC:1`、`StbSecColumn_S:1`、`StbSecBeam_RC:1` は別の定義です。
同じ系列の `1` と `01` は同じ数値IDなので、形状・材料・強度が同じでも重複定義として拒否します。
断面の符号・階・形状が一致することは、部材から参照する系列を変更する理由にはなりません。

部材の種類と `kind_structure` から要求する系列を決めます（[系列対応表](03_ST-Bridge_要素別変換状況.md#断面参照の系列対応)）。
要求系列に参照先がなく、別系列だけに同じ数値IDがある場合も、取り込み全体を拒否します。
診断には元部材の要素名・ID・`kind_structure`・要求系列・`id_section` と理由を示します。
`kind_structure` の欠落・不正値・未対応の構造種別は区別し、別系列や既定断面へ結びません。
床・壁の断面参照自体の省略は、要素別変換状況に示す未割当の扱いを維持します。
取り込み失敗時は、現在のモデル・Undo履歴・解析結果の世代を変更しません。

断面からの強度指定も同じ入力識別に結びます。別系列に同じIDがあっても、柱のFc30を梁のFc24へ取り違えません。
以下の強度優先順位、配筋、原階と材料参照節点、任意物性の扱いは共通です。
この入力識別はST-Bridge読込用です。ネイティブモデルとOVIKAの断面参照・強度指定は、保存・再読込後も保持します。
元の外部断面IDをOVIKAへ永続保存する契約ではありません。

XSDへの適合と、部材が正しい断面・強度へ結び付くことは別に確認する必要があります。
本機能は全文XSD検証器ではなく、全形状・全標準要素への対応を意味しません。
出典：[公式2.0.2 XSD](https://www.building-smart.or.jp/wp-content/uploads/2026/04/ST-Bridge_v202.zip)、
[公式仕様説明書](https://www.building-smart.or.jp/wp-content/uploads/2022/06/ST-Bridge_XML%E4%BB%95%E6%A7%98%E8%AA%AC%E6%98%8E%E6%9B%B8%EF%BC%88ver.2.0.2%EF%BC%89_20220615.pdf)の本文64頁§5.2.1補足10、68頁§5.3.1、73頁§5.4.1補足16、75頁§5.5.1、77頁§5.6.1。

### 原階と強度指定の保持

原階の元 ID/GUID・名称・height・kind・id_dependence・strength_concrete・明示節点列を保存し、
節点の元 ID/GUID も再出力します。
原階・節点の標準IDは編集・並べ替え・Undo/Redoでも保持します。異なる階への多重所属は診断します。準備計算で推定した解析所属や剛床代表節点は、元の明示所属へ追加しません。

コンクリートの強度指定と省略状態は、部材・断面・原階・共通ごとに保持します。
採用値を元属性へ補完して保存しないため、再出力で省略の優先順位が変わりません。

## 標準強度の解決と編集

コンクリートのFcは **部材 → 断面 → 指定節点の明示原階 → 共通** の順に採用します。
上位属性が存在しても未知名・空文字・非正値・非有限値なら未解決とし、下位の既知値へ迂回しません。
全指定の欠落も未解決です。原階の参照は次の節点で決まり、近傍階・平均標高・準備計算の解析所属では代用しません。

| 部材 | 材料参照節点 |
|---|---|
| 柱・間柱 | `id_node_top` |
| 大梁・小梁 | `id_node_start` |
| 床 | 元 `StbNodeIdOrder` の第1節点 |
| 壁 | 元 `StbNodeIdOrder` の最終節点 |

原階に異なるFcが競合する場合、上位の部材・断面で確定していれば材料は解決できます。
材料の採用元と、原階の所属・依存関係の診断は別に確認します。

鉄筋は、各部位の `strength_*` があればその指定を採用し、省略時だけ対応する `D_*` と
共通の `StbReinforcementStrengthList` の `D`/`strength` を照合します。
主筋・副主筋・帯筋・あばら筋・腹筋・巾止筋、位置別指定をそれぞれ保持します。
径や強度の欠落をD13・SD345で補完しません。同径の競合と未知名は理由を示して解析を停止します。
位置別の各指定が解けても、現行計算で一つの主筋・せん断補強筋・内蔵鋼材へ縮約できない強度は解析に採用できません。
高強度鉄筋のgrade読取りと、各検定式の適用範囲は別です。

`StbCommon` の `project_name`・`app_name`・`app_version`、任意の `strength_concrete` と径別リストを保存します。
共通子要素の出力順は径別リスト、適用条件リストの順です。RC/SRC梁・柱の原配筋と `ApplyConditionsList` は省略を含めて保存し、[役割・位置・適用の対応](03_ST-Bridge_要素別変換状況.md)を参照します。
説明図中の `concrete_strength` は標準属性 `strength_concrete` の別名として受け付けません。

準備計算の「STB強度指定と採用元」で、元指定の有無、共通・原階・部材・断面・鉄筋部位の指定と採用結果を確認・編集します。
チェックを外すと元属性を省略し、チェックを入れた空欄は明示された空文字として未解決になります。
通常の材料テーブルの名称変更は表示名の変更であり、保存された標準gradeやFc・Fyを変更しません。
Fc数値の意図的な変更は、その材料を採る元明示指定へ反映します。E・ν・密度の編集では元強度指定・省略を変えません。
断面への明示材料割当は、その断面の強度を変更します。主材料・主筋・せん断補強筋・SRC内蔵鉄骨を別々に指定できます。S断面の主材料は鋼材、RC・SRC・CFT断面の主材料はコンクリートです。鋼材割当を解除した場合は、必須の鋼材強度が未解決になり、旧gradeへ戻りません。上位の部材Fc指定があれば部材の採用値はそのままです。
標準鋼材gradeの編集は、Sの主材料・二次部材の鋼材・SRC内蔵鋼の実採用材料にも反映します。明示材料割当がある場合は、その材料の数値を採用し、標準gradeによる採用と区別します。明示割当だけの操作で別の既定材料を追加しません。
鉄筋や鋼材のFy数値を編集した場合は、その数値を採用し、元の標準gradeとは区別します。標準gradeで編集後の数値を表せない場合はSTB出力を理由付きで拒否します。独自の標準gradeを生成せず、任意物性の保存にはOVIKAを使います。
明示材料の物性を採る結果には「明示材料指定」を表示し、標準gradeからの解決と区別します。
任意の明示鉄筋物性と標準gradeの数値が一致しない場合は、ネイティブ保存と標準書出しを区別し、標準で表せない出力を拒否します。

ST-Bridge強度名の解決とE・ν・密度の既定復元は別の処理です。
認識済みgradeの強度を採用した後、明示物性を持たない材料にSEPIKAの[標準材料既定値](../calc_basis/02_材料/04_標準材料一覧.md)を与えます。
CFT鋼管も認識済みの標準鋼材名からE・ν・密度を復元します。SN400Bの鋼管密度は7.85 t/m³で、同じ文書内の通常鋼断面の有無には依存しません。主材料は充填コンクリート、鋼管は別の材料として扱います。
ST-Bridgeに存在しない独自材料表は追加しません。任意物性を含む完全保存には `.ovika` を使います。
長さmm・角度deg・強度N/mm²を保持します。

### 強度の入出力制限

| 条件 | 読取り・材料供給 | 標準書出し |
|---|---|---|
| 対応部位の強度・径・省略 | 元指定と採用元を保持 | 元属性を再出力。解決値を各部材へ補完しない |
| 床が領域ごとに分割される | 各分割床へ元第1節点からFcを供給 | 元第1節点が分割境界に残る場合は、その節点を先頭にして出力し、原階・共通由来と元Fc省略を保つ。元第1節点が境界にない原階・共通依存の省略は、理由付きで拒否。明示部材・断面Fcで意味を保持できる場合は区別する |
| 同領域へ複数の元床を合算する | 元の強度・採用元が異なる場合は拒否 | 任意の先勝ち値で出力しない |
| 原配筋の位置別入力 | 各部位の元指定・posを保持 | 標準の同じ系列へ出力。位置別解析は理由付きで不可 |
| 断面系列間で同じ数値IDを使う | 具体的な系列ごとに断面と強度を結ぶ。同系列の数値ID重複は拒否 | 元の外部断面IDをそのまま再出力する保証はない |

床の元幾何を再結合して出力する機能はありません。取り付く壁版や配筋全体にも既存の出力制限があります。
材料を対象にしたXMLの適合が、建物全体の標準適合を保証するわけではありません。

出典: buildingSMART Japan「ST-Bridge XML仕様説明書 ver.2.0.2」2022-06-15、§2.4（本文11頁）、
§3.2–3.2.4（本文18–24頁、優先順20頁）、§4.4.1（本文57–58頁）、§6.2.5（補足4頁）。
[採用対象の仕様説明書](https://www.building-smart.or.jp/wp-content/uploads/2022/06/ST-Bridge_XML%E4%BB%95%E6%A7%98%E8%AA%AC%E6%98%8E%E6%9B%B8%EF%BC%88ver.2.0.2%EF%BC%89_20220615.pdf)、
[公式配布入口](https://www.building-smart.or.jp/meeting/buildingsmart/st-bridge/)。標準属性・子要素順序は2.0.2 XSDによります。

<div class="impl-ref">

**実装参照**：`sepika_core::model::Model::{resolve_stb_concrete, resolve_stb_rebar, resolve_stb_steel}`（`crates/sepika-core/src/model/strength.rs`）と `sepika_io::stbridge::strength_export`（`crates/sepika-io/src/stbridge/strength_export.rs`）が解決と元指定の出力を担います。

</div>

読み込みは、ST-Bridge 2.0.2の標準要素・属性のうち、要素別変換状況に示す対応範囲を対象とします。旧独自の材料表 `StbMaterial`、物性を直接記す `StbSecRaw`、独自の `id_material` 系参照は読み取りません。標準にない属性名や異なる階層の属性を、標準入力の代わりに採用しません。

標準の `StbExtensions`・`StbCalData`・`StbAnaMaterial` が存在すること自体を旧形式の判定には使いません。これらの全情報を取り込めるという意味ではありません。標準ルート直下の `StbExtensions` 内も要素の名前空間を検査しますが、内容をモデルや強度指定として取り込みません。読込時のXSD全文検証や旧形式の専用判定・移行は行いません。

書き出しには現在も `StbSecRaw` への出力がありますが、その出力を再読込できる保証はありません。書き出しの制限を含む完全なモデル保存にはOVIKAを使用してください。任意断面性能・材料物性・強度指定の編集内容はOVIKAで保持します。

要素ごとの詳細な変換状況（取り込み／書き出し／往復・備考）は、
[ST-Bridge 要素別 変換状況一覧](./03_ST-Bridge_要素別変換状況.md)を参照してください。

<div class="impl-ref">

**実装参照**：取り込みと書き出しは `sepika_io::stbridge::{import, export}`（`crates/sepika-io/src/stbridge/`）が担い、床板・壁版の床領域／壁領域への付け直しは `sepika_core::{region_rebuild, wall_region_rebuild}` が行います。

</div>

## 非対応（対象外）

非対応項目は入出力の対象外です。取り込み時の扱いは、[ST-Bridge 要素別変換状況一覧](./03_ST-Bridge_要素別変換状況.md)を参照してください。

- 剛域・製作情報などの詳細属性。
- 解析結果・SEPIKA 独自の解析／設計属性。ST-Bridge の対象外で、保持には [`.ovika`](./01_プロジェクト形式_ovika.md) を使います。

未対応の要素（`StbFooting`・`StbPile` など）で欠落する情報は、取込時の注意で通知します。部材グループ・断面の直属子にある未対応要素や拡張も要素名で通知します。対象を元ファイルと照合し、必要な情報をSEPIKA上で入力し直してください。

### 属性の扱いの報告

下ドックの「ログ」タブには、ファイルに存在した属性の扱いを要素名・属性名ごとに表示します。直後の注意には「取り込まなかった属性が N 種類あります」という要約を表示します。未取込属性は要素の警告とは別にログで確認してください。

同じ属性でも一部だけ採用される場合は「N 件中 M 件を取り込み」と表示します。例えば図形が複数ある断面では最初の図形だけを採るため、後続の寸法は保持されません。未対応のGUID等もログに表示されます。欠落が設計に影響する場合は元入力を見直すか、OVIKAで必要情報を補って保存してください。

### 支点の自動設定（取り込み時）

ST-Bridge は境界条件（支点）を持たないため、支点が 1 つもないモデルを取り込んだ
ときは、そのままでは解析できません。そこで取り込み時に、**最下レベル（Z 最小、
許容差 1 mm）で柱脚が取り付く節点**をピン支点（並進 3 自由度を拘束・回転自由）に
自動設定します。これは柱脚ピンの仮定であり、架構全体の安全性や解析の成立を保証しません。この支点自動設定に限り、柱脚候補を鉛直な 2 節点線材（部材軸の鉛直成分が大きい部材）で判定し、
柱が取り付かず梁だけが取り付く最下レベル節点（地中梁の中間節点など）は支点にしません。
最下レベルに柱脚候補がない場合は、最下レベルの全節点を
ピン支点にします。設定内容は取込時の注意で知らせ、
モデルタブ→境界条件で変更できます。実際の支持位置・並進拘束・回転拘束を照合し、必要に応じて修正してください。すでに拘束を持つモデルは変更しません。

<div class="impl-ref">

**実装参照**：`sepika_io::stbridge::import::assemble::auto_assign_supports`（`crates/sepika-io/src/stbridge/import/assemble.rs`）が判定・設定します。

</div>

## 断面用途の取り込み

鋼断面は、部材から未参照でも柱断面・ブレース断面の種別と大梁の明示指定を保持します。梁断面に大梁指定がなければ断面名・形状から用途を推定しません。明示用途と部材からの参照用途が競合すると読み込みを拒否します。

柱・大梁・ブレースの用途は標準部材要素 `StbColumn`・`StbGirder`・`StbBrace` で決まり、部材角度・鉛直性・断面符号から推定しません。傾斜した `StbGirder` も大梁です。用途不明・不整合は角度で補正せず拒否します。

小梁 `StbBeam`・間柱 `StbPost` は二次部材です。二次部材が参照する断面は、主架構の用途指定がなくても使用でき、主架構と共有する場合もその用途指定だけで拒否しません。支点の自動設定で用いる幾何条件は用途分類とは別です。

<div class="impl-ref">

**実装参照**：`sepika_io::stbridge::import::assemble::section_uses`（`crates/sepika-io/src/stbridge/import/assemble.rs`）が用途を解決します。

</div>

## 断面の符号と階（取り込み）

ST-Bridgeの部材から断面への参照は、採用名前空間・具体的な断面系列・数値IDで解決します。`guid` や符号・階は、この参照識別の代わりには使いません。
**同じ符号の断面を階ごとに異なる数値IDの定義として持つことができます**。
そのため 1 つのファイルに `name="C1"` の `StbSecColumn_S` が、`floor="1"`・`floor="2"`・`floor="3"`
と 3 つ並ぶことは正常な状態です。

SEPIKA の断面は[符号と階の組](../model_edit/02_断面の符号と階.md)で識別するため、この構造を
そのまま取り込めます。
断面の `floor` 属性は文字列としてそのまま保持し、階（`StbStory`）への参照としては扱いません。
ST-Bridge の `floor` は自由文字列で、階への id 参照を持たないためです。
実際、断面の階名が `1`・`R`・`PHR` で `StbStory` の名称が `1FL`・`RFL`・`PHRFL` というように
食い違うファイルや、断面の階名に対応する `StbStory` が存在しないファイルがあります。

異なる数値IDの断面定義を取り込むとき、符号＋階が重複する場合は次のように解決します。
同一系列の同じ数値ID（`1` と `01` を含む）の重複は、この統合処理の対象ではなく取り込みエラーです。

- 同一の具体的な断面系列内で、断面性能・断面形状・**材料**と、強度・配筋の元指定がすべて一致する定義に限り、1 件へ統合する。統合した件数は
  取込時の通知で知らせる
- 別系列の定義や、上記のいずれかが食い違う定義は、符号へ連番を付けて（`b3` → `b3#2`）別の断面として残す。同名同形状でも、別系列を1件へまとめない。
  符号を変えた内容は 取込時の警告で知らせる

材料も一致の判定に含めるのは、材料は断面が持ち、違う材料を割り当てるならそれは
別の断面だからです。材料だけが違う定義を 1 件へまとめると、片方の材料が無言で消えます。

食い違う定義を捨てずに残すのは、利用者が書いた断面定義を無言で消さないためです。
連番を付けた時点で符号＋階は一意になるので、モデル側の制約とも矛盾しません。

階を持たない断面定義（`floor` 属性のない `StbSecBeam_S` など）も、異なる数値IDで、同一具体系列・同一符号かつ断面性能・形状・材料・強度と配筋の元指定がすべて一致する場合に限り、1 件へ統合されます。
小梁の断面定義が同じ内容で何件も並ぶファイルは実際にあるため、この統合で断面一覧が実態に近づきます。

<div class="impl-ref">

**実装参照**：重複の統合・連番付与・材料を含む一致判定は `sepika_io::stbridge::import::assemble::build_sections`（`crates/sepika-io/src/stbridge/import/assemble.rs`）が担います。

</div>

## 断面表現（書き出し）

書き出しは **ST-Bridge 2.0.2 の標準要素を用いる** 1 形式です。全体のスキーマ適合は未完了で、
対応範囲と制限は上記の対応範囲・非対応項目を参照してください。
入力した断面形状を対応する標準断面要素と形鋼ライブラリ（`StbSecSteel`）へ出力します。

断面ごとの書き出し先と、取り込み・書き出し・往復の詳細は、[ST-Bridge 要素別 変換状況一覧](./03_ST-Bridge_要素別変換状況.md)を参照してください。

材料の物性値まで含めた完全一致での往復が必要な場合は
[`.ovika`](./01_プロジェクト形式_ovika.md) を使います。

**実装参照**：断面の写像は `sepika_io::stbridge::section_std`（`crates/sepika-io/src/stbridge/section_std.rs`）が、XML 全体の組み立ては `sepika_io::stbridge::export`（`crates/sepika-io/src/stbridge/export.rs`）が担います。
