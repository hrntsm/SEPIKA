# OVIKA — SEPIKA Project File

OVI（卵）とIKAを組み合わせた名前です。

SEPIKAの構造モデル、解析条件、解析結果などを、一つの卵のようにまとめて保存します。

OVIKA（`.ovika`）は SEPIKA ネイティブの保存形式です。入力モデルを格納し、保存・読込で入力を保持します（ST-Bridge のようなサブセット制約はありません）。古い自動生成荷重と計算成果の保存条件は下記を参照してください。

<div class="impl-ref">

**実装参照**：`sepika_io::ovika::{save_ovika, load_ovika}`（`crates/sepika-io/src/ovika.rs`）が保存・読込します。

</div>

小梁・間柱への CFT 割当は、断面用途が柱でも保存・読込時に拒否します。領域内・所属未割当のどちらも対象です。保存が拒否された場合は既存ファイルを変更せず、読込が拒否された場合は現在のモデル・選択・Undo 履歴・計算成果を保持します。入力を自動置換・削除して受け入れることはありません。対応範囲は[断面用途](../model_edit/08_断面用途.md)を参照してください。

主架構の梁・柱・ブレース等の線材は、保存・読込で異なる2節点を持つことを検査します。断面未割当の床境界線も対象です。0・1・3節点以上や同じ節点の二重指定は、対象部材・種別・節点数・指定した節点を含むエラーです。不正保存は既存ファイルを上書きせず、不正読込は現在のモデル・Undo履歴・結果を置換しません。自動分割や先頭2節点による救済はしません。


単一リップ溝形は、有限正の H/B/C/t [mm]、t < C < H/2、t < B/2 を満たさない場合、入出力時に断面ID・符号・寸法と原因を表示して拒否します。
上下リップの接触・重複、ウェブとリップの接触・重複、非有限の派生性能も対象です。
自動C切詰め・微小隙間補完・閉断面Jへの読み替え・0質量化は行いません。
[寸法と総断面性能](../preparation/07_断面性能.md#単一リップ溝形の寸法と総断面性能)を参照してください。

## 未完成の入力と参照の整合性

断面・材料の未割当や主架構断面の用途未設定だけを理由に、保存を拒否することはありません。
入力途中の状態をそのまま保存でき、未設定を既定値で補いません。ただし、上記の断面用途・形状等の制約は入力途中でも適用します。

梁を短くした後など、準備計算が古く、自動生成した部材荷重の位置・区間が現在の材長に収まらない場合も、通常の「保存」で編集済み入力を保存できます。
この場合は、自動生成した節点荷重・部材荷重と本案の計算成果をファイルに含めません。検討の保持計算は、下記の[保存対象](#保存対象と再読込)に従って別に保持します。手入力荷重・荷重ケース・組合せ・生成条件は保持します。
保存のために準備計算を実行する必要はありません。開き直した後、準備計算を実行して自動荷重を再生成してください。
保存操作は編集中のモデルや Undo/Redo 履歴を変更しません。有効な自動荷重や直接検定の同梱条件は、下記の保存対象で確認してください。
手入力した固定距離荷重の範囲外位置・区間は保存時も拒否し、自動で短縮・削除しません。

未割当と、割り当てた参照先が存在しない状態は区別します。節点・部材・断面・材料等の ID と保存位置の不一致や重複、
検査対象の参照先欠落は、対象と理由を示して保存・読込を拒否します。通常のモデル編集では ID を管理しますが、
不整合なファイルを読み込む際に ID の付け替え、断面の置換・削除、用途の推定をして受け入れることはありません。
小梁・間柱と版の割当領域は安定した ID を持つため、連番でないことだけでは不整合になりません。

参照の不整合で保存を拒否した場合、既存ファイルと現在のモデル・選択・Undo/Redo 履歴・計算成果を保持します。
読込を拒否した場合も、入力ファイルと現在のモデル・履歴・計算成果を保持します。
ハッシュが正しくても、参照の整合性まで保証されるわけではありません。

階が持つ節点一覧と、節点に設定した所属階も、参照先が実在することを検査します。
剛床・剛リンク・多点拘束では代表節点と従属節点（多点拘束の各項の節点を含む）、剛床では所属階を検査します。
節点荷重の載荷先は、手入力・自動生成のどちらも対象です。存在しない節点の荷重を無視して受け入れることはありません。

自動生成した剛床代表節点の記録と、地震用重量の生成記録に明示された節点・階も対象です。
後者には算定重量の対象階、記録した拘束の代表・従属節点と剛床の所属階、代表節点の拘束条件の対象節点を含みます。
自動生成した代表節点は、現在の拘束や階所属から使われていなくても、実在していれば保持できます。

階所属の未設定、空の節点一覧・拘束・荷重、生成記録の未設定や空の一覧だけでは、参照不整合にしません。
生成記録と現在の拘束条件・採用重量が異なる状態や、再生成前の古い記録も、参照先が実在すれば保持できます。
保存時の参照検査は、所属の相互一致、入力の完成度、生成入力・出力の識別の新しさ、記録した値の正しさを認定しません。
解析へ採用する重量の更新は、[算定値と採用値の更新](../calc_basis/01_荷重/05_地震用重量_層データの生成.md#算定値と採用値の更新)で確認します。

保存できることと、GUI の「開く」で受け入れられること、解析できることは別です。
保存・読込のライブラリは入力完成度の検査を一括適用しませんが、GUI の「開く」はモデル全体の検証も行います。
例えば、主架構断面の用途が未設定の入力は保存できても、GUI の「開く」では拒否されます。
解析に必要な入力は、[解析前チェック](../preparation/README.md)でも確認してください。

部材荷重の作用方向の全成分が有限であれば、ゼロ方向など方向の[計算条件](../calc_basis/01_荷重/07_荷重の入力.md#作用方向の計算条件)を満たさない入力も、方向と手入力荷重を変更せず保存・再読込できます。参照先や位置・区間など、他の入力条件は引き続き適用します。方向の不備は計算時に拒否し、保存や読込による既定方向への置換・荷重削除・自動修復は行いません。

<div class="impl-ref">

**実装参照**：参照 ID の検査は `sepika_core::model::Model::validate_reference_ids`（`crates/sepika-core/src/model/aggregate.rs`）、アプリの状態変更前の検査は `sepika_app::app::App::{load_model, save_project_to_opts, open_project_from}`（`crates/sepika-app/src/app/actions/io.rs`）です。

</div>

## GUI からの操作

ファイルメニューに以下の項目があります。

| メニュー | 動作 |
|---|---|
| 📄 **新規** | 空モデルを開く |
| 🏠 **サンプル(門型ラーメン)** | 内蔵のサンプルモデルを開く |
| 📂 **開く…** | `.ovika` プロジェクトを読み込みます。読込後、モデルの整合性を検証してから差し替わります |
| 💾 **保存** | 現在のプロジェクトを上書き保存する（保存先が未設定なら保存先を尋ねる） |
| 💾 **名前を付けて保存…** | 保存先を指定して `.ovika` として保存する |

読み込むとそのファイルが現在のプロジェクトの保存先になり、以降の「保存」は同じファイルへ上書きします。

<div class="impl-ref">

**実装参照**：ファイルメニューは `sepika_app`（`crates/sepika-app/src/app/mod.rs`）が表示し、モデルの差し替えは `sepika_app::app::App::load_model`、開く・保存は `App::{open_project_from, save_project_to_opts}`（`crates/sepika-app/src/app/actions/io.rs`）が担います。

</div>

## 保存対象と再読込

通常の「保存」「名前を付けて保存」は、表示している案にかかわらず本案とすべての検討を一つのファイルへ保存します。
**保存して履歴を残すこと、読み込んで閲覧できること、現在入力の有効な結果として採用できることは別です。**
検討の履歴を現在の本案の計算結果へ移植することはありません。

| 保存対象 | 保存する条件・内容 | 再読込 | 現在結果としての再利用 |
| --- | --- | --- | --- |
| 本案の現在有効な解析・検定結果 | 解析全体が最新なら、静的・組合せ・固有値・増分・立体時刻歴・質点系等を同梱。検定は自身の生成入力と検定版も照合 | 同梱結果を復元し、計算版・生成入力を検査 | 対象ごとに現行版と現在のモデル・計算条件が一致する結果だけ利用可 |
| 本案の計算時入力付きの過去時刻歴 | 現モデルで解析に成功した後など、本案結果を同梱できる状態で、生成時のモデル・実入力の対応が確認できる旧モデルの時刻歴を保持 | 計算時入力に対応する履歴として復元 | 旧モデルの結果は現モデルの耐力等へ採用不可。履歴だけ残る場合は最新解析済みとは認定しない |
| 検討の基準案・各比較案と全保持計算 | 本案の結果が最新かどうかと独立して、各案の現在入力・条件、全保持計算の開始時入力・準備後入力・結果・数量・警告等を保存 | 再編集前の計算も履歴として確認可。保存した採否・根拠も保持 | 案と計算時入力・条件・計算版を確認。本案の現在結果にはならない |
| 本案の準備計算結果 | モデルに対して最新で、質量モデル方式の変更が未反映でない場合だけ同梱 | 同梱がなければ未実行として再計算 | 古い準備結果を現在入力へ採用しない |
| 本案の解析・検定設定 | 結果の有無・最新性にかかわらず現在の設定を保存。立体時刻歴・質点系の波形選択は別々 | 同梱設定を復元。設定がない・読めない場合は現在値（既定値または直前の値）を保持。質量モデル方式は読込モデルの値に合わせる | 設定の復元だけでは結果を有効にしない |
| 本案の動的ケース定義（振動荷重ケース） | 本案結果を同梱する場合、または検討が1件以上ある場合に保存 | 検討が1件以上なら対応結果なしでも復元。検討がなければ対応結果のないケースは再読込時までに除去 | ケース定義だけでは実行済み・結果確認済みとはしない |

| 保存時・読込時の状態 | 保存 | 再読込・必要な操作 |
| --- | --- | --- |
| 通常保存（検討なし・本案結果が最新） | 最新の本案成果と有効な検定、準備結果、設定をそれぞれの条件で保存 | 入力・計算版が一致する結果を利用 |
| 検討あり | 本案の同梱可否とは独立して、すべての検討・各案・全保持計算を保存。本案の動的ケース定義も保存 | 履歴と各案を復元。対応する本案結果がなくてもケース定義を保持 |
| 本案解析が古い・未実行 | 本案の旧解析を除外。現入力・検定版が有効な、架構応力を必要としない直接床板・小梁検定は単独保存可 | 直接検定は利用できても解析済みとはしない。必要な解析を実行 |
| 古い自動部材荷重が現在の材長を外れる、または質量モデル方式の変更が未反映 | 本案の解析・検定結果を同梱しない。前者は全自動荷重も除外。入力・設定・検討は保持 | 準備計算を実行し、必要な解析・検定を再実行 |
| 時刻歴の詳細記録を「除外して保存」 | 本案の立体時刻歴の詳細記録を除外。層応答・ピーク等の集計、本案の他結果、検討の全保持計算は通常の条件で保存 | 詳細を使う表示には再解析が必要。全結果や検討履歴を除外する操作ではない |
| 生成入力が欠落・不一致 | 本案検定は同梱しない。時刻歴は計算時入力との対応を確認できない結果を除外 | 選択した静的応力と依存検定等も照合し、不一致の対象は利用不可。履歴の保持を現在入力への認定に使わない |
| 計算版が旧版・不明・未知の新版 | 保存し直しても版や生成入力を認定し直さない。検討の保持計算の保存自体とは別に判定 | 下記の[再実行条件](#保存結果の計算契約と再実行)に従う。モデル・設定の読込と結果の再利用を分ける |

実行中の計算は保存済みの成功結果にならず、再読込しても自動再開しません。
Undo/Redo履歴とすべての編集版は保存しません。保存後に完了した計算結果は未保存になります。
検討に保持する入力・根拠の操作は[断面案の検討](../section_study/01_断面案の検討.md#保存)を参照してください。

<div class="impl-ref">

**実装参照**：本案の同梱・復元は `App::{save_project_to_opts, open_project_from}`（`crates/sepika-app/src/app/actions/io.rs`）、検討は `App::{saved_studies, restore_studies}`（`crates/sepika-app/src/app/study.rs`）です。

</div>

## 外部波形と可搬性

時刻歴の外部CSV波形そのものはOVIKAに同梱しません。
波形ライブラリで実行した場合は、波形名と実行時の内容の識別を保存し、再読込時にそのマシンのライブラリを参照します。
別のマシンへ渡す場合は波形ファイルも別途渡し、ライブラリへ登録してください。
ファイルがない場合は選択解除、同名でも内容が変わっている場合は通知します。
「📂 波形CSVを開いて実行…」による一回限りの読込では、再実行用の波形参照を保存しません。再実行時に元のCSVを選び直してください。
保存結果が残っていても入力波形を取り出せるわけではありません。操作は[波形ライブラリ](04_波形ライブラリ.md)を参照してください。

## 保存結果の計算契約と再実行

保存結果には、生成時の解析版と検定版を別々に記録します。現行は解析版 **65**、検定版 **44** です。計算式・適用条件・解析準備の条件が変わると対応する版が変わります。アプリのリリース番号や表示・カメラの変更とは区別します。

| 保存版 | 利用状態 | 操作 |
|---|---|---|
| 現行版と完全一致 | 生成入力も現在のモデル・計算設定と一致する結果を利用できます | 選択したケース・組合せを確認します |
| 欠落 | 版不明の成果として利用不可 | 対象の解析または検定を再実行します |
| 現行版より小さい | 旧契約の成果として利用不可 | 対象の解析または検定を再実行します |
| 現行版より大きい | 現アプリ未対応の成果として利用不可 | 対応アプリを使用するか、現アプリで再実行します |

解析版が非一致の場合は解析成果と依存する検定成果を除外します。モデル・解析設定は読み込みます。
検定版だけが非一致の場合は現行解析の応力を保持し、部材・接合部・壁・小梁・床板の検定を除外します。
理由には保存版と現行版、必要な再実行を示します。読込時に自動計算はしません。
同版でも、保存時に選択していた静的ケース／組合せの生成入力が不一致または識別欠落の場合は、その応力と依存検定を除外します。
検定自身にも成功完了時の生成入力を記録します。採用した計算モデル、実際の静的ケース／組合せとその既存生成入力、実効荷重期間、RC損傷制御・付着・QD方式が一致する場合だけ検定を利用します。
生成入力が欠落・不一致の検定は、解析が最新でも保存対象から除外します。新しい時刻歴等の解析結果は保存でき、再読込で旧検定を復活させません。保存は生成入力や版を新規認定しません。
直接床板・小梁検定は架構応力源を持たず、解析が未実行でも保存できます。解析が古い場合、この保存には直接検定のみを含め、保持された旧解析を同梱しません。
他の方向・固有値・目的別の計算結果はそれぞれの既存入力照合で利用可否を判断します。
立体・質点系の時刻歴は、ケースの識別 と実入力・実効設定・開始時の計算モデルの識別を結果の生成入力とともに保存します。
現行成果の保存再読込で結果の所属を保持します。同じモデルで異なる時間刻み・倍率等を用いた複数ケースは、
最後に表示したケースの設定に揃えて上書きせず、各実行時の条件に対応するケースの識別と結果を保持します。識別が欠落・不一致の成果は利用できず、
再保存や波形の表示選択変更では補完・再認定しません。波形 CSV のファイル名やハッシュだけを、実入力の識別の代用にはしません。

材料条件などのモデル編集後に現モデルで解析に成功した場合、生成時のモデル・実入力の対応を確認できる旧時刻歴は、別ケースの履歴として保存・再読込できます。
履歴の保持と現モデルへの採用は別に判断します。旧モデルの結果は履歴表示できても現モデルの耐力等へ採用できず、現モデルと生成入力が一致する結果だけを採用できます。
現モデルに利用できる解析成果がなく、旧モデルの時刻歴履歴だけが残る読込は、解析済みの最新状態とは認定しません。
モデル編集後に未再実行で解析全体が古いまま保存する場合、本案の旧解析は同梱しません。直接検定と検討・振動荷重ケースの例外は、[保存対象](#保存対象と再読込)を参照してください。

検定版だけが失効した場合は、対象を選び、検定画面の「検定を再実行」を押してください。
応力の版または生成入力が失効した場合は、対象のケース／組合せを再解析してから検定します。
解析の一部だけを再実行しても、旧契約の固有値・増分・時刻歴・目的別に採用した計算結果は復活しません。同版の旧入力で生成された未再計算の検定も利用不可のままです。
必要な解析と目的別評価点の採用をそれぞれ再実行してください。
表示切替、保存し直し、結果状態の更新だけでは新版へ認証し直しません。
現行条件で生成された「未検定」や参考値の「算定不能」も正当な現行成果ですが、全適合を意味しません。
新しい床板・小梁の直接設計は架構解析を要求しません。

計算版とファイルを開けるかどうかを判定する保存スキーマ版は別です。
保存スキーマを読み込める場合でも、計算版不明の保存結果は再実行が必要です。
未知の項目を無視する旧アプリでの結果利用の安全性は保証しません。

<div class="impl-ref">

**実装参照**：版定義は `sepika_core::result_contract`（`crates/sepika-core/src/result_contract.rs`）、OVIKA 成果の利用判定は `sepika_app::app::result_validity`（`crates/sepika-app/src/app/result_validity.rs`）です。

</div>

## 整合性・安全性

内容のハッシュが一致しない、必須の内容が欠ける、保存スキーマ版が未対応、展開後の1項目が4 GiBを超える場合は、読込を拒否します。
保存は一時ファイルへ書き出してから置き換えます。

本案の解析結果の保存サイズが512 MBを超え、立体時刻歴の詳細記録を含む場合は「時刻歴の詳細記録を保存に含めますか？」を表示します。
「除外して保存」の対象は[保存対象](#保存対象と再読込)で確認してください。編集中のメモリ上の詳細記録は保持します。

<div class="impl-ref">

**実装参照**：コンテナ検査・保存は `sepika_io::ovika::{load_ovika, save_ovika}`（`crates/sepika-io/src/ovika.rs`）、詳細記録の確認は `App::save_project_to_opts`（`crates/sepika-app/src/app/actions/io.rs`）です。

</div>

壁版の自重支持辺の負担率と間柱の端部負担率は `.ovika` に保存します。未指定は支持先なしとして扱い、対象壁版の解析前チェックでエラーになります。

増分解析の壁応答には、正負耐力の選択に用いる符号付き面内せん断力 [N] を保持します。壁下辺a→bの向きを正とします。壁以外にはこの値を持ちません。

## スキーマと互換性

モデルには共有数量設定（壁筋の仮定径・定着係数等）と、RC壁の明示横筋比・縦筋比を保存します。
方向比の欠落は欠落のまま復元し、最小筋比から補完しません。現行スキーマで方向比を持たず
方向別でないせん断補強筋比だけを持つ入力も、その方向の鉄筋数量は未算定です。数量設定を変更して保存・再読込すると、
GUI・CSV・MCPは保存値で数量を再集計します。数量設定は解析入力に含めず、積算鉄筋重量を解析質量へ加算しません。
契約は[数量積算](../calc_basis/10_数量積算/01_数量積算の算定式.md)を参照してください。

現行の保存スキーマ版は **1** です。異なるスキーマ版のファイルは開けません。
初回リリースまでは同じ版でも破壊的な変更があり、開発中に保存したファイルの後方互換は保証しません。
旧形式への変換機能はありません。初回リリースはGitタグで判定し、リリース後のスキーマ変更では版を上げ、リリース済みファイルの移行を提供します。
