# OVIKA — SEPIKA Project File

OVI（卵）とIKAを組み合わせた名前です。

SEPIKAの構造モデル、解析条件、解析結果などを、一つの卵のようにまとめて保存します。

OVIKA（`.ovika`）は SEPIKA ネイティブの保存形式です。内部モデルをそのまま格納するため、保存・読込でモデルが**完全一致**します（ST-Bridge のようなサブセット制約はありません）。名称は ZIP という実装技術に依存しません。

<div class="impl-ref">

**実装参照**：`sepika_io::ovika::{save_ovika, load_ovika}`（`crates/sepika-io/src/ovika.rs`）が保存・読込します。

</div>

小梁・間柱への CFT 割当は、断面用途が柱でも保存・読込時に拒否します。領域内・所属未割当のどちらも対象です。保存が拒否された場合は既存ファイルを変更せず、読込が拒否された場合は現在のモデル・選択・Undo 履歴・計算成果を保持します。入力を自動置換・削除して受け入れることはありません。対応範囲は[断面用途](../model_edit/08_断面用途.md)を参照してください。

主架構線材 `Beam`・`Fiber`・`MultiSpring`・`Brace` は、保存・読込で異なる2つの NodeId を明示検査します。断面未割当の床境界線も対象です。0・1・3節点以上や同一IDの二重指定は、ElemId・kind・実節点数・期待2・入力NodeId列を含むエラーです。不正保存は既存ファイルを上書きせず、不正読込は現在のモデル・Undo履歴・結果を置換しません。自動分割や先頭2節点による救済はしません。

## GUI からの操作

ファイルメニューに以下の項目があります。

| メニュー | 動作 |
|---|---|
| 📄 **新規** | 空モデルを開く |
| 🏠 **サンプル(門型ラーメン)** | 内蔵のサンプルモデルを開く |
| 📂 **開く…** | `.ovika` プロジェクトを読み込みます。読込後、モデルは検証（`validate`）を通ってから差し替わります |
| 💾 **保存** | 現在のプロジェクトを上書き保存する（保存先が未設定なら保存先を尋ねる） |
| 💾 **名前を付けて保存…** | 保存先を指定して `.ovika` として保存する |

読み込むとそのファイルが現在のプロジェクトの保存先になり、以降の「保存」は同じファイルへ上書きします。

<div class="impl-ref">

**実装参照**：ファイルメニューは `sepika_app`（`crates/sepika-app/src/app/mod.rs`）が表示し、モデルの差し替えは `sepika_app::app::App::load_model`、開く・保存は `App::{open_project_from, save_project_to_opts}`（`crates/sepika-app/src/app/actions/io.rs`）が担います。

</div>

## 保存結果の計算契約と再実行

保存結果は、生成時の解析契約版と検定契約版を独立して持ちます。現行の解析契約版は **13**、検定契約版は **5** です。標準配筋の適用・未対応ゲート、共通断面質量の採用契約、矩形SRCの内蔵Hとコンクリートの非重複材料領域の契約を満たす版の成果だけを利用します。静的解析の長期軸力無効化・引張専用の採用契約も含みます。履歴ばねの確定点再評価による履歴保持と初期接線の契約も含みます。通常静解析は規模によらず元の f64 剛性を疎 Cholesky で分解する契約を含みます。鋼材の自動強度割増は標準物性・F値と同じ対応済み名称を認識する契約を含みます。囲まれた床・壁の主架構支持は Beam・Fiber・MultiSpring の解析表現に依存しない契約を含みます。正常区間の符号付き単純梁反力は合力と一次モーメントを保存する契約を含みます。囲まれた床では閉合・直交・面積で矩形の適用を判断し、非直交床は真面積による多角形分配を用い、矩形の一方向版検定の結果を生成しない契約を含みます。固定距離の部材荷重は有限な支間内の位置・正の分布区間だけを解析へ渡す契約を含みます。主架構の Beam・Fiber・MultiSpring・Brace は異なる2節点だけを受け付ける契約を含みます。解析契約版12以前・検定契約版4以前の保存成果は対応する再実行が必要です。
計算式、適用条件、解析準備・solver の適用ゲートが変わった場合は対応する版を更新します。
アプリのリリース番号、Git SHA、カメラ・表示ステップ・ハイライト・表示専用通り芯の変更では版を変更しません。

| 保存版 | 利用状態 | 操作 |
|---|---|---|
| 現行版と完全一致 | 生成入力も現在のモデル・計算設定と一致する結果を利用できます | 選択したケース・組合せを確認します |
| 欠落 | 版不明の成果として利用不可 | 対象の解析または検定を再実行します |
| 現行版より小さい | 旧契約の成果として利用不可 | 対象の解析または検定を再実行します |
| 現行版より大きい | 現アプリ未対応の成果として利用不可 | 対応アプリを使用するか、現アプリで再実行します |

解析版が非一致の場合は解析成果と依存する検定成果を除外します。モデル・解析設定は読み込みます。
検定版だけが非一致の場合は現行解析の応力を保持し、部材・接合部・壁・小梁・床板の検定を除外します。
理由には保存版と現行版、必要な再実行を示します。読込時に自動計算はしません。
同版でも、保存時に選択していたケース／組合せの生成入力が不一致または識別欠落の場合は、その応力と依存検定を除外します。
検定自身にも成功完了時の生成入力を記録します。採用した計算モデル、実際の静的ケース／組合せとその既存生成入力、実効荷重期間、RC損傷制御・付着・QD方式が一致する場合だけ検定を利用します。
生成入力が欠落・不一致の検定は、解析が最新でも保存対象から除外します。新しい時刻歴等の解析結果は保存でき、再読込で旧検定を復活させません。保存は生成入力や版を新規認定しません。
直接床板・小梁検定は架構応力源を持たず、解析が未実行でも保存できます。解析が古い場合、この保存には直接検定のみを含め、保持された旧解析を同梱しません。
他の方向・固有値・目的別runはそれぞれの既存入力照合で利用可否を判断します。

検定版だけが失効した場合は、対象を選び、検定画面の「検定を再実行」を押してください。
応力の版または生成入力が失効した場合は、対象のケース／組合せを再解析してから検定します。
解析の一部だけを再実行しても、旧契約の固有値・増分・時刻歴・目的別採用runは復活しません。同版の旧入力で生成された未再計算の検定も利用不可のままです。
必要な解析と目的別評価点の採用をそれぞれ再実行してください。
表示切替、保存し直し、結果状態の更新だけでは新版へ認証し直しません。
現行条件で生成された「未検定（Skipped）」や参考値の「算定不能（Unavailable）」も正当な現行成果ですが、全適合を意味しません。
新しい床板・小梁の直接設計は架構解析を要求しません。

この版情報の追加では OVIKA コンテナの schema_version は変更しません。
旧ファイルのモデル・設定は読めますが、版不明の保存結果は再実行が必要です。
未知の項目を無視する旧アプリでの結果利用の安全性は保証しません。

MCP の DesignCheck は毎回新しい解析を行い、OVIKA の保存応力を再利用しません。
MCP の Parquet/FsResultStore の result_get は別の保存経路で、この OVIKA の版・入力照合の対象には含みません。

<div class="impl-ref">

**実装参照**：版定義は `sepika_core::result_contract`（`crates/sepika-core/src/result_contract.rs`）、OVIKA 成果の利用判定は `sepika_app::app::result_validity`（`crates/sepika-app/src/app/result_validity.rs`）です。

</div>

## ファイル構造

`.ovika` の内部は現在 ZIP コンテナです。`manifest.json`・`model.msgpack`・`settings.json` は必須エントリ、
残りは任意エントリ（同梱がなければ読込側の該当項目が `None` になる）です。

| エントリ | 必須 | 内容 |
|---|---|---|
| `manifest.json` | ○ | スキーマ版、単位系、各エントリの SHA-256 ハッシュ |
| `model.msgpack` | ○ | 内部モデル本体（MessagePack でシリアライズ） |
| `settings.json` | ○ | 設計コード等の設定 |
| `preparation.msgpack` | - | 準備計算の結果（モデルに対して最新の場合のみ同梱） |
| `results.msgpack` | - | 解析結果（静的・組合せ・固有値・増分・時刻歴・質点系など。モデルに対して最新の場合のみ同梱） |
| `analysis_settings.msgpack` | - | 解析タブの設定値（立体時刻歴と質点系それぞれの波形パラメータ・減衰、固有値／質点系のモード数など） |

4 種の MessagePack エントリでは、struct をフィールド名付きの map（named MessagePack）として保存します。
入れ子の struct も名前を保持するため、Rust のフィールド宣言順序を変更しても読み込みは順序に依存しません。
任意エントリの直列化はアプリ側が行い、IO 層は内容を解釈しないバイト列として保存・返却します。

内部モデルには節点・部材・断面・材料・荷重・層に加え、断面形状（`SectionShape`）や部材付帯情報（ハンチ・継手位置）まで含まれ、これらは保存・読込で保持されます。
時刻歴を実行すると振動荷重ケースもモデルへ入りますが、解析結果が最新でない保存では書き出しません。
開き直したときに、結果のない空ケースが残らないようにするためです。

`preparation.msgpack`・`results.msgpack` はモデルから再計算できる派生データですが、再計算が
高価なため保存して復元します。解析全体が古い場合は解析を同梱しません。検定は独立した生成入力の一致も要求し、未再計算の旧検定を最新解析と一緒に保存しません。
再読込後は同梱されていない成果を未実行として扱います。

`analysis_settings.msgpack` はモデルから導出できない独立した設定値（時刻歴の波形パラメータ・
減衰モデル、固有値解析のモード数など）で、解析結果を生成した条件そのものです。モデルの新陳とは
無関係に、保存のたびに現在の設定値を常に同梱します。このエントリを持たないファイルを読み込んだ
場合、解析タブの設定値は変更しません（既定値のまま、または直前の値を保持します）。

質量モデルの方式（`mass_method`）は例外で、モデル本体（`model.msgpack`）が持つ値を単一情報源
とします。`analysis_settings.msgpack` にも同じ項目がありますが、読込後は常にモデル側の値で
上書きします。

なお、時刻歴応答解析の入力波形（CSV読込波）そのものは `.ovika` に含まれません。波形ライブラリ
（[波形ライブラリ](./04_波形ライブラリ.md)）から選んで実行した場合は、`analysis_settings.msgpack`
にライブラリ内のファイル名と実行時点の内容の SHA-256 を記録し、開き直したときにライブラリから
自動で同じ波形を参照します。立体時刻歴と質点系は別々の選択を持ちます。ファイル選択ダイアログ
（「📂 波形CSVを開いて実行…」）から一回限りで実行した場合は、波形は保存されず再現できません。

<div class="impl-ref">

**実装参照**：各エントリの中身の直列化・復元は `sepika_app::app::App::{save_project_to_opts, open_project_from}`（`crates/sepika-app/src/app/actions/io.rs`）が担います。

</div>

## 整合性・安全性

- **ハッシュ検証**: 読込時に各エントリの SHA-256 を `manifest.json` の記載と照合し、不一致ならエラーにします。必須エントリ（`model.msgpack` / `settings.json`）が manifest に列挙されていない場合も拒否します（未検証のまま読み込ませないためです）。
- **スキーマ版チェック**: 本ソフトはリリース前で後方互換を持たないため、現行スキーマ版（`1`）以外は拒否します。
- **原子的な保存**: 一時ファイルへ書き出して `fsync` した後に `rename` することで、電源断でファイルが破損しないようにしています。
- **ZIP 爆弾対策**: 1 エントリあたりの展開サイズ上限（4 GiB）を超える書庫は拒否します。現在の `.ovika` は単層 zip（deflate）で展開率は理論上約 1032 倍が上限のため、絶対サイズ上限がメモリ保護として機能します。ヘッダの申告サイズは信用せず、実際の展開バイト数でも検査します。
- **保存サイズの確認**: 解析結果（時刻歴の詳細記録を含む）の直列化サイズが 512 MB を超える場合、保存時に「時刻歴の詳細記録を保存に含めますか？」の確認を表示します。除外して保存しても、層応答・ピーク値等の集計結果は保存され、詳細記録は再解析で復元できます。

<div class="impl-ref">

**実装参照**：ハッシュ検証・スキーマ版チェック・原子的保存・ZIP 爆弾対策は `sepika_io::ovika::{load_ovika, save_ovika}`（`crates/sepika-io/src/ovika.rs`）が、保存サイズの確認は `sepika_app::app::App::save_project_to_opts`（`crates/sepika-app/src/app/actions/io.rs`）が担います。

</div>

壁版の自重支持辺の負担率と間柱の端部負担率は `.ovika` に保存します。未指定は支持先なしとして扱い、対象壁版の解析前チェックでエラーになります。

増分解析の部材応答には、壁の正負耐力の選択に用いる符号付き面内せん断力 `wall_shear_signed` [N]を保持します。壁以外はnullです。壁下辺a→bの向きを正とします。スキーマ番号は1です。

## スキーマと互換性

`manifest.json` の `schema_version` は、モデルと任意エントリを含む永続化スキーマの版です。
現行値は `1` で、読み込み時にはこの値との一致を確認します。
ただし初回リリースまでは、版を `1` に据え置いたまま破壊的変更を行い、開発中に保存したファイルの後方互換は保証しません。
同じ版でも過去のファイルを読み込める保証はなく、旧形式への変換や互換層は提供しません。

named 形式はフィールド順序への依存をなくしますが、フィールド名・型・意味の変更まで自動的に互換にするものではありません。
たとえば `#[serde(default)]` を持つ追加フィールドは欠落時に補完できますが、その値が計算上も適切かは別に確認する必要があります。
struct の未知フィールドは通常無視されますが、フィールド削除に伴う情報の喪失が許されることを意味しません。

初回リリースは Git タグで判定します。
初回リリース後に永続化スキーマを変更するときは版を上げ、リリース済みファイルからの明示的な migration を実装します。
順序だけの変更は named 表現のスキーマ変更に当たりません。
それ以外の変更は、以下の観点でデータの保存・復元と計算上の意味を確認します。

| 変更 | 確認する事項 |
|---|---|
| フィールド追加 | 欠落を default 等で読めるか、補完値が適切か |
| フィールド削除 | 未知フィールドを無視しても必要な情報が失われないか |
| フィールド名変更 | 旧名から新名への明示的な変換が必要か |
| 型変更 | 値の範囲・単位・表現を保って変換できるか |
| enum variant の追加・削除・意味変更 | 未知 variant や廃止値をどう扱うか、計算の意味が保たれるか |
| 構造の分割・統合 | 対応する値を欠落・重複なく移せるか |
| 任意エントリの変更 | producer 側の具体型の変更と、同梱がない場合の挙動が整合するか |

リリース済みスキーマを移行する場合は、その版の型へ decode してから現行型へ変換します。
現行型への直接 decode を migration の代用にはしません。
現在は版間の変換を行わず、未対応版は MessagePack の decode 前に `UnsupportedVersion` として拒否します。

**実装参照**：`sepika_io::ovika::CURRENT_SCHEMA_VERSION` と `load_ovika`（`crates/sepika-io/src/ovika.rs`）が現行版と版一致チェックを定義します。

</div>

## 開発者向け: ライブラリ API（Rust）

<details>
<summary>Rust コード例（開発者向け）</summary>

```rust
use sepika_io::ovika::{save_ovika, load_ovika, OvikaExtras};
use std::path::Path;

// 保存: 内部モデル＋任意エントリ（各バイト列は呼び出し側が事前に
// rmp_serde::to_vec_named で直列化したもの。io 層は中身を解釈しない）→ .ovika
save_ovika(Path::new("model.ovika"), &model, OvikaExtras {
    preparation: Some(&preparation_bytes),
    results: Some(&results_bytes),
    analysis_settings: Some(&analysis_settings_bytes),
})?;

// 読込: .ovika → 内部モデル＋同梱されていれば各任意エントリ
let contents = load_ovika(Path::new("model.ovika"))?;
let model = contents.model;
```

</details>
